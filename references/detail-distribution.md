# 细节与分布执行 SOP

本阶段把已经通过空间白模和代表样件门禁的资产，转成完整场景里的可控细节群体。输入是`scene-register.json`、`visual-build-map.json`、`asset-ledger.json`中已审核的`prototype.formVariants`及冻结的middleForms构建；输出是引用这些原型ID的实际放置记录、分布诊断图、上下文/近景截图和`distribution-report.json`。材质与灯光的最终响应留给下一阶段。

## 1. 先确定细节要改变的画面关系

只把会影响目标图的细节纳入本阶段。逐项读取视觉特征，说明细节出现在哪里、形成什么节奏、在多远处需要可见，以及什么区域必须保持开放。可表达的目标包括：轮廓断续、结构节奏、尺度参照、局部聚集、表面覆盖、功能标识或环境反馈。不要把“增加数量”当成目标。

一个分布组对应同一类资产/效果、同一分布方法和一组可复核目标区。将登记表里的允许区、宿主面、洞口/路线净空、相邻群组和视觉特征ID写入计划。面状宿主用准确的`planGeometry`多边形及孔洞；仅有surface AABB时不能把整个盒子当作合法散布区。体积粒子或云雾可用登记的三维distribution envelope，但仍需单独标出要保留的通道、焦点和稀疏区。

## 2. 按空间拓扑选生成方式

| 空间关系 | 首选方式 | 不适合的方式 |
|---|---|---|
| 建筑构件、铺装、窗格等规则节奏 | 轴网/模块阵列，按边界与开口裁切 | 全局随机散点 |
| 植被、碎石、珊瑚等有聚集/生境差异的群体 | 先采簇中心，再在簇内采成员；由高度、坡度、湿度、朝向或邻近关系调节权重 | 在整张场地均匀取样后只靠拒绝采样补形 |
| 沿岸线、道路、枝干、裂缝等连续结构 | 沿实际曲线/骨架按弧长采样，再施加受限横向偏移 | 对控制点插值后直接按世界XYZ等距撒点 |
| 局部雕饰、焦点道具或需要确定构图的元素 | 手工落位，必要时以程序生成可控变体 | 为了省事强行程序化所有资产 |
| 雾、雨、火花、气泡等三维群体 | 在明确体积/发射器域内分层或按流场采样 | 用地面二维分布掩盖深度与流向 |

随机只负责同一组内部的变化。先安排大组的位置、边界、方向和留白，再生成组内实例；固定seed，位置、尺度、朝向、变体之间按生境/构造逻辑关联。`variantId`必须引用资产族`middleForms`已批准的`prototype.formVariants[].id`；位置、缩放、旋转和颜色/表面随机另存为实例参数或材质参数，不据此增加形态变体数。缩放范围若会明显改变资产的主次比例或剪影，应登记为单独几何原型。人工控制的焦点实例保留明确稳定ID，不能被随机流程移走。

## 3. 让生成器输出可核对的真实结果

Three.js中先生成候选，再按顺序做合法性筛选：登记区/孔洞 → 功能净空 → 最小间距/相交 → 宿主面命中与高度 → 朝向/尺度/变体。记录候选数、实际接受数和按原因统计的拒绝数；三者必须能相加核对。固定次数拒绝采样容易使目标区实际密度低于计划，若拒绝率过高，改用域内采样、分区采样或路径参数采样，不要静默缩减实例。

每个最终实例保存稳定`id`、`zoneId`、来自`middleForms`原型目录的`variantId`、世界锚点和尺度；锚点是对象落地/附着点，不是未说明的包围盒中心。`InstancedMesh`可用于同拓扑、变换简单且共享材质的族，但实例矩阵必须从同一份放置数据生成。保存的放置数据、运行网格和诊断图需来自同一build与同一seed。宿主采样使用最终曲面或明确surface ID；高坡度、悬挑、多层地面和洞顶不能由单一`heightAt(x,z)`猜测。数百个以上的重复实例可用独立CSV作为`placementTable`，列为`id,zoneId,variantId,x,y,z,sx,sy,sz`，以便流式校验；小型组可直接嵌入JSON `placements`。两种方式都必须纳入detailDistribution哈希证据。

按真实连接方式检查附着足迹：根部、底座或各支脚需要支承，冠层/挑出部分可以悬空。中心点命中不证明整块基部成立；分布允许区也可能延伸到宿主之外。候选落位先满足允许区与实际可附着区域，再检查足迹边缘；边缘落空时移动、缩小或改附着方式，并保存计划位置、实际位置及修正原因。修正后重新核验受影响的允许区、净空、间距、原型尺度和支承，不继承修正前的通过结论。不能用延长根柱或把未命中的高度设为零掩盖无支承。

```js
const placements = buildPlacementPlan({
  zones, exclusions, hostSurface, densityField,
  familyVariants, seed: fixedSeed,
});

for (const item of placements) {
  // 运行网格与诊断图共用相同的item，不各自重新随机一次。
  const host = sampleActualHost(item.positionXZ, item.hostSurfaceId);
  item.anchorWorld = host.point;
  item.normalWorld = host.normal;
  item.variantId = chooseVariant(item.familyId, item.id, item.seed);
}
placeInstances(placements);
writePlacementReport(placements, generationStats, seed); // QA侧导出，不把HUD/调试线放入最终画面
```

这是结构示意，`buildPlacementPlan`等不是Three.js API。具体分布函数应能从视觉特征回溯到生成参数，再追到放置数据和实际网格/实例。仅有源代码、count或`userData`标签不能证明该实例被绘制。

## 4. 先看分布图，再看真实Three.js画面

批量扩展前先对每个组生成同坐标范围的诊断图：允许区、排除区、候选点、接受点、目标分区计数/密度和宿主面。诊断图用于找空区、偏区、边界泄漏和采样偏差；不替代最终场景图。按目标分辨率捕获三个互补画面：

1. **context**：整组在完整场景中的占幅、焦点让位、前中远关系与实际空白。
2. **distribution-map**：组域、孔洞/净空、分区目标与实际放置点。色标/符号可读，坐标方向和比例尺明确。
3. **detail**：代表近景显示实例形态族、尺度变化、间距与真实接地/连接；不能仅用无材质点云。

再结合最终相机包络检查近、中、远屏幕尺度：投影尺寸足够时保留结构细节，进入次要景别时让细节合并为群体轮廓、色带或稀疏纹理。高频内容低于目标采样尺度时降低对比/密度或合并表示，避免远景变成均匀噪点；焦点资产可保留更细变化。任何像素阈值、计数范围和密度曲线都由当前参考、对象尺度、视口及相机域推导，不照抄通用常数。

## 5. 逐组放行与失败归因

每个组在`distribution-report.json`里记录资产族、目标视觉特征、分布方法/seed、实现放置的源码/函数符号、合法区和排除区、各区目标数量范围、真实placements、候选/接受/拒绝统计、最低变体数、图像证据及以下检查：

| 检查 | 通过时必须能从画面读到 |
|---|---|
| coverage | 目标区域覆盖完整，预留空区有明确用途；局部不扎堆、大面不漏空 |
| spacing-rhythm | 重复间距、簇间距、方向和疏密变化服从设计规律，不出现机械等距或白噪声 |
| variation | 实际用到规格声明的几何原型；差异来自剪影、截面/拓扑、主体体块或主要连接，在同机位目标尺寸下可读且仍属于同一资产族。缩放、旋转、换色、噪声或贴花单独变化不算形态变体；有意统一的设计说明理由 |
| screen-scale | 近/中/远景从单体细节到群体轮廓逐级收敛；不挡焦点或形成不合比例的高对比噪声 |
| support-clearance | 实际锚点落在指定宿主；坡度/法线、路线、开口和功能净空无浮空、穿插或侵入 |

结构校验只核对特征覆盖、计数、域位置、哈希、视图关联和统计算术；“看起来节奏自然”“细节尺度合适”必须由对应PNG人工观察。全场总数不能代替每个zone的目标范围，图表齐全也不能代替实际渲染。任一组未通过时停在当前族：覆盖失败改zone/簇尺度或布局；节奏失败改采样过程；变体失败改形态族/变化权重；尺度失败改投影预算/LOD/材质对比；支撑/净空失败回到宿主、路径或区域边界。修复后重生成放置数据、截图、哈希和报告，再通过`validate_delivery.py ... --through detailDistribution`；通过后才进入lookdev。
