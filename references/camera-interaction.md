# 可交互相机与真实运行验收 SOP

> 默认制作按本文的方法真实检查环绕、缩放、复位及声明范围；固定契约样本表、cameraMotion报告、manifest字段与总门禁属于显式选择的[正式阶段协议](formal-stage-workflow.md)。普通制作记录实际输入操作、相机读回与当前入口证据即可。


适用于用户要求环绕、缩放或观察3D场景的交付。它将相机设计、完整观看范围、真实输入操作和最终可运行页面串成一个可复核交接。固定机位影片不套用环绕要求；静态导出帧也不能证明页面可交互。

## 1. 相机先服务可观察的场景

在空间代理阶段确定相机目标、合法方位/俯仰/距离、焦点占幅与必要净空。用户要求完整360°时，不把“能拖动鼠标”当成无死角：布局和正式资产必须能支撑所有可达方向，默认检查至少8个水平方位及声明的俯仰/远近端点，再补测底部、背面、透明面、窄通道等易漏区域。显式采用正式阶段协议时，使用交付契约定义的至少20个包络样本。通过侧背/上下样本检查模型是否只有正面、场景是否在环绕后变成空黑或缺少承托关系。相机边界应由内容、构图和使用目标设计，不以缩窄`minAzimuthAngle/maxAzimuthAngle`掩盖未完成区域。

目标是可巡视场景时，选择透视/正交相机、目标点、镜头焦段和尺度变化都要符合查看任务。保证近景可接近但不穿模，远景仍保留环境语境；为透明物、反射面和细节物安排可见检查角度。相机目标与地平线不要被一张英雄视角锁死；所有可达视域都要有有效场景内容。

## 2. 用实际页面测输入与状态

从用户将要打开的最终页面或完全相同的build开始，用可用的Playwright/CUA方式操作真实视口；不要只调用controls API、改相机参数或播放预设截图。至少测：

1. **初始状态**：记录初始azimuth、polar、distance并截取页面。
2. **完整水平环绕**：真实鼠标/触控拖动累计至少359°，记录相机实际方位行程。回到初始方位时确认极角与距离没有意外跳变，并截取360°后画面。
3. **缩放**：实际滚轮/双指缩放，确认相机距离改变且仍在声明范围内；在近/远状态检查没有穿模、裁切或脱离场景。
4. **复位**：实际点击页面的复位入口，等待控制器阻尼停止，再检查相机回到初始方位、俯仰和距离容差内并截图。

相机自身状态最好从实际OrbitControls读回：`getAzimuthalAngle()`、`getPolarAngle()`及相机到`controls.target`的距离。角度按弧度转度，累计跨越`-π/π`时需正确unwrap；不能只用鼠标像素位移推算实际旋转。如果产品有阻尼，在状态稳定后再记录和截图。只读QA状态的挂钩不能改变交互或场景输出，也不要把调试HUD合成进最终截图。

## 3. 把输入、截图和被测页面绑定

普通制作记录最终入口/版本、真实输入动作、相机状态、目标视口图和观察结论；页面变化后重测受影响状态。静态包络图检查内容，真实输入图检查操作，两者共同支持当前交付。

### 仅正式阶段协议：结构化报告与门禁

显式选择正式阶段协议时，执行以下报告格式与校验命令：

`camera-interaction-report.json`记录：最终被测HTML文件及哈希、浏览器和输入方式、实际执行的orbit/zoom/reset动作、累计旋转角、各步真实相机状态、空页面错误列表，以及初始/环绕后/缩放后/复位后四张页面PNG及哈希。每张图的状态必须表明控制器已settle；所有截图、报告和被测HTML均进入`cameraMotion`阶段证据。报告buildId与相机阶段一致；相机约束与互动实测来自同一camera contract。页面代码变更后必须重新操作，不得沿用旧截图。

静态相机包络截图与实际输入证据分工不同：前者说明规定视角被取样，后者说明用户能操作页面。全屏录屏、测试日志、Playwright通过、按钮存在和角度公式本身都不能代替目标视口截图。对全360°还需人工逐视角确认场景完整、视线有内容、没有进入黑幕/空域，交互报告只验证动作、状态和图像文件链。

从`assets/templates/camera-interaction-report.template.json`创建报告，将路径填入`cameraInteractionReportPath`。在manifest登记`cameraContractPath`并确保runtime输入引用同一哈希，然后运行：

```bash
python3 <skill-root>/scripts/validate_delivery.py <project-root>/delivery-manifest.json
```

`validate_delivery.py`会对`interactive-orbit`要求真实旋转至少359°、相机状态位于设计范围、缩放改变距离、复位回到初始状态，并核对被测页面、四张PNG、SHA-256与buildId。它不会操作浏览器，也无法从截图反推出页面控件确实被点击；操作者仍须实际观察页面、确认样本可见且画面完整。固定导演镜头的影片交付不需要此互动报告；若任务只要求有限视角，manifest应记录有限包络，不伪称360°。
