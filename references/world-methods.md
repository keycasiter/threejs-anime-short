# 空间生成的本地实现方法

在需要从设计关系生成路网、街区、房间或模块布局时读取本页对应小节。已有[图与地块工具](algorithm-recipes.md#随包工具走廊图与沿边地块)优先使用；下面补其未实现的求解方法。算法步骤是项目实现说明，不是隐藏的Three.js API。全部输出先经过真实场地资格，再进入几何工厂。

## 方向场与分级路网

### 输入与表示

保存世界XZ边界/孔洞、保留区、地标、区域用途与基准高程。每个方向基元有`centerXZ`、影响范围、权重衰减和`angleRadians`；区域方向不是Three欧拉旋转。边保存端点节点ID、中心线、道路宽度、等级、标高层及用途。

把带主/次身份的无向正交方向场表示为对称矩阵的两个分量：`a=w*cos(2*theta)`、`b=w*sin(2*theta)`，矩阵为`[[a,b],[b,-a]]`。多个基元分别累加a/b；局部主方向`theta=.5*atan2(b,a)`，另一个方向加π/2。规则基元theta固定；环向基元取`atan2(z-cz,x-cx)+π/2`。若混合时a/b接近0，方向未定义，按区域优先级选基元或停止流线，不用任意normalize(0)。这是一种线场混合；不保证任意交叉角的道路美感。

### 从方向到流线

1. 先放主干种子，再次干，再局部街道，分别给间距、长度/步数预算和允许区域。保留的地标与广场不随随机流移动。
2. 给定当前位置p与上一方向d，取局部场方向v；无向线场需在v与-v中选`dot(v,d)>=0`的一支，防止每步翻转。两组正交路可分别跟踪主/次特征方向，区域边界明确切换责任。
3. 沿切向积分。Euler为`pNext=p+h*v(p)`；弯曲变化明显时用真正RK4：`k1=v(p)`、`k2=v(p+h*k1/2)`、`k3=v(p+h*k2/2)`、`k4=v(p+h*k3)`，位移`h*(k1+2k2+2k3+k4)/6`。每次方向求值均与当前参考朝向对齐。h是世界距离，不是无关的标量偏移。
4. 对每一条新线段查场地/保留区与附近已有线段，不仅查新端点。接近合法端点时吸附；横穿同层道路时裁到交点并建立共享节点；桥式跨越保留不同层和垂直净空。
5. 越界、不能保持净距、重复回到近邻、达到长度/步数预算或方向无效时停止。种子尝试数和总边数有界；保留接受/拒绝原因，不为凑数量无条件缩小净距。

间距大于道路宽度加所需地块/留白时才有可填区域；步长要足以解析曲率和交点，不能比目标分离尺度还粗。先看两组方向和稀疏主路，再扩支路。方向场控制走势，人口/用途/地形代价控制在哪生长，两者分别设计。需要更直接的手工规划时直接给节点/路线，不必实现自动路网。

## 交点图与地块

### 交点切分

对线段`p+t*r`与`q+u*s`，二维叉积`cross([x,z],[x2,z2])=x*z2-z*x2`。非平行时：

`t=cross(q-p,s)/cross(r,s)`，`u=cross(q-p,r)/cross(r,s)`。

t/u均在[0,1]内才在线段上。平行时再判断共线及投影区间：正长度重叠需合并/裁切，单个公共端点可保留。容差按世界尺度设置。为每条边收集全部交点参数，排序去重后切成小边，近重合节点用空间索引和明确容差归一为同一ID；切分后重建邻接。宽相位可用二维边AABB，最终仍做精确线段判断。

用BFS/DFS计算连通分量，入口到目的地必须在同一合法层连接图。几何看上去交叉但无共享ID并不连通；桥跨过道路也不应凭XZ相交建节点。

### 从闭环到地块

1. 将无向边拆成两条有向半边；每个节点按出边方向角排序。
2. 从未访问半边开始，走到终点后，在反向边旁始终选同一侧的下一半边，直到回到起边。半边重复但未闭合或超边数预算则失败，避免无限遍历。
3. 计算环的有向面积，区分外部无限面和内部面；用包含关系识别孔洞。不要把外部面也生成建筑。
4. 先按道路半宽、退界和交角求可用多边形，再细分。凸矩形可直接沿长轴切分；凹域/孔洞需稳健多边形偏移与裁切，不能只把所有顶点朝质心移动。
5. 每块保存稳定ID、轮廓/孔洞、临街边/方向、用途、可用高程和入口；足迹完整地检查坡度/基座高度与道路标高。若一批都被拒，调整道路/台地/尺度，再确定目标建筑数。

随包`generateFrontageLots`是沿明确边放矩形的简化路线，已检查矩形互占；它没有实现上述任意街区提取或偏移。使用哪种路线，应由目标街区形状和实际场地决定。

凸街区可用半平面裁切完成本地退界：统一外环朝向，对每条临路边建立指向内部的单位法线n，允许域为`dot(n,p-edgePoint)>=retreat`；从原多边形开始逐条裁切，边界交点按线性插值求出。空结果表示退界后无可用地块，尖角处明确miter上限/切角设计。对凹域和孔洞不套用这条凸算法；需要任意拓扑时可适配已查Manifold `CrossSection.offset(delta,joinType?,miterLimit?,circularSegments?)`，负delta内缩，保持孔洞朝向/填充语义并处理空域与多连通输出。异步WASM初始化、轮廓输出与delete归属按锁定包确认；未装该库时选择已提供的矩形/凸域路线，不虚构通用裁切工具。

## 房间、走廊与分阶段重写

### 可直接实现的二分布局

输入二维矩形、最小房间宽深、墙/走廊宽、入口出口与用途。下面是自写BSP方法，不把ROT内部四分迷宫称为同一API。

| 步骤 | 实际操作 | 结束/边界 |
|---|---|---|
| 分区 | 选允许切分的叶区，沿长轴或设计轴分割；分割位置两侧都保留最小室内尺寸与墙厚 | 两侧无法满足最小尺寸、达到深度/房间预算则不切 |
| 放房 | 在叶区内留边生成房间，保存房间矩形/用途与可接门边 | 门与室内尺度先给，不用0宽缝当通道 |
| 连子树 | 每次父分割，把左右子树的一对可连接房间用走廊连接，端点接真实门口 | 可选直/L形路线；冲突则在该父区找绕路，仍无解返回布局失败 |
| 加环 | 在已有通路上选少量邻近但路径绕远的房间加第二条连接 | 保留关键空隙/功能区，循环数是设计量 |
| 网格化 | 用实际米制单元或多边形生成可走区、墙体带、门洞和净空 | 有限格坐标转换到世界XZ；楼层/楼梯另建层间图 |

父分割连接可建立连通骨架，但障碍、门口变化和后续规则可能破坏它，最终仍跑可达与使用者宽高检查。走廊画成中心线不证明实体可通行。

### 语法负责有意义的变化

把区域写为用途符号，规则是“在什么上下文，把哪些单元替换成哪些单元”。例如已规划通道边生成墙带，墙带在入口处生成真实门洞，临街住宅选择有院/连排/拱廊等不同构造族。按**骨架→功能区→边界→局部构件**分阶段重写，约束每阶段步数与保留符号。既有稳定ID派生构件ID，随机只选择允许的分支。

每条规则声明会占用、让位或连接的空间；一轮后检测关键入口/保留区，不让装饰规则填死通道。符号最终调用实际几何工厂，不能只输出着色网格或文字标记。

## 局部邻接约束求解

WFC用于已设计边界内的模块兼容，先定义自己的模块和接口，不取外部示例tile模型。

**数据：** 每格候选集合`D[cell]`；模块权重`w[t]>0`；各方向的允许邻居集合`A[t,dir]`；可选旋转/镜像后的不同模块ID；固定格与边界。模块的连接口、封闭侧、转角等语义必须对应实际几何。

**求解步骤：**

1. 初始化候选域并确认非空，应用固定道路/门口/边界；首次把**所有格**入队做全域传播，即使未加固定格、初态已经全是单元素也如此。后续仅把改变的格入队。否则单元素但互不兼容的初态会错误跳过检查。
2. 取队首格c，对每个邻格n，计算`U=union(A[t,dir] for t in D[c])`；令`D[n]=D[n]∩U`。若变小则n入队；若为空，立即报告矛盾。队列清空前不做下一次选择。
3. 未全确定时，从多候选格中选最小熵或最少候选者。加权熵`H=log(sum w)-sum(w*log w)/sum w`，并列用固定seed或稳定序选择。
4. 按剩余候选权重随机选一个，将该格域缩为单元素，重新传播。重复直到所有格单元素。
5. 设置总选择/传播预算；矛盾用有界重启或显式回溯恢复域/队列/随机状态，不能在坏域里继续补格。预算耗尽记为未完成，不能当成功。

输出是模块ID与变换。随后从入口在“实际允许通行的模块端口”上跑BFS，检查出口、通道宽度与保留空隙；局部邻接规则本身不保证全局可达。小权重不是硬禁止，必须禁止的邻接写进集合/固定条件。

## 可达性、导航与镜头阻挡

路线图A*输入节点/边、非负代价与起终点。维护open最小堆、`gScore/cameFrom`，每次取最小`g+h`，对邻边松弛，抵达目标后回溯。欧式距离只有不高估剩余代价时才是合适启发；未知代价关系先用h=0。找不到路返回失败，不画穿墙直线替代。几何通行仍要按使用者体积扫掠/净空检查。

从网格导航时先按半径/高度/坡度和台阶能力筛选可走三角形/区域，再做区域邻接与路径；路径平滑不能切出可走域。动态几何改变后更新相关导航/空间索引。只需要镜头导览时不必引入全角色导航引擎。

跟随镜头由目标/期望位置→阻挡查询→受限相机→平滑构成；检查近裁面或相机体积，单中心射线会漏细柱。撞到遮挡时及时收回，恢复时平滑展开；同时核对主体是否仍可读。相机避障和关键内容视线是两个检查。真实输入方法见[相机交互](camera-interaction.md)，具体库接法见[库接线](library-integration.md)。
