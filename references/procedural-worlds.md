# 让完整世界由空间规则生成

用于多区域环境、宏观场景、重复群体和近中远表示设计。先完成[可生成设计](procedural-design.md)；本页负责区域、关系与细化次序，具体放置算法读[分布方法](detail-distribution.md)，运行组织读[制作系统](production-systems.md)。

导航：[世界骨架](#1-先设计世界骨架) · [空间语法](#2-用语法建立区域与组成物) · [稳定数据](#3-稳定身份种子与真实关系) · [多尺度表示](#4-近中远使用同一个世界) · [数据示例](#5-轻量世界数据示例) · [扩场完成条件](#6-按区域完成可建造的接力)

本分支的三维环境由自写 JS/Three.js 几何、程序表面与 shader 构成。宏观方法可以学习城市、生态或建筑案例；最终对象仍须从当前设计规则重建，不使用借来的模型图集、扫描立面、烘焙模型块或预制三维资产。

## 1 先设计世界骨架

把“世界大而丰富”转换成可建的多尺度关系：**全场 → 区域 → 组团 → 对象族 → 构件**。小作品可以少一级；一株植物内部也可用组织/分枝层级，不能强制所有题材变成城市或射击关卡。

| 顺序 | 做出的设计 | 交给下一层的实际输入 |
|---|---|---|
| 观看与尺度 | 相机最近/最远距离、移动/环绕范围、主视角、场地总尺寸 | 相机包络、世界单位、全貌与近景视图 |
| 连续空间 | 地形/承托、边界、高程、洞/谷/房间、地平线 | 能生成实际承托网格的轮廓、截面或场；标明哪些不能用单值高度场表达 |
| 区域与联系 | 区域用途/生境、主要形态、与邻区的通路/水系/组织联系 | 区域边界、相邻关系和实际连接段 |
| 主次与空隙 | 地标、焦点、视线走廊、安静区、前中远层 | 明确保留的空地/负形与关键对象定点位置 |
| 组成与密度 | 各区需要的主物、承托、边界、次级物与群体 | 对象族清单、原型权重、组团尺度和允许密度范围 |

先手工确定决定身份的区域和主要关系，再生成有边界的局部变化。把一切交给随机会同时丢失方向、层级和可复查性；把一切排满也会消除必要的负形。导演镜头按合法视锥组织，自由查看则覆盖实际可达方向。

完成此步时，全场灰盒已包含重要区域、完整承托/路径和远景轮廓。实际相机能读出空间去向，侧背没有未设计的空洞；灰盒仍可简化，但不能缺少整个环境层。

## 2 用语法建立区域与组成物

每个区域定义“在什么条件下，哪些对象以什么关系出现”。语法是可执行约束与设计例外，不是额外的描述语言；普通 JS 条件、列表与项目函数即可。

| 语法层 | 建筑/人工环境 | 自然/有机环境 |
|---|---|---|
| 区域条件 | 用途、轴网、高程、入口、可承载范围 | 坡度、水深/水分、光向、组织年龄、流向 |
| 主体组 | 地块→主楼/院落→开间/构件 | 生境→核心群落→主枝/次枝/附生层 |
| 从属关系 | 门朝通路、桥接两端、构件安装到真实接口 | 根接地、叶附枝、群落依托地形与遮蔽 |
| 边界与过渡 | 路肩、台阶、基础、墙顶、区域交界 | 岸带、林缘、裸露/覆盖过渡、分叉收分 |
| 受限变化 | 结构原型、跨数、有限朝向、组内间距 | 物种/形态族、年龄尺度、簇密度、相关偏转 |

为每个主要区域先制作一个**完整代表组**：主物与邻接支撑、边界、次级物、材料和光线一起完成。建筑区不能只有楼体没有街地/入口/收口；自然区不能只有树冠没有根部/坡面/林缘；有机对象不能只做外包络忽略分枝交界。

先检查原型的真实轮廓差异，再按区域权重分配。连贯的组间节奏由布局产生，细微不齐由实例参数产生，色调/粗糙度由表面产生；三个责任层分别控制。随机噪声不能替代区域身份或构造方向。

## 3 稳定身份、种子与真实关系

**稳定 ID。** 给区域、组团、对象和关键接口分配不随数组顺序改变的 ID；人工控制的地标保留定点数据。插入一件道具不应让远处树林重新洗牌。

**按用途派生种子。** 从项目 seed、稳定 ID、用途名称派生局部随机源，如 `world/valley-east/tree-07/shape` 与 `.../surface`。几何、摆放、材料、运动相位分别使用自己的随机流。新增表面细节不会消费布局随机数；绝对时间和历史模拟的复位另行处理。

**关系进入真实消费者。** 同一布局数据生成承托网格、路径和对象落位；连接从已生成对象的实际锚点/表面求解。资产局部锚点经过当前世界矩阵变换，实例附着需包含实际 instanceMatrix；shader 变形的接触点必须由对应变形求解，静态代理不能证明动态接触。

| 关系 | 在代码中落实 | 扩场前核对 |
|---|---|---|
| 支撑/附着 | 从承托范围与接触足迹求落位、姿态和基部；复杂面用实际表面采样 | 边缘/多足/宽基部均有支撑；非单点命中后直接放整物 |
| 连接/跨越 | 两端真实锚点、局部切线与截面共同生成连接件 | 端点贴合、过渡完整，主尺寸变化后重新求解 |
| 通行/观看 | 路线具有宽、高、转弯与相机/对象体积净空 | 实际发射几何无阻断；同时保留应有框景/遮挡 |
| 生长/邻接 | 宿主、环境条件、间距与遮蔽参与候选筛选 | 对象属于对应区域；群落边缘和内部有区别 |

先生成候选→按宿主/允许区/净空筛选→保存通过点→用同一批结果发射网格和检查。容量按实际计划计算；不足时调整设计或容量并报告，不静默截断。更详细的足迹、表面查询和采样边界使用[分布方法](detail-distribution.md)。

## 4 近中远使用同一个世界

先用目标距离和实际视口估算投影尺寸，再选择表示；距离阈值只是项目输入，不是通用质量常数。

| 层次 | 保留什么 | 由自写规则生成什么 |
|---|---|---|
| 近景 | 剪影转折、厚度、真实孔洞、连接、材料区与动态件 | 正式截面/拓扑、开口内壁、支撑/基部、米制表面与必要内部结构 |
| 中景 | 原型身份、主要体量、可见空隙、遮挡与材料节奏 | 简化分段、成组构件、有限开口与少量共享材质；同族可分块实例化 |
| 远景 | 地形/天际线、轮廓族、主要负形、区域色块和层间关系 | 低段数几何、程序生成的簇/体量或程序立面；省略不可读内面和细件 |

三档读取同一稳定 ID、主尺度、地面基准、原型、关键锚点与材料身份。远景不能把带孔轮廓换成实心块、改掉树冠宽度或移走地标；精简小层不改变世界拓扑。程序立面只承担其能表达的中远表面，靠近时由对应真实洞口/框架接替。

切换前后在同一相机位置比较轮廓、基部、洞口和明暗；沿实际移动路线往返查看跳变、抖动和阴影。采用距离滞回避免临界反复切换；需要交叉淡化时同时处理透明/阴影成本，不能只把 `opacity` 当作完整方案。质量档降低细节后仍保持区域身份与承诺观看范围。

## 5 轻量世界数据示例

以下是原创设计数据，**不是已实现 API**；实现者按当前项目编写消费者。范围与净空是本例设定，可用简图/表格表达同样关系。

```js
const worldPlan = {
  seed: 'valley-study-01', units: 'm',
  regions: [
    {id: 'clearing', boundsXZ: [-9, -8, 10, 9], height: 0,
      role: '观察空间与开阔前景', families: ['station', 'low-plants']},
    {id: 'east-slope', boundsXZ: [10, -20, 28, 25],
      role: '分层树群与谷坡边界', families: ['trees', 'rock-ridges']}
  ],
  routes: [{id: 'entry-walk', pointsXZ: [[-20, 16], [-8, 6], [0, 0]],
    width: 1.8, clearHeight: 2.4}],
  fixedObjects: [{id: 'station-01', region: 'clearing',
    family: 'station', archetype: 'gabled-long', position: [0, 0, -3]}],
  groups: [{id: 'tree-edge-01', region: 'east-slope',
    family: 'trees', archetypeWeights: {'upright-tiered': 3, 'wide-branched': 1},
    count: 18, spacing: [2.4, 5], avoidRoute: 'entry-walk'}],
  relations: [{id: 'walk-to-entry', type: 'connect',
    from: 'entry-walk:end', to: 'station-01:entry'}]
};
```

`boundsXZ` 在本例为 `[minX,minZ,maxX,maxZ]`。`pointsXZ` 只给水平路线，实际路面高度/横断面从最终承托求解；`height: 0` 只适用于本例平地。`entry` 要由真实观察站生成器输出，`:end` 从实际路线末端求得；这些字符串不会自动完成连接。代码应消费 `avoidRoute` 检查完整树冠/基部与路线净空，不能只比较中心点。世界布局可先保存普通数组，只有真实调用需要时再加运行接口。

## 6 按区域完成可建造的接力

按“全场骨架 → 各族代表原型 → 完整代表区域 → 逐区扩展 → 跨区过渡与全貌”推进。每区完成后立即检查真实相机下的区域身份、承托/净空和近景结构；已有工厂用于展柜和场景，避免另写看起来更好的展示模型。

扩场时应已有：可运行的全场草案；能生成各主要原型的函数；稳定布局/种子；接入实际表面与锚点的关系；按景别选择的几何表示；当前区域的全貌和近景结果。完成一个区域仍要回看全场主次；最终统一使用[验收标准](validation.md)，无需新增世界清单协议。
