# 构图、空间与中层形体的构造方法

用于选机位、搭场景、决定主体比例与中层，或定位“齐全却空、薄、散、像通用占位”的画面。开工前从[资产设计](asset-craft.md)进入；本页教设计与构造，几何算法查[代码SOP](threejs-code-sop.md)，最终放行只用[统一验收](validation.md)。

## 1. 把目标画面变成关系，而非物品名单

先看全幅与缩略图，选择影响当前目标的关系填入现有制作规格。观察图中的屏幕事实；尺寸、背面和隐藏连接仍按事实来源或美术设定处理。

| 关系 | 观察与选择 | 进入实现的位置 |
|---|---|---|
| 焦点与观看方式 | 视觉中心、主体占幅、可见顶面/侧面比例、观察高度、主轴/动作方向 | 相机方位/高度、FOV、距离、lookAt与主体姿态 |
| 构图骨架 | 主体和环境的大明暗块、支撑面边缘、主要斜线、留白与裁切用途 | 大体积、开口/光源方向、相机朝向；不是先均匀分配道具 |
| 深度与尺度 | 哪些对象遮谁、地面/台面如何延伸、远近尺寸与层级、空间边界在哪里 | 世界尺度、前后间距、轮廓错开、边界/开口与支撑面 |
| 结构身份 | 宽高深和沿程收放、转折位置、负形、厚度、构件承接 | 关键截面、连接锚点、实体与孔洞、连续/分件策略 |

给决定设计的少数屏幕锚点记归一化位置，例如主体顶/底/轴心、支撑面边缘或背景开口角点。选择需要保留的比例、间隙、遮挡和明暗关系，不从单张图反求唯一真实三维场景。标出的数值是设计输入，后续必须进入相机或生成器的实际消费者。

## 2. 先选择透视，再调占幅

以主体典型高度或已知尺度建立统一单位。保留一份可改的相机配置：`target / azimuth / elevation / distance / fov`，由它计算camera.position和lookAt；姿态与世界尺寸另存，避免每次试镜都改模型比例。

1. **观看高度和方位。** 用主体与支撑面的简单体量定相机侧向与俯仰，让目标中的顶/侧面、负形和环境线索可读。看不到的连接先换方位；不先通过放大细节补偿。
2. **透视关系。** 选择近处与远处相对大小。较近机位通常加强纵深和近大远小；较远机位配较窄FOV可保持占幅并压缩深度。改变FOV而保持相机中心不变，主要改变取景范围；相同占幅下移动机位才会改变透视关系。
3. **取景与焦点。** 透视关系选定后，联合微调距离、target和FOV，把主体占幅、屏幕重心、支撑面边缘和关键负形校到目标关系。避免自动居中包住所有对象，使主体被环境总包围盒缩小。

普通无viewOffset/filmOffset、zoom已纳入有效FOV的透视相机，视轴居中且与成像面平行的高度H，可用`d = H / (2 * 占画面高度比例 * tan(有效垂直FOV/2))`估距离；横向同时受aspect约束。用`camera.getEffectiveFOV()`得到角度并转换为弧度。真实对象有深度/倾斜时只作起点，仍需实际投影与渲染。OrthographicCamera改左右上下视域/zoom控制占幅，移动远近本身不产生透视缩放。

若机位选择尚未确定，用同一代理/材质/光区比较少量有实质差异的方案，例如空间更有纵深与结构更清晰的两个观看方向。选出最能表达目标的方案并记录差距，再细化；不要搜索任意参数组合。相机已由用户或可靠拍摄规格锁定时，保持相机并解决布局/模型。

### 把世界锚点投影到目标视口

以下是有效Three相机、世界点与正视口尺寸下的像素诊断；投影矩阵由调用方在改变FOV/aspect/视域后更新。返回屏幕事实，不评价美观，也不判断点是否被别的物体遮住。

```js
function projectAnchor(camera, worldPoint, width, height) {
  camera.updateWorldMatrix(true, false);
  const view = worldPoint.clone().applyMatrix4(camera.matrixWorldInverse);
  const depth = -view.z;
  if (depth < camera.near || depth > camera.far) return null;
  const ndc = worldPoint.clone().project(camera);
  return {
    u: (ndc.x + 1) / 2, v: (1 - ndc.y) / 2,
    x: (ndc.x + 1) * width / 2, y: (1 - ndc.y) * height / 2,
    depth,
    withinViewport: Math.abs(ndc.x) <= 1 && Math.abs(ndc.y) <= 1
  };
}
```

锚点与几何共用数据：对象局部点先在当前父级世界矩阵更新后`localToWorld()`，再传入此函数；实例、骨骼或shader变形需取实际实例/变形后的点。比较当前投影与目标锚点时，先检查“相机还是形体”在造成差异：相机改变常同时影响多个面与对象的比例；局部截面改变只影响相应结构。世界AABB角点投影只能给保守占幅，不能当作真实可见轮廓；跨near面的盒更不能直接取八角点的min/max当裁切结果。

## 3. 用空间关系构成环境

先用完整代理安排主体所在空间，再铺正式资产。主体、主要环境组和大占幅背景分别承担可见关系；同一套单位、承载面和锚点把它们联系起来。按以下顺序做布局，已由可靠设计锁定的关系直接继承。

| 构造动作 | 实际做法与Three.js落点 | 这一步应读出的关系 |
|---|---|---|
| 定空间骨架 | 搭有厚度的支撑面、边界/开口和主要体积；从目标标出主轴、地面边缘、背景开口及明暗块，投影到目标视口比较 | 主体在哪里、尺度多大、空间向哪里延伸；留白与边缘裁切有用途 |
| 排前中远组 | 按世界深度及横向错位放组，先调组的尺度、轮廓、透空和遮挡，再填组内细节；高占幅背景也先用有代表性的形态族 | 大块节奏和识别性负形成立，近层框景、中层承接、远层收束；远景简化仍保留所需轮廓和层间关系 |
| 定朝向与承载 | 有开口、内容或功能面的资产定义局部front与内容锚点，布局时一起变换；接触位置/法线从实际承载面取得，整体姿态同时遵守重力轴与功能朝向 | 功能面朝向使用区或指定观看方向，内容没有被自身背板/外壳吞掉；不能只查物体存在。数值示例见[局部前向](threejs-code-sop.md#局部前向与内容锚点) |
| 组织群体与光区 | 按用途/生境选择规则阵列、人工落位或簇状分布，再调大小、间距和形态族；让主要亮暗与场景开口/光源及反射来源对应 | 成组关系、疏密和例外有依据，主体轮廓可读；重复布局的落地方法见[环境场](motion-and-scale.md#植被与程序环境共享场而非无关随机数) |

看完整代理的缩略图与原尺寸全幅：若空间仍散、空、遮错，先改组的位置、尺度、朝向或边界。消除一个机位的遮挡时，连同受影响的中景/背景重排；保留有用框景和层间穿插。增加实例之前确认当前缺的是覆盖、形态族、组间关系还是单件结构。

### 从空间计划生成布局

先手工确定有作用的组，再在组内生成变化：例如一组沿路径延伸、另一组形成背景开口、近组承接支撑面。每组保存落点/范围、形态族、尺度与朝向；层次来自组的位置与轮廓，随机只处理组内差异。人工场景可用轴网/模块/重复节奏，自然场景可用地形、生境和簇密度；无需统一成围绕主体的圆环。

用同一个场地数据源生成承载网格、路径和落点。简单单值地形可以共享heightAt，但应核对实际三角网格的插值；复杂岩面、曲面或导入资产从真实表面采样。需要接触位置/法线与局部框架时，用[SOP共享表面示例](threejs-code-sop.md#从实际承载面建立布局和接口)。结果分别进入：

| 消费者 | 从共同数据取得什么 | 仍需要设计什么 |
|---|---|---|
| 植被/道具/构件 | 表面位置、法线、功能前向、组与形态变体 | 重力朝向或随面贴合、尺寸族和疏密 |
| 路面/台阶/岸线 | 路径两侧及转折处的实际承载高度/边界 | 宽度、厚度、路肩/填土或支承体，不能仅抬高中心点 |
| 主体/软体接触 | 接触区域与邻域法线、支点或贴合段 | 连续截面压扁/转向、接触过渡及离面净空 |
| 水/地面反馈 | 最终姿态后的接触锚点、介质高度/法线 | 足迹、涟漪或尘雾的尺度、方向和寿命 |

支撑由多个点或一段表面关系定义。先沿接触轮廓/路径采样，再生成底/侧过渡、变形或支架；单个中心命中只证明该点有表面。相机通道要留出时，移动/错开完整组，并补回受影响的层间承接。布局诊断可看各组覆盖与接触净空；最终构图仍由实际多机位画面选择。

**自由相机的观看内容。** 在声明包络内选择能暴露差异的方位，定每处要读出的内容及允许的遮挡。正面可读核心关系，侧面可读厚度/承接，背面可读后部结构或另一组景观；不要求主体从实体背后仍全露。正常遮挡、环境缺失和画面没有有用信息分别判断。导演镜头按其合法视锥/运镜范围规划；交互场景按完整包络构造，随后实际操作验收。

真实地点保持可靠位置与拓扑；单图未见空间记录为估计或美术设定。数值投影/射线可辅助定位，但不能替代完整画面的构图选择。

## 4. 将中层设计成真实体积关系

中层是主轮廓与微表面之间可见的结构：有方向的收放、承接、层叠、凹入、分枝或受力转折。它应在无花纹、适当侧光下仍改变轮廓、遮挡、平面转折或接触阴影。不是“每个对象加若干小零件”。

从目标选择**决定身份且尚未证明的一段完整结构关系**：主形在哪里收放，如何经过中间体量承托/包裹/嵌入，再进入下一体量、连续体的下一段或负形。样件包括相关主形与过渡两侧；连续体体现转折前后邻域，有装配/分枝关系时体现真实连接。不能用一个孤立零件的正确替代整段关系。已知API能生成孔或曲面，只说明算法可用；当前样件按视觉价值与实际差距选择。

1. **标目标关系。** 在目标局部标轮廓拐点、交界高度、凹凸与遮挡次序，选出决定身份的一段；核对它在整幅的作用。深度与背面不足的部分明确为设定。
2. **把关系变成能独立改的控制量。** 选主轴/路径，先写关键截面的位置、宽/深、偏心和朝向；交界补突出量、转折曲率/折边、厚度及净空。量取相对主形的比例，末端构件、开口与间隙也与相邻体量一起比较。每个待修特征至少有一个能改变它的实际输入：只改细分若不能改变该关系，就应增加控制量或换表示。沿程示例见[SOP截面生成](threejs-code-sop.md#用截面生成连续曲面)。
3. **生成连续体、交界与负形。** 连续体按截面与曲率生成；装配体从共源承载面和局部框架导出子件。洞顶/内壁、折叠间隙和分枝凹部需要真实边界；融合场先核对平滑范围是否吞掉净空。恒厚挤出适合恒厚部分，独立厚度/台肩/层间距离由相应截面驱动；单值高度场只负责可表达的表面，倒扣空间由其他曲面/实体承担。
4. **在最小完整上下文中选择。** 固定机位、种子和中性材料/侧光，比较主形与加入这段中层的结果，另看暴露厚度/负形的方向。只改变与当前缺陷有关的控制量，检查“更宽/深/弯/分离”是否确实发生且整段承接更接近目标。连接、转折尚不成立就继续改对应截面/界面；成立后再分配附属件和表面。

| 形态关系 | 可实施路线 | 关键消费者与局部证明 |
|---|---|---|
| 沿轴/路径连续收放 | 宽深独立的截面loft、变截面扫掠或曲面；轴对称才用回转 | 截面位置/轮廓真正生成顶点；看侧背厚度、转折、截面方向与端口 |
| 壳、凹入和开口 | 内外表面/厚壁、带洞Shape挤出或适当实体建模 | 厚度/洞壁/口沿形成遮挡；绘在表面的深色形状不能承担孔洞 |
| 承接与装配 | 子件局部框架、支撑截面、套接/法兰/台阶或材质接缝 | 锚点与实际表面共源；留缝/穿入有设计量，运动时围绕真实支点 |
| 有机连续体与分枝 | 曲面控制网格、沿骨架的截面/融合、DCC或修整资产 | 体积和曲率连续，分枝有收分与承接；仅摆刚性球柱不自动成为连续皮肤 |
| 地层、侵蚀与沉积 | 相关的脊线/断面/沟谷、共享场与层间边界 | 大形方向约束中层，中层控制实际面；同类结构有节奏和尺度，而非独立白噪声 |

算法入口：截面/扫掠见[代码SOP](threejs-code-sop.md#用截面生成连续曲面)，内腔/回转/孔洞见[截面方法](profile-geometry.md)。平滑法线只改变受光，不能替代正确曲率与几何交接；提高细分前先确认中层形态存在且方向/尺度正确。

**为显著差异选择真正的自由度。** 截面若有平面和圆角，分别定义直段长度、角半径及宽深；整体缩放或单一指数无法独立调整它们。凹入需要边界曲线、深度、口沿及洞壁。连续组织的凸起/眼窝/分枝交界，应进入同一控制网格或融合/差分场，并控制过渡宽度；独立附加件适合有意的装配关系。弯曲柔体先把接触段、离面段和转向段写入路径，再分别控制腹背/侧向截面，附件从最终表面框架派生。选择这些输入后，实际移动一次，确认对应顶点/负形及接触邻域随之改变。

## 5. 按当前责任层比较，再扩展

把试作分成“机位/空间选定→主要中层样件→完整代表镜头”，每步保留当时实际画面与选择。改机位或布局后重看整体关系，改形体后重看目标/侧背与受影响接触。已有同目标、同构建的通过证据可继承；构图/形体是当前待优化项时，旧画面不能替新方案通过。

| 当前要判断 | 最少有用的比较 | 解释与后续 |
|---|---|---|
| 构图与空间 | 同一完整代理的目标机位与可比较备选；若机位锁定则比较实际布局方案 | 缩略图看焦点/明暗块，整幅看尺度、遮挡与负形；选定机位和布局后再细化 |
| 中层 | 同机位、相同灰材质/侧光的主形与新增中层，另看最能暴露厚度/连接的视角 | 应读出结构而不是仅“变复杂”；无对应收益就重选截面/交接，不能靠纹样替代 |
| 完整镜头 | 最终光材质的原尺寸全幅与目标，含必要相邻时刻 | 局部进步不能牺牲整场主次；按[统一验收](validation.md#核心镜头放行标准)记录真正的品质差距 |

每步比较服务当前未知：先写清要区分的解释和能改变它的输入，再选择最小完整样件；具体批次组织见[生产流程](production-workflow.md#3-代表画面实现与差异校准)。不为已定事项制作固定数量候选。两轮同层微调没有对应可见改善时，回到上一层的设计/表示选择；数值对齐、素材数量和诊断脚本PASS分别只说明其覆盖的事实。
