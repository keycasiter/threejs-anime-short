# 程序资源、视觉参考与声音

本分支用Three.js、JavaScript和自定义shader从设计参数构建三维作品。对象几何由当前工程生成，不接入下载、扫描、AI或DCC导出的预制模型；把这些网格编码成base64、顶点数组或JS文件仍属于引入模型。几何算法库可以参与构造，条件见[库接线](library-integration.md)。

## 设计参考如何进入代码

| 输入 | 提炼与实际消费者 |
|---|---|
| 照片、视频、设计图、生成参考图 | 提炼轮廓、截面/比例、材料分区、光区和空间关系，交给[可生成规格](procedural-design.md)与[构造配方](procedural-construction.md)；参考图不作为场景背景或物件替身 |
| 平面/CAD、地图、尺寸与测量记录 | 核对来源、比例、轴向和高程基准，把边界/尺寸/路线转为共享设计参数，再由生成器创建地面、墙体、路径等几何 |
| 代码配方与算法库 | 锁定版本和单位，确认生成步骤和消费者，做一个完整代表关系；复用代码能力，不复制第三方成品场景的隐藏数据 |

参考覆盖宏观、主要组成、连接与表面；数量随未知问题决定，不用同角度重复图充数。生图用于探索候选、补侧背设定、研究材料/光色；多视角仍需核对身份、比例与连接。用户已选方向或授权自行设计时，由执行者完成具体构造选择。

## 在代码里生成可复用资源

| 资源 | 可执行方向 | 质量与接入条件 |
|---|---|---|
| 表面 | `CanvasTexture`、`DataTexture`、程序场/GLSL；已有[材质目录](../assets/materials/procedural-palette.mjs)和通道烘焙 | 材料形成区域、物理tile、颜色/数据空间、UV/切线和实际Material消费；颜色纹样不能代替主形、厚度或开口 |
| 标签/标线 | Canvas或程序字形，按最终曲面/UV贴合 | 标识尺度、朝向、边缘和可见距离；图案不漂移，不重复叠加宏观构造 |
| 天空/反射 | 程序天空、场景Cube/PMREM、实际镜像RT | 可见环境与受光一致，捕获对象/时机/成本明确；能力边界见[制作工具](production-toolkit.md) |
| 动作与骨骼 | 代码创建枢轴、曲线、Bone/Skeleton与权重，程序轨迹或关键帧 | 网格/枢轴/接触共源；跳时、复位和历史明确，见[动作与规模](motion-and-scale.md) |
| 声音 | Web Audio振荡器、噪声、滤波/包络与有界声部；叙事需要时接入获准的旁白/声音工具 | 实际试听音色、节奏、层级与循环；共享事件决定起点，静音/暂停与用户手势初始化可用 |

默认缓存有限的材料/几何变体，同类实例共享。异步生成使用稳定ID/版本，放入真实场景并预热后才算READY。项目离线交付包含依赖及许可，资源销毁服从所有权；技术成功与实际审图/试听分别记录。

## 生成困难时如何继续

先定位轮廓、拓扑/连接、表面或受光责任层。轮廓失败改截面/控制网格；洞口失败改开孔拓扑；复杂分叉改连续场或分支网格；材质失败修区域、度量与环境；预算失败改变远距表示、合并/实例和更新频率。保持必要视觉目标，选择同一代码路线中更合适的表示，不自动回退为导入模型或固定视图效果图。

生成器及其设计数据、参数、seed和资源清单共同交付，使对象可重新生成。实现在当前预算下仍不充分时，明确剩余缺口；不得通过缩小观看范围、降低目标或隐藏代理来追认完成。
