## 1 每个主要对象的构造顺序

| 子步骤 | 原子动作 | 真正产生的内容 |
|---|---|---|
| 主轴/轮廓 | 确定局部坐标、尺寸基准、关键截面宽深和收分；相机下看侧背体积 | 可控制的剖面/控制网格与主壳，不由高频噪声定义主形 |
| 中层分段 | 把结构转折、开间/节段、层次、分叉、支撑和功能界面分开控制 | 同类对象可共享的结构参数与原型差异 |
| 壳壁/负形 | 明确外壁、内壁、开口边界、壁厚和端面；孔洞贯穿该贯穿的全部层 | 实际可见的凹入、洞壁、口沿和遮挡，去掉无意挡在窗口后的实心面 |
| 连接/承载 | 接头、枢轴与支承从最终形体/锚点派生，区分刚接、搭接、活动与有意嵌入 | 实际附件位置、方向、接触面和活动层级 |
| UV/材料区 | 每个表面有材料身份、形成区域、方向与米制尺度；共享字段进入所需通道 | 正确法线/切线、颜色、roughness/metalness和必要表面数据 |
| 上下文/受光 | 加相邻地面/物体与目标环境，设计主光、暗部和反射内容，再看互补视图 | 结构在实际像素中的厚度、连接、材料差异与空间层次 |

完整构造不等于所有地方平均增加零件。优先使近/中景可见的轮廓、结构界面、材料边界和接触成立；远处保留身份与空间节奏。风格化可简化纹理，仍要有清楚的体量、结构和材料响应。

## 2 按结构选择算法

| 结构 | 具体生成方法 | 细节如何依附 / API方向 |
|---|---|---|
| 板、框、墙、面板 | 外轮廓和全部孔洞从同一二维数据产生；挤出有限厚度；按孔边界建框、密封或台口 | `Shape.holes`/`ExtrudeGeometry`；已有`createPerforatedPlate`。物体多层时逐层开洞，窗后真实内容单独建立 |
| 回转壳、管、口沿 | 沿主轴设计外/内剖面，显式决定肩部、收分、硬折和端环；按弧长分配采样 | `LatheGeometry`或已有`createRevolvedShell`；内剖面不是自动等壁厚，配方须检查最薄区域和端部连接 |
| 长体、弯管、枝干 | 沿路径放控制站：宽/深、偏心、旋转、收分；相邻站连接；变化大处增加站 | `BufferGeometry`分站放样或扫掠；附件读取相同截面与局部框架。固定半径Tube不负责全部腹背差异 |
| 连续有机体/复杂分叉 | 从骨架/控制笼或显式体积场产生连续表面，处理分叉处拓扑和曲率，再布组织分区 | 项目实现控制网格或场→网格提取；需要阴影/拾取/接触时优先有实际网格。仅把球柱相交不能形成全部连续皮肤 |
| 地形/岩层/侵蚀 | 先脊线、谷地、台地与断面，再局部冲刷/崩塌场，最后较细尺度起伏 | 单值部分用共享高度场；洞穴/悬挑使用完整曲面或实体。坡度/水线等同时驱动材料与分布 |
| 自然群体/建筑群 | 先生成有结构差异的原型，再按区域、宿主和局部框架组团 | `InstancedMesh`或静态合并；同拓扑一批，种子按区域/对象/用途派生，不只改颜色和缩放 |

分站放样、体积场提取、分枝拓扑等不是Skill已提供的万能生成器；先把控制数据和最难连接做成一个项目小样。复杂实体布尔与高密求交可按[库接线](library-integration.md)选算法库。本分支不以导入模型回退造型困难。

## 3 真实开口、厚度与锚点装配

[参数化开间](../assets/examples/procedural-bay.mjs)是独立原创的构造样件，展示壁体、洞壁、框、台口、顶部/底部带和真实接口。它不是完整楼房，也不是所有对象的模板。

```js
import {buildArchitecturalBay} from './assets/examples/procedural-bay.mjs';
import {placeAtAnchor} from './assets/scene/anchor-connection.mjs';
// THREE、scene、palette来自当前锁定工程；所有尺寸为米。
const materials = {
  wall: palette.get('stone', {tileSizeMeters:[1,1]}),
  trim: palette.get('coated-metal', {tileSizeMeters:[1,1]})
};
const first = buildArchitecturalBay(THREE, {width:3, materials});
const second = buildArchitecturalBay(THREE, {
  width:2.7, variant:'arch', materials
});
scene.add(first.root);
placeAtAnchor(THREE, {
  host:first, hostAnchor:'bay.right',
  guest:second, guestAnchor:'bay.left', parent:scene
});
```

改变width或洞形会重建实际墙体、贯穿洞、框和锚点。默认无玻璃，射线能穿过洞口；传`materials.glass`只增加玻璃层，不增加实心背板。门洞到地面、偏心洞、哥特/椭圆拱不在这个样件范围，需按同源轮廓方法另建相应生成器，不能调整无效参数追认支持。

输出`root/parts/spec/anchors/dispose`；`parts`含`wall/frame/sill/header/plinth`和可选`glass`。单元局部+Y向上、+Z为立面前方；锚点为局部Matrix4。`bay.left/right`的+Z朝对应外侧，装配器默认反转接口法线使两者相对；接口的up保持一致。各端点与开口语义见源码，不假设它们都只有平移。

`placeAtAnchor`实际求：

`guestLocal = inverse(parentWorld) × hostWorld × hostPort × opposedTurn × inverse(guestPort)`

它要求host/parent祖先链与guest子树保持世界矩阵自动更新；更新矩阵、验证刚性单位尺度后再写guest的parent与TRS；输入锚点不被修改。尺寸由几何参数生成，根scale保持1，避免拉伸物理UV。中心接口对齐不意味着不同高度对象的地脚自动齐平；需要地脚对齐时选择对应结构端口或按设计建立新端口。连接对齐后另查承载、穿插与可见接缝。

生成器拥有生成几何，借用材料；`dispose()`只释放自有几何。表面为每米UV且已算切线；换tile需要匹配UV度量。分面拱只支持偶数8–64段半圆顶，尺寸/净距约束见源码。用同一工厂在展柜和场景中生成，不保留第二套简化替身。

## 4 让表面和受光一起完成

1. **先划形成区。** 材料身份、接缝、边缘/接触、使用或生长方向来自构造数据；确定哪些地方洁净、磨损、潮湿或半透。不是每件物体都要做旧。
2. **写同源通道。** 同一区域决定需要的颜色、roughness、metalness和高度/法线；涂层露底才改变金属度，纯颜色变化未必产生凹凸。已有[程序材质目录](../assets/materials/procedural-palette.mjs)与[字段烘焙](surface-detail.md)。
3. **接物理尺度。** 运行几何的UV、tile、切线与高度单位一致。装配器不保留输入tangent时在最终几何上按[工具接线](production-toolkit.md)重建；不抹掉硬边与UV边界。
4. **建立实际环境。** 先主光与阴影，再程序天空/PMREM和必要局部探针；只有画面需要场景镜像时再加真实平面/适合的反射源。
5. **看目标关系。** 固定镜头与曝光，转物/转灯看结构转折和材料差异，再补小尺度颗粒、AO或有限高亮扩散。若几何与材料区本身错误，返回对应层修正。

玻璃要按目标决定反射、透射和窗后可读性。需要看内部时，用适合的Physical传输配置、实际开口与窗后物件/受光一起实现；不能只把深色面改透明，背后的实心壳仍会遮挡。金属、高光、半透组织和流体各有不同责任，不把一个材质预设套到全部对象。现有反射/天气/后期工具的能力范围与扩展方向见[可调用工具](production-toolkit.md)。

## 5 动作与场景反馈

从因果与接触建立动作。机械先枢轴/连杆/限位；自然体先主干或波面，再从属枝叶/泡沫；角色先代码骨架与连续网格/权重，再步态和支撑。解析轨迹适合预定动作；需要累计物理时另接固定步长与历史重置。

| 链路 | 实际代码责任 |
|---|---|
| 输入→状态 | 统一时间、事件与对象ID；交互改变真实状态，离线镜头使用记录/设定输入 |
| 状态→形体 | 枢轴、骨骼、曲面或instance buffer读取同一参数，法线/包围体同步 |
| 形体→接触 | 最终表面、活动锚点或等价求值提供真实位置/方向；不继续读取静止代理 |
| 接触→反馈 | 有界粒子、局部光、声音与表面状态按事件生成；具体层由题材决定 |
| 冻结/复位 | 解析层按绝对时间；历史层复位并重放，曝光/后期历史各自管理 |

## 6 第一轮代码的结束点

应有能真实运行的全场草案、一个最能决定画质的完整代表关系、共享生成数据和相机/时间状态。近景及互补角度已查看，主要对象和邻接环境的构造/表面/受光有实际消费者，尺寸变化时接口能重新装配。

随后按资产族和空间组团扩展，控制几何、纹理、光/反射遍和动态成本。结构统计与测试通过不代替审图；制作方法与机制例也不证明整场已达参考品质。参考研究只提供算法与组织依据，原作者的未公开提示词/过程和模型能力差异不从最终源码推定。
