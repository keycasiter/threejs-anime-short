## 1 每个主要对象的构造顺序

| 子步骤 | 原子动作 | 真正产生的内容 |
|---|---|---|
| 主轴/轮廓 | 确定局部坐标、尺寸基准、关键截面宽深和收分；相机下看侧背体积 | 可控制的剖面/控制网格与主壳，不由高频噪声定义主形 |
| 中层分段 | 把结构转折、开间/节段、层次、分叉、支撑和功能界面分开控制 | 同类对象可共享的结构参数与原型差异 |
| 壳壁/负形 | 明确外壁、内壁、开口边界、壁厚和端面；孔洞贯穿该贯穿的全部层 | 实际可见的凹入、洞壁、口沿和遮挡，去掉无意挡在窗口后的实心面 |
| 连接/承载 | 接头、枢轴与支承从最终形体/锚点派生，区分刚接、搭接、活动与有意嵌入 | 实际附件位置、方向、接触面和活动层级 |
| UV/材料区 | 每个表面有材料身份、形成区域、方向与米制尺度；共享字段进入所需通道 | 正确法线/切线、颜色、roughness/metalness和必要表面数据 |
| 上下文/受光 | 加相邻地面/物体与目标环境，设计主光、暗部和反射内容，再看互补视图 | 结构在实际像素中的厚度、连接、材料差异与空间层次 |

完整构造不等于所有地方平均增加零件。优先使近/中景可见的轮廓、结构界面、材料边界和接触成立；远处保留身份与空间节奏。风格化可简化纹理，仍要有清楚的体量、结构和材料响应。

## 2 按结构选择算法

| 结构 | 具体生成方法 | 细节如何依附 / API方向 |
|---|---|---|
| 板、框、墙、面板 | 外轮廓和全部孔洞从同一二维数据产生；挤出有限厚度；按孔边界建框、密封或台口 | `Shape.holes`/`ExtrudeGeometry`；已有`createPerforatedPlate`。物体多层时逐层开洞，窗后真实内容单独建立 |
| 回转壳、管、口沿 | 沿主轴设计外/内剖面，显式决定肩部、收分、硬折和端环；按弧长分配采样 | `LatheGeometry`或已有`createRevolvedShell`；内剖面不是自动等壁厚，配方须检查最薄区域和端部连接 |
| 长体、弯管、枝干 | 沿路径放控制站：宽/深、偏心、旋转、收分；相邻站连接；变化大处增加站 | `BufferGeometry`分站放样或扫掠；附件读取相同截面与局部框架。固定半径Tube不负责全部腹背差异 |
| 连续有机体/复杂分叉 | 从骨架/控制笼或显式体积场产生连续表面，处理分叉处拓扑和曲率，再布组织分区 | 项目实现控制网格或场→网格提取；需要阴影/拾取/接触时优先有实际网格。仅把球柱相交不能形成全部连续皮肤 |
| 地形/岩层/侵蚀 | 先脊线、谷地、台地与断面，再局部冲刷/崩塌场，最后较细尺度起伏 | 单值部分用共享高度场；洞穴/悬挑使用完整曲面或实体。坡度/水线等同时驱动材料与分布 |
| 自然群体/建筑群 | 先生成有结构差异的原型，再按区域、宿主和局部框架组团 | `InstancedMesh`或静态合并；同拓扑一批，种子按区域/对象/用途派生，不只改颜色和缩放 |

分站放样、体积场提取、分枝拓扑等不是Skill已提供的万能生成器；先把控制数据和最难连接做成一个项目小样。复杂实体布尔与高密求交可按[库接线](library-integration.md)选算法库。本分支不以导入模型回退造型困难。

## 3 真实开口、厚度与锚点装配

[参数化开间](../assets/examples/procedural-bay.mjs)是独立原创的构造样件，展示壁体、洞壁、框、台口、顶部/底部带和真实接口。它不是完整楼房，也不是所有对象的模板。

```js
import {buildArchitecturalBay} from './assets/examples/procedural-bay.mjs';
import {placeAtAnchor} from './assets/scene/anchor-connection.mjs';
// THREE、scene、palette来自当前锁定工程；所有尺寸为米。
const materials = {
  wall: palette.get('stone', {tileSizeMeters:[1,1]}),
  trim: palette.get('coated-metal', {tileSizeMeters:[1,1]})
};
const first = buildArchitecturalBay(THREE, {width:3, materials});
const second = buildArchitecturalBay(THREE, {
  width:2.7, variant:'arch', materials
});
scene.add(first.root);
placeAtAnchor(THREE, {
  host:first, hostAnchor:'bay.right',
  guest:second, guestAnchor:'bay.left', parent:scene
});
```

改变width或洞形会重建实际墙体、贯穿洞、框和锚点。默认无玻璃，射线能穿过洞口；传`materials.glass`只增加玻璃层，不增加实心背板。门洞到地面、偏心洞、哥特/椭圆拱不在这个样件范围，需按同源轮廓方法另建相应生成器，不能调整无效参数追认支持。

输出`root/parts/spec/anchors/dispose`；`parts`含`wall/frame/sill/header/plinth`和可选`glass`。单元局部+Y向上、+Z为立面前方；锚点为局部Matrix4。`bay.left/right`的+Z朝对应外侧，装配器默认反转接口法线使两者相对；接口的up保持一致。各端点与开口语义见源码，不假设它们都只有平移。

`placeAtAnchor`实际求：

`guestLocal = inverse(parentWorld) × hostWorld × hostPort × opposedTurn × inverse(guestPort)`

它要求host/parent祖先链与guest子树保持世界矩阵自动更新；更新矩阵、验证刚性单位尺度后再写guest的parent与TRS；输入锚点不被修改。尺寸由几何参数生成，根scale保持1，避免拉伸物理UV。中心接口对齐不意味着不同高度对象的地脚自动齐平；需要地脚对齐时选择对应结构端口或按设计建立新端口。连接对齐后另查承载、穿插与可见接缝。

生成器拥有生成几何，借用材料；`dispose()`只释放自有几何。表面为每米UV且已算切线；换tile需要匹配UV度量。分面拱只支持偶数8–64段半圆顶，尺寸/净距约束见源码。用同一工厂在展柜和场景中生成，不保留第二套简化替身。

## 4 让表面和受光一起完成

1. **先划形成区。** 材料身份、接缝、边缘/接触、使用或生长方向来自构造数据；确定哪些地方洁净、磨损、潮湿或半透。不是每件物体都要做旧。
2. **写同源通道。** 同一区域决定需要的颜色、roughness、metalness和高度/法线；涂层露底才改变金属度，纯颜色变化未必产生凹凸。已有[程序材质目录](../assets/materials/procedural-palette.mjs)与[字段烘焙](surface-detail.md)。
3. **接物理尺度。** 运行几何的UV、tile、切线与高度单位一致。装配器不保留输入tangent时在最终几何上按[工具接线](production-toolkit.md)重建；不抹掉硬边与UV边界。
4. **建立实际环境。** 先主光与阴影，再程序天空/PMREM和必要局部探针；只有画面需要场景镜像时再加真实平面/适合的反射源。
5. **看目标关系。** 固定镜头与曝光，转物/转灯看结构转折和材料差异，再补小尺度颗粒、AO或有限高亮扩散。若几何与材料区本身错误，返回对应层修正。

玻璃要按目标决定反射、透射和窗后可读性。需要看内部时，用适合的Physical传输配置、实际开口与窗后物件/受光一起实现；不能只把深色面改透明，背后的实心壳仍会遮挡。金属、高光、半透组织和流体各有不同责任，不把一个材质预设套到全部对象。现有反射/天气/后期工具的能力范围与扩展方向见[可调用工具](production-toolkit.md)。

## 中层控制：把转折与连接做成可独立调整的输入

中层是主轮廓与微表面之间可见的结构：有方向的收放、承接、层叠、凹入、分枝或受力转折。它应在无花纹、适当侧光下仍改变轮廓、遮挡、平面转折或接触阴影。不是“每个对象加若干小零件”。

从目标选择**决定身份且尚未证明的一段完整结构关系**：主形在哪里收放，如何经过中间体量承托/包裹/嵌入，再进入下一体量、连续体的下一段或负形。样件包括相关主形与过渡两侧；连续体体现转折前后邻域，有装配/分枝关系时体现真实连接。不能用一个孤立零件的正确替代整段关系。已知API能生成孔或曲面，只说明算法可用；当前样件按视觉价值与实际差距选择。

1. **标目标关系。** 在目标局部标轮廓拐点、交界高度、凹凸与遮挡次序，选出决定身份的一段；核对它在整幅的作用。深度与背面不足的部分明确为设定。
2. **把关系变成能独立改的控制量。** 选主轴/路径，以总长/宽/高归一化参考中的交界站位，分别记录各段占比、直段/曲段、宽深、偏心及朝向；外轮廓与开口/材料区边界分别标注。透视图推得的比例标为设计估计，不当成实测。先把这些站位、段间转折、开口上下界和构件厚度写入实际生成输入，再作候选；整体bounds或已放行的代理体不能提供这些内部比例。每个待修特征须有直接控制量：两种相近的整体缩放/曲率变化若都缺少目标分段，先改分段表示，再比较局部参数。交界补突出量、折边与净空，末端构件、开口和间隙连同相邻体量比较。沿程代码见[SOP截面生成](geometry-recipes.md#用截面生成连续曲面)。
3. **生成连续体、交界与负形。** 连续体按截面与曲率生成；装配体从共源承载面和局部框架导出子件。洞顶/内壁、折叠间隙和分枝凹部需要真实边界；融合场先核对平滑范围是否吞掉净空。恒厚挤出适合恒厚部分，独立厚度/台肩/层间距离由相应截面驱动；单值高度场只负责可表达的表面，倒扣空间由其他曲面/实体承担。
4. **在最小完整上下文中选择。** 固定机位、种子和中性材料/侧光，比较主形与加入这段中层的结果，另看暴露厚度/负形的方向。只改变与当前缺陷有关的控制量，检查“更宽/深/弯/分离”是否确实发生且整段承接更接近目标。连接、转折尚不成立就继续改对应截面/界面；成立后再分配附属件和表面。

| 形态关系 | 可实施路线 | 关键消费者与局部证明 |
|---|---|---|
| 沿轴/路径连续收放 | 宽深独立的截面loft、变截面扫掠或曲面；轴对称才用回转 | 截面位置/轮廓真正生成顶点；看侧背厚度、转折、截面方向与端口 |
| 壳、凹入和开口 | 内外表面/厚壁、带洞Shape挤出或适当实体建模 | 厚度/洞壁/口沿形成遮挡；绘在表面的深色形状不能承担孔洞 |
| 承接与装配 | 子件局部框架、支撑截面、套接/法兰/台阶或材质接缝 | 锚点与实际表面共源；留缝/穿入有设计量，运动时围绕真实支点 |
| 有机连续体与分枝 | 曲面控制网格、沿骨架的截面/融合、显式体积场与网格提取 | 体积和曲率连续，分枝有收分与承接；仅摆刚性球柱不自动成为连续皮肤 |
| 地层、侵蚀与沉积 | 相关的脊线/断面/沟谷、共享场与层间边界 | 大形方向约束中层，中层控制实际面；同类结构有节奏和尺度，而非独立白噪声 |

连接到曲面或斜向路径时，用实际路径的端点切线建立接头局部框架；沿接头周界向明确的宿主网格采样，得到各点的贴合深度，再生成有厚度的收口/过渡件。周界深度不同就保留差异，不以一个平面圆环代替曲面承接；采样漏失时先重选接口范围或表示。轴线对齐与法兰本身有孔只证明局部条件，接头仍需连同壳面、边界及管段一起建造。

大截面需要急转或局部形变时，先按[转向与形变设计](geometry-recipes.md#给转向与局部形变保留足够空间)分配过渡范围和局部参考方向，再生成正式网格；不要等闭合壳体出现黑斑后只调法线或灯光。

算法入口：截面/扫掠见[代码SOP](geometry-recipes.md#用截面生成连续曲面)，内腔/回转/孔洞见[截面方法](profile-geometry.md)。平滑法线只改变受光，不能替代正确曲率与几何交接；提高细分前先确认中层形态存在且方向/尺度正确。

**为显著差异选择真正的自由度。** 截面若有平面和圆角，分别定义直段长度、角半径及宽深；整体缩放或单一指数无法独立调整它们。凹入需要边界曲线、深度、口沿及洞壁。连续组织的凸起/眼窝/分枝交界，应进入同一控制网格或融合/差分场，并控制过渡宽度；独立附加件适合有意的装配关系。弯曲柔体先把接触段、离面段和转向段写入路径，再分别控制腹背/侧向截面，附件从最终表面框架派生。选择这些输入后，实际移动一次，确认对应顶点/负形及接触邻域随之改变。

## 静态装配与活动层级

[资产装配器](../assets/scene/asset-assembly.mjs)提供已经实现的接口；跨对象端口放置可调用[锚点装配](../assets/scene/anchor-connection.mjs)，实际例见[参数化开间](../assets/examples/procedural-bay.mjs)。静态装配接口如下：

```js
import {createAssetAssembly} from './asset-assembly.mjs';
// THREE与mergeGeometries由同一锁定版本注入。
const assembly = createAssetAssembly(THREE, {mergeGeometries});
assembly.add(panelGeometry, shellMaterial, {
  matrix: panelLocalMatrix, castShadow: true, receiveShadow: true, layers: 1,
});
assembly.dynamic(doorPivot); // 尚无parent的真实活动层级
assembly.anchor('mount', mountLocalMatrix);
const asset = assembly.finish();
scene.add(asset.root);
// asset.anchors是Map<string, Matrix4>，均为资产局部坐标。
```

它克隆输入几何、烘焙局部变换，以材质UUID/阴影/图层分桶，并兼容索引/非索引及基础属性；动件保留。输出stats是结构统计，不是GPU draw calls或美观评分。它拒绝镜像/退化变换、morph/skin/实例属性等不适合此静态路径的输入；这些对象走独立运行分支。已有多材质geometry先提取成对应子几何与材质，再送入；不会按geometry.groups自动分材质。

`finish()`结果可复用，之后不能再add；`dispose()`只释放装配器创建的静态几何。输入geometry/material和动态子树由调用者管理。生成工厂应统一回收临时几何以及自有动件几何，避免把“可重复生成”变成显存泄漏。

可直接运行的组合例子：[有铰链与通风开孔的设备箱](../assets/examples/hinged-cabinet.mjs)。它组合已有真实开孔板与新装配器，返回活动门、静态局部锚点与`setOpen(open)`；`serviceClosed`是闭门布局快照，`parts.serviceAnchor`是门下随动Object3D，使用`getWorldPosition()`取得实际服务点。展柜与场景都调用`buildHingedCabinet`。示例证明接口、结构与连接方法；不同题材的最终美术仍需重新设计。

## 变体、缓存与动作接口

缓存键包含所有影响结构的尺寸、拓扑选择与种子；材质目录作为上下文，避免跨项目拿到别人的材料。几何原型、实例变换和表面变化分别管理，有意统一的设计无需强加随机原型。动态枢轴/骨骼保留独立层级；静态合并后不再按旧子件改位置。

动作与接触读[运行与规模](motion-and-scale.md)；风、湿区、事件或时间必须进入实际mesh、uniform、instance buffer或动件。解析层按绝对时间重算，历史层复位重放，阴影/反射/拾取使用相应变形表示。完整代表关系与全场同源，不能另写更漂亮但不进入交付的展柜模型。
