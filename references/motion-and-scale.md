# 程序对象、动画、GPU状态与场景规模

用于代码生成的角色/机械、程序植被、GPU粒子、地形和大量可交互对象。API按当前安装版本和官方文档核对；渲染侧约束见 [rendering-choices.md](rendering-choices.md)。选技术前确认近景需要、运动方式、目标设备和是否必须随机跳帧。

场景资产的整体细节生产顺序、放置清单和分布图验收见[细节与分布 SOP](detail-distribution.md)；本页补充植被、GPU状态、动画与性能方法。

选解析运动、IK/群集、布绳约束、刚体或导航时读[运动算法选择](algorithm-recipes.md#运动导航与规模)，明确尺度、dt和真实状态消费者后再接库；已有确定动作不必加载物理引擎。

## 运行预检与公共接口

先锁定Three/addons同版本及单一模块实例、renderer后端、目标视口与精确输出尺寸。确认依赖实际可用后运行真实WebGL场景，检查资源请求、shader/console和像素；再建正式资产。CDN/registry失败先查工程已有包和可校验离线缓存，不把缺少包管理索引误当没有依赖。

浏览器启动失败与renderer创建失败分开定位。受支持的系统Chrome/Chromium headless+CDP、本地浏览器自动化或可用MCP都可做自身项目验证；使用独立临时profile和同一目标入口。启动成功后仍需真实canvas/后端读回。软件WebGL只能证明该软件路径可绘制，不能推断硬件性能。工具明确拒绝的目标不换入口绕过。

初始化依赖：renderer/scene/camera→公共材料与字段→工厂→布局/动态→环境探针与预热→统一帧循环。项目接口保存确实共享的seed、quality、clock、fields与事件；工厂返回真实root/局部anchors/动件/dispose，消费者要进入当前mesh、Material、uniform或buffer。已有接口见[工具目录](production-toolkit.md)。

## 从构造数据到运行对象

完整链为：设计/共享参数 → 几何、UV/法线、材质区域、代码骨架/动作 → 实例或合并 → 程序预热 → 运行与释放。代码路线的具体建造顺序见[构造配方](procedural-construction.md)，空间扩展见[程序世界](scene-layout.md)。本分支不接入GLTF/FBX/OBJ等预制模型或外部角色动画包。

由同一份结构数据创建Object3D层级或Bone/Skeleton；柔性网格显式生成skinIndex/skinWeight并bind，机械刚件可各自随一个骨骼或枢轴。动作可用解析轨迹或代码创建KeyframeTrack/AnimationClip；导入动画的便利不能替代本工程的结构和接触设计。树、机械与连续软组织需要不同的生成/变形表示。

生成完成后更新世界矩阵再核对包围盒、单位、up axis、根缩放、pivot、材料角色和活动范围。READY包含真实生成对象与关键程序预热；worker/纹理失败不能用空对象继续交付。压缩的程序缓存仍须绑定生成器、参数和版本，修改输入时重建。

资源共享与销毁明确归属：替换对象时停止并uncache私有mixer，解绑事件/RAF，释放私有geometry、material、texture、render targets、PMREM结果与worker；共享对象保留引用关系，避免销毁仍被使用的资源。移出scene不等于释放GPU资源。

## 骨骼、动作与接触：绝对时间之后仍要约束

克隆蒙皮角色优先使用`SkeletonUtils.clone`，保证骨骼引用重新映射；普通Object3D.clone不保证得到独立骨架。骨架独立不等于geometry/material也独立，需要单角色换材质或修改几何时再复制对应资源。

推荐求值顺序：

```text
t → clip区间、循环与速度映射 → 明确action权重/时间/启停
  → 动画求值 → root motion与支撑脚约束/IK
  → updateMatrixWorld + skeleton更新 → 变形后锚点/包围体
  → 更新加速结构、捕获/阴影/渲染
```

`AnimationMixer.setTime(t)`会重置mixer和action的time再update，但输入仍受`mixer.timeScale`影响：设成0暂停后再setTime会得到0时刻。它也不是所有crossfade、warp、循环事件和未跟踪transform的通用重置器。按时间明确配置权重/动作状态，清理依赖历史的fade/warp，恢复需要的基准姿势，避免每次seek再叠一次`.play()`或以事件回调累加状态。R3F的`useAnimations`负责生命周期和update，不自动提供影片所需的无历史求值。

脚底固定需要支撑阶段、世界空间脚锚点和root/髋/腿链共同修正；动画clip会动不代表接地成立。先读最终蒙皮/形变位置再计算接触；近景不要拿静止geometry顶点作为脚底。`getVertexPosition`可读取当前蒙皮/morph后的局部顶点，再转世界空间；shader独有变形需另有一致的CPU锚点或GPU读回，CPU原几何无法知道它。

脚锁锚点来自明确支撑区间或可重建的状态，不从“上一帧脚在哪”临时猜。测试首尾、循环缝、换动作、连续播放与乱序seek，分别检查身体重心、足底滑动与接触误差；骨骼API通过不等于表演自然。

## 程序角色的姿势约束

分件角色用FK设计姿势，两骨IK保持端点。设肩/髋到目标距离为L、两段长度为a/b，则沿目标方向的投影为`x=(a²-b²+L²)/(2L)`，垂直偏移为`h=sqrt(max(0,a²-x²))`，用pole方向确定弯曲平面。先约束可达距离，处理零距离、pole平行和极限伸展退化。IK之外仍需设计支撑相、重心、预备/发力/收势及躯干滞后。

长体沿弧长采样中心线和连续局部坐标架；处理切线/法向平行、坐标架翻转、端点外延与四元数同半球插值。附属物、GPU形变与CPU锚点使用同一映射；不能只用中心线近似最终表面接触。

## 粒子和物理：区分解析时间与历史积分

解析式`position=f(seed,id,t)`可直接取时刻；GPUComputationRenderer纹理ping-pong、TSL storage compute和物理step通常是`state[n+1]=F(state[n],dt)`。给后者换一个time uniform不会复原位置、速度、寿命、碰撞和交互历史。

官方WebGL GPGPU通过变量依赖、初始化texture及双缓冲更新；TSL compute通过storage/instanceIndex更新GPU缓冲，渲染材质再读取同一状态。流场demo的链为初始形体属性 → position/life/strength缓冲 → curl场积分及寿命回收 → 节点材质，不是“噪声移动顶点”一句话即可替代。

影片改造按成本选择：解析近似；固定seed+固定dt从初态重放；带版本/输入hash的检查点；预计算缓存。检查点需包含速度、寿命、交互输入等完整状态，不只存position。重置ping-pong两侧、compute缓冲、累积效果和随机源；尾端不足一步按明确策略处理。实时鼠标/物理事件先录入时间线，不能从当前鼠标位置决定历史画面。

新TSL示例和旧GLSL计算纹理只是两条实现路径。确认目标GPU、storage/纹理格式、readback和fallback能力后再选；设备支持WebGL2不等于支持任意WebGPU compute。局部storage重置与重放的验证不代表完整粒子/物理系统通过。避免逐帧大量GPU→CPU读回；数值锚点与渲染尽量共享解析关系，确需读回时计入异步导出协议。

## 植被与程序环境：共享场，而非无关随机数

重复环境先从目标空间确定轮廓和透空，再选分布方法：规则阵列、人工位置与成簇过程各有用途。需要自然聚集或局部密度变化时，可按“分布区→簇→成员→承载面”生成；下面展开这一分支。

1. 用世界空间定义功能/生境分区、密度场与排除区；植被可由高度、坡向、湿度约束，人工陈设按通道、工作区与承载关系约束。保留目标所需的开口和安静区。
2. 以固定seed生成簇中心和范围，先取得簇内合法候选域，再生成成员；例如沿真实缝隙/边界先筛选局部线段，再按长度采样并加有界横向偏移。全局取样后大量拒绝，在固定候选次数或拒绝预算耗尽时会使实际密度低于计划；必要时换采样表示。保留实际落点计划，再由计划分配实例容量；相关大小/方向/形态族形成组内节奏，规则阵列保留其秩序。
3. 对每个候选查排除mask、间距及实际承载面：纯高度场可直接求高度/坡向；存在桥、叠层、洞顶时选择所属表面/锚点，必要时沿指定方向射线求交。按对象规则合成姿态：贴附面可对齐法线，直立体保持重力轴，功能面另朝向使用区；接触部位单独适配承载面。
4. 先铺少量代表簇到完整代理，在目标/侧背视口看组间遮挡、近中远轮廓与透空，再扩容量。疏空先定位分布区、簇范围、成员轮廓或遮挡；大量实例不自动形成目标覆盖。位置、形态与材质变化应能分别调整。

植被顶端可随高度增长弯曲，方向/长度/色彩变化保持空间相关；形变同步法线/背面明暗，投影使用一致depth/distance或shadow节点。不可见高频细节随像素尺度衰减。群体的构图选择见[空间方法](scene-layout.md)。

植被可采用实例几何/四元数弯曲，也可合并三角属性并以节点位移回卷近景区域；按数据表示选择，不能统称为InstancedMesh。旧示例的手动颜色pow/输出编码与旧API需要按当前颜色链迁移。

相机周围回卷可以减少无用远景几何，但要按稳定世界格子/id生成随机变化，避免游动时植被花纹漂移。展示中常见的随机数和交互相机用于影片时需改为固定seed与镜头时间。不要全局关闭裁剪掩盖包围体错误；局部草场可按其表示有意关闭，普通实例则分块并更新保守bounds。

程序地形采用四叉树/分块/worker时，难点包括共享高度场、不同LOD边界和异步结果一致性。邻接块层级改变时需要统一边界顶点/法线并按影响重建邻居。仅用不同细分数的平面会裂缝。任务结果携带chunk身份、版本与镜头状态，丢弃过期worker结果；仅有worker不代表已实现这类版本防护。

固定核心镜头未必需要无限地形：先按可见范围与景别控制几何、LOD与细节预算。CSG用于造型结构时检查封闭二流形、世界矩阵、属性/材质groups与法线；three-bvh-csg明示数值边界，不把快速布尔当可靠CAD。静态布尔优先在准备阶段计算并缓存，是否需要每帧重算先用镜头需求证明。

环境接触反馈从同一表面函数派生：水面/地表与主体的交界、泡沫/水花/尘埃的出生点使用共享高度/变形场与最终世界锚点。大体积、贴面薄层、碎屑和雾分别选择表示，再共享色板、时间与尺度。

把共享场接到完整环境：同一时间/天气状态同步背景、雾、IBL、主辅光与局部发光；地形高度/坡向/湿度同时约束道具落点、材质过渡与反馈。发射器放在所属对象的局部锚点，移动后由世界矩阵取位置。粒子设计先明确命中表面后的驻留、融化/消散和回收；复杂焦点表面用网格相交，低关注对象可用包围体近似。脚印、尾迹等依实际接受的移动/接触事件生成，碰撞后未移动不能继续刷痕迹。

已有动作可先离线测量关键锚点的伸展、速度、支撑和接触区间，再由语义选出事件；测量峰值不自动等于打击/落脚。姿势、事件表与FX共用经过速度映射的时钟，按最终变形位置发射；跳帧时处理跨越事件并防止重复，随机seek则重建相应粒子历史。

## 大规模实例、拾取和BVH

| 变化/任务 | 必须同步的内容 | 边界 |
|---|---|---|
| setMatrixAt修改实例 | GPU上传标记`instanceMatrix.needsUpdate`；按需重算aggregate boundingSphere/Box和空间索引 | 上传标记不更新CPU包围体；移位后旧包围体可能造成漏拾取 |
| 万级实例拾取 | 对象/实例层空间分块、候选筛选或适用版本ObjectBVH，稳定instanceId到业务对象映射 | 一个draw call不等于一次相交；传统InstancedMesh.raycast在总包围体通过后遍历实例，MeshBVH仅加速共享几何内部三角测试不足以移除此循环 |
| 静态网格顶点变化 | position更新、bounds更新、MeshBVH.refit | refit适合同拓扑，严重变形后树质量可能下降；拓扑改变需重建 |
| 骨骼/形变网格 | 最终姿势后更新骨架/矩阵；支持版本的SkinnedMeshBVH与refit，或生成静态快照重建 | 支持类型依安装版本核对，不能泛称BVH均不支持蒙皮。其`raycastObject3D`接口不等于MeshBVH的`raycastFirst`；按实际类核对 |
| shader风/位移 | 保守渲染bounds；相同形变的阴影；匹配的拾取proxy或CPU变形 | 原始CPU几何及其BVH不会自动跟随任意shader位移；proxy只能声明为近似 |

直接BVH几何查询一般使用局部坐标；Object3D/raycaster适配层可能处理世界矩阵。核对具体接口的坐标、near/far、返回distance及非均匀缩放，不能混用。少量已知射线与原生raycast对照，覆盖变形前后、尺度变化、边缘与空命中；firstHitOnly只在业务确实需要最近交点时使用。

## 性能、质量档与成片可靠性

瓶颈先分类：CPU遍历/动画/构建、draw calls、顶点、透明overdraw、阴影/反射/环境捕获、后期像素、纹理显存、编译与解码。`renderer.info`跨多遍统计要控制autoReset并汇总全部render，单次主场景数字不能代表整帧。像素工作量约随宽×高×DPR²增长；大量草叶或全屏粒子可能是填充瓶颈，减draw calls并不够。

实时质量档可按窗口样本调整：按窗口样本和上下界调整DPR、影图、实例密度、后期规模，并设滞回/退档锁定，避免每帧来回切换。影片导出锁定档位、seed、分辨率、采样预算与LOD策略，不能随机器瞬时fps改变内容。预热代表性材质/阴影/透明组合，再分别报告冷启动、稳定帧和峰值。

每次优化固定机位做A/B：差异能否被看见、边缘/遮挡/接触是否退化、CPU/GPU耗时与资源是否确实降低。持续切镜、seek、装卸资产后观察资源是否稳定；帧数高不能抵消主体不完整、阴影错位或随机导出失败。

## 标签、声音与资源所有权

标签/标线可用Canvas或程序字形，按最终曲面/UV、方向与距离贴合。声音可用Web Audio振荡/噪声/滤波与包络，叙事需要时使用获准的旁白；实际试听，共享事件决定起点，用户手势初始化、静音/暂停与循环可用。声音和粒子使用有界声部/池，不随运行无限创建。

静件按材质/阴影/图层合并，同几何实例复用，动态件保留句柄。资源由创建者拥有，借用的材质/纹理不由每个实例释放；异步生成带版本/稳定ID，进入真实场景并预热后再报告可用。离线包包含依赖/许可；历史缓存须绑定源参数/版本，不能替代可重新生成的规则。
