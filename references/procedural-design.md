# 先设计能生成的作品，再编写生成器

用于短需求补全、主要对象开工和代表区域设计。这里产出能交给代码的设计；全场组织接[程序世界](procedural-worlds.md)，几何与材质实现接[制作系统](production-systems.md)。

导航：[需求规格](#1-把短需求补成可生成规格) · [对象族](#2-先决定形态族再生成实例) · [特征接线](#3-把视觉特征拆成原子决策) · [数据示例](#4-轻量设计数据示例) · [完成条件](#5-交给代码的实际输出)

本分支用 Three.js、自写 JavaScript 几何与 shader 建立最终三维世界。参考图片用于查证和设计；不导入现成、扫描、AI 或 DCC 三维模型，也不把模型数组、模型图集或扫描立面藏入源码。选择能从结构参数重新生成的表示。题材、画风、模型供应商和观看方式互不绑定。

## 1 把短需求补成可生成规格

先继承用户已经明确的主题、风格和范围。能从上下文查到的事实自行核对；缺少但不影响目标的部分直接做设计设定。只有会改变作品目标的冲突才需要询问。真实尺寸与虚构设定分别标明，避免把参考透视当测量。

| 设计动作 | 写成什么 | 此步结束时应有的输入 |
|---|---|---|
| 明确观看任务 | 影片/环绕/漫游、最近观察距离、全貌范围、允许交互、交付平台 | 相机运动包络与目标视口；观众应读出的空间或动作 |
| 画完整空间 | 场地边界、区域、承托/地形、高差、路径/视线、地平线 | 简图或坐标表，包含侧背与远景；主体不单独悬在空场 |
| 给尺度基准 | 米制单位、主对象尺寸、构件/生物尺度、相邻对象比例 | 总尺寸与关键截面，不确定尺寸有设定范围 |
| 定造型语言 | 主轴、轮廓族、实与空、层级、对称性、转折与收分 | 每个主要族的形体草图/截面；能说清它区别于其他族的结构 |
| 分配画面责任 | 前/中/远层分别表达什么，哪些材料/连接需要近看 | 全貌、代表关系近景、侧背检查视图及对应质量目标 |
| 定动态与成本 | 主动作、反馈、静动边界；目标设备与几何/材质预算 | 可实现的动作关系和起始预算，不凭实例数量承诺帧率 |

例如“一个静谧的山谷植物观察站”需要同时设计谷坡、步道、观察空间、植被群落和远山。静谧可落实为大片安静面、有限光区对比与低频动作；不自动加入雨、锈、枪械或霓虹。先确定这些关系，再挑算法和库。

把“精细”“高级”“真实”转换成目标画面的具体信号：哪些轮廓拐点、开口深度、表面层次、受光带和运动承接必须读得出。参照图的复杂度是质量依据；首版能力不足不能反向改写目标。

## 2 先决定形态族，再生成实例

盘点**所有主要可见组成**：焦点、承托、邻接对象、区域边界、群体与远景。按结构相同而参数可变的范围归族；不要只为主角做正式生成器，把环境保留为无限期代理。

| 族的设计项 | 建筑/装配示例 | 自然/有机示例 |
|---|---|---|
| 身份不变量 | 承重框架、开间关系、屋面排布 | 主干/主枝层级、组织方向、重心 |
| 结构原型差异 | 双坡长体、分层退台体、围合带孔体 | 直立塔冠、横展分枝、贴地簇生 |
| 可变结构参数 | 跨数、进深、层高、洞形、悬挑 | 分枝级数、收分、曲率、冠层空隙 |
| 从属构件 | 墙厚、洞壁、框、屋缘、接头 | 分叉过渡、基部、叶序、附生部位 |
| 使用/生境条件 | 面向入口、避开通路、服务净空 | 坡度、水分、光向、与邻群距离 |

先生成各原型的完整代表件，在相同灰材质、尺度与主/侧视图比较。新的原型要有目标像素下可读的剪影、体量分组、开口或连接差异；随机缩放、旋转、换色不构成新原型。设计要求统一时保持统一，由组间距、节奏和材料关系组织画面，不强制凑变体数。

每个族先选一件与支撑、邻件、灯光共同完成。决定身份的一段连续体或连接要完整：包括过渡前后、真实厚度、孔洞内壁和接触。结构已成立后，才在规定尺寸范围、区域权重和密度内生成实例。多种不同原型分别缓存/批处理，缓存键包含实际影响结构的参数。

## 3 把视觉特征拆成原子决策

每个关键特征沿下表落地，形成“**特征 → 表示 → 生成器输入 → 实际消费者 → 目标视图**”。一个字段只有进入当前几何、材质、变换或更新逻辑才算实现；`userData`、规格名和台账本身不会产生像素。

| 决策 | 开工前明确的输入与责任 | 用哪个视图判断 |
|---|---|---|
| 形状/剪影 | 轮廓转折、关键截面宽深、主轴站位、端部收分；选回转/扫掠/放样/自建拓扑 | 全貌缩略图与侧背；灰模能读出身份 |
| 分层/孔洞 | 壳厚、内外边界、层距、洞深/口沿；真实几何负责透空和遮挡 | 斜侧与穿越视角；能看到厚度和洞壁 |
| 连接/过渡 | 相邻件接口、融合/套接范围、支撑足迹、运动枢轴 | 连同宿主取景；尺寸变化后接触仍成立 |
| UV/材料 | 米制图案尺度、方向、材料区与形成依据；UV/顶点场进入实际材质或 shader | 最近目标距离；纹理不拉伸、不漂移，材质区能分开 |
| 光/表面响应 | 需要的明暗和反射带、真实接收面、主光/环境；按风格选 PBR 或自写着色 | 最终曝光及互补角度；不能只靠法线噪声读结构 |
| 动作/交互 | 事件或绝对时间、静动层级、变形边界、接触反馈 | 关键姿势与连续运动；子件与附件随真实枢轴/表面变化 |

按项目实际代码命名生成器与消费点。例如“深窗洞”可由带孔墙体、洞壁、窗框和后退窗面共同产生；宽高/墙厚输入真实顶点生成，安装面从同一局部框架推导，再看斜向近景。把深色矩形贴在墙面只能承担色区。

已有低层方法不重复另写：截面与洞壁读[几何方法](profile-geometry.md)，结构过渡读[构图与形体](composition-and-form.md)，UV/表面场读[表面细节](surface-detail.md)。先选合适表示再调整参数；细分不能补出缺失的层级、孔洞或连续体。

## 4 轻量设计数据示例

以下是**原创项目数据草案**，用于展示怎样把设计交给实现；不是 Three.js API，也不声称 Skill 已有同名生成器。只保留当前项目真正需要的字段，可用普通 JS 对象、表格或图替代。

```js
const brief = {
  units: 'm', seed: 'valley-study-01',
  extent: {x: [-28, 28], y: [-2, 18], z: [-30, 32]},
  camera: {mode: 'orbit', target: [0, 2, 0], radius: [12, 46],
    elevationDeg: [8, 65], fovDeg: 42},
  views: ['whole-valley', 'station-entry-oblique', 'tree-base-side'],
  families: {
    station: {
      archetypes: ['gabled-long', 'stepped-open'],
      bayWidth: 2.8, wallThickness: 0.18,
      feature: '深窗洞与薄屋缘形成不同的受光层',
      representation: '开孔墙壳、独立屋缘、后退窗面',
      inputs: ['bayWidth', 'wallThickness', 'openingInset'],
      implementation: '待实现：从这些输入建立顶点、安装面与材质区',
      checkView: 'station-entry-oblique'
    },
    trees: {
      archetypes: ['upright-tiered', 'wide-branched'],
      heightRange: [3.5, 7], branchLevels: [2, 4],
      constraints: ['根部接坡面', '冠层留出步道', '分枝收分'],
      checkView: 'tree-base-side'
    }
  }
};
```

开工时为 `implementation` 写真实函数和调用点，删除待实现描述；输出 Mesh 的函数、消费 Mesh 的装配代码和实际相机分别能定位。对象族尺寸是本例的设计值，不是通用规范。全场区域、宿主、路线和种子使用下一页的世界规则。

## 5 交给代码的实际输出

结束设计阶段时，下一步应能直接制作：一份包含完整范围/尺度/相机的简明 brief；主要区域与关系简图；每个主要族的结构原型和尺寸控制；关键特征到生成器/消费者/视图的短映射。尚未写的函数标作待实现，不填写渲染通过。

代表关系完成后，保留同一工厂生成的展柜和场景视图；改变一个主尺寸，确认开口、连接、材料区与附属件随动。全貌能读出层次、近景能读出目标结构后，再扩大数量。最终质量仍由[统一验收](validation.md)判断，本页不增加独立表单或门禁。

## 方法来源与边界

[Saltline 固定源码](https://github.com/realcodebear/saltline-fable-5.2/blob/09c51774cd77aad750bd2d6c42af2b1020cb668d/index.html)可核对资产工厂、动静分离、程序表面与世界字段消费者；[Claude of Duty 上游 kit](https://github.com/mshumer/Claude-of-Duty/blob/main/src/world/kit.js)与[建筑装配](https://github.com/mshumer/Claude-of-Duty/blob/main/src/world/buildings.js)可核对厚度、真实洞口与开间组装。Duty 链接为 2026-11-12 检查的上游，部署分叉一致性未确认。

本文的设计顺序、示例数据与完成条件是从机制归纳的制作建议，不是作者提示词或原始创作记录。学习结构、空间和消费者关系，自行编写题材对应生成器；不复制第三方应用代码、模型、专用布局或美术参数，也不从这些案例推断某个模型的一次生成能力。
