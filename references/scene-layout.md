# 用共享空间数据组织完整场景

用于全场草案、相机/构图设计、区域扩展和实际宿主接触。需求与对象特征见[视觉设计](visual-design.md)；正式形体见[构造配方](procedural-construction.md)，低层算法见[几何配方](geometry-recipes.md)。

## 1. 先建立世界骨架

按“全场→区域→组团→对象族→构件”设计；小场景和单个有机体可减少层级。把决定身份的主关系手工确定，再给局部生成有边界的变化。

| 空间层 | 设计输入 | 在画面中的责任 |
|---|---|---|
| 连续空间 | 地形/承托、边界、主要高程、开口、洞/谷/房间及地平线 | 观众知道场所在何处、空间向哪里延伸 |
| 区域与联系 | 各区用途/生境、形态、通路/水系/组织连接 | 区域有差异，并属于同一个完整世界 |
| 组团与空隙 | 焦点、地标、组中心/范围、视线走廊、安静区 | 前层提供尺度，中层表达关系，远层延续环境 |
| 对象与边界 | 结构原型、支撑物、从属物、边缘过渡和密度 | 邻接、使用与生长逻辑可读 |

建筑区从入口、工作/通行和收口生成组成；自然区从坡度、水分、光向和群落边缘组织。每区选择一个包含主物、支撑、边界、材料和受光的完整代表组，使用同一工厂扩展。先安排组的位置与轮廓，随机只处理组内有限差异。

宏观场景规划“全貌→区域→特征”的视图阶梯：全貌看空间结构，区域看独特内容与疏密，近景看截面/连接/材料。按目标距离和视口分配细节，远处保留身份与关系，近处提供需要的真实构造。

## 2. 共享数据与稳定变化

坐标、区域、路径、宿主与对象落位使用一份权威布局。生成器、图纸和运行消费者读取同源输入；复杂场地可以拆模块，但每个值只有一个负责来源。

| 数据 | 实施方法 |
|---|---|
| 稳定身份 | 区域、组、对象、接口使用不随数组顺序变化的ID；定点地标保留人工数据 |
| 独立随机流 | 由项目seed、稳定ID与用途派生种子，如`east-slope/tree-07/shape`和`.../surface`；新增纹理不会重排全场 |
| 共享驱动 | 几何、摆放、材料或反馈确实受同一规律影响时，保存共同字段/曲线及坐标、单位和消费者 |
| 实际输出 | 布局生成承托/路径网格与落点；端口变换进入附件位置，材料场进入材质/着色器 |

对相交的山脊/沟槽、路径/平台或分枝/接触区，先选“穿越、汇合、分隔、跨越或让位”的关系，再组合场。由优先级决定保留哪条轮廓、哪里需要抑制/改道/支撑；简单叠加或取最大值不保证交汇正确。看中心和两侧断面，以及隐藏引导线后的真实灰模。

扰动一个有意义的共享参数，读回已实现消费者并看对应区域变化。草案验证当前空间关系；材质、动态等消费者实际加入时再验证相应链路。

## 3. 运行完整草案，再细化代表关系

先跑通同一Three.js/addons版本、renderer、相机、单位、seed、时钟、材质目录和基础环境。按以下依赖建立全场：

1. 从共享数据生成主要承托、地形、水位、边界/开口和地平线；按表面类型选表示。
2. 加入主要对象的简化轮廓/体量、路线、平台、支撑与必要净空。让重要区域、连接与负形在草案中已可见。
3. 在中性材质下用实际视口比较机位、尺度、遮挡和前中远层，转动检查侧背及合法端点。
4. 修正空间问题后，选决定品质的代表关系制作正式工厂；扩场时保留布局，按最终宿主重算接触和附件。

| 空间问题 | 合适表示与工具 |
|---|---|
| 规则地面、布局、路径或参数对象 | 共享JS数据、`BufferGeometry`、轮廓/截面和实际表面采样 |
| 地块、测量位置或高程 | CAD/GIS提供核对后的边界与尺寸，记录坐标转换，由代码重建 |
| 悬挑、洞穴、倒扣或多层宿主 | 显式曲面/控制网格、代码实体或场→网格提取；单值高度场只用于其可表达区域 |
| 大量重复区域 | 结构图/区域规则、分块实例/静态合并，按确有成本的计算使用worker |

草案可简化零件和材料，仍保留决定身份的轮廓、深度与空间连接。目标是完整空间可判断；正式资产按[构造配方](procedural-construction.md)增加真实中层、开口和表面。

## 4. 先定透视，再调占幅

保存可改相机配置：`target / azimuth / elevation / distance / fov`，由它计算位置；对象尺寸与姿态另存。

先选观看高度和方向，使需要的顶/侧面与负形出现；再选透视关系，最后校准占幅、重心和裁切。移动机位改变近远比例；固定机位改变FOV主要改变取景范围。较远机位搭配窄FOV可保持主体占幅，同时压缩深度。

普通透视相机中，视轴居中、与成像面平行的高度`H`要占画面高度比例`q`时，可用`d = H / (2 * q * tan(effectiveFov / 2))`估距离。`camera.getEffectiveFOV()`返回度，计算前转弧度；横向还受aspect约束。深度/倾斜、viewOffset/filmOffset等需要实际投影。正交相机通过视域/zoom改变占幅，移动远近本身不产生透视缩放。

### 把实际世界锚点投影到视口

下面返回屏幕位置和视锥事实。调用方在FOV、aspect或视域改变后更新投影矩阵；`worldPoint`是当前姿态的世界点，`width/height`是目标视口尺寸。

```js
function projectAnchor(camera, worldPoint, width, height) {
  camera.updateWorldMatrix(true, false);
  const view = worldPoint.clone().applyMatrix4(camera.matrixWorldInverse);
  const depth = -view.z;
  if (depth < camera.near || depth > camera.far) return null;
  const ndc = worldPoint.clone().project(camera);
  return {
    u: (ndc.x + 1) / 2, v: (1 - ndc.y) / 2,
    x: (ndc.x + 1) * width / 2, y: (1 - ndc.y) * height / 2,
    depth,
    withinViewport: Math.abs(ndc.x) <= 1 && Math.abs(ndc.y) <= 1
  };
}
```

局部锚点先更新父级矩阵再`localToWorld()`；实例要包含实际instanceMatrix，骨骼/shader变形使用最终位置或等价求值。世界AABB角点仅给保守占幅；跨near面的盒不能直接用八角点min/max当裁切结果。投影不检查遮挡。

### 让关键关系在镜头里可读

连接要能追踪起点、连接段和终点；承托要能辨认接触与暴露边缘；穿越/入口要能区分开口与前后次序。复用实际路径/接触点投影，必要时从相机发射射线到关键样点，定位无关几何的遮挡。射线使用最新世界矩阵与实际网格，排除关系自身和合法宿主。

按目标像素设置有意义的边距与最小间隙，再看无标签缩略图和全幅：共线、投影过小或过度重叠的关系即使端点入镜也可能读不出。一机位难以同时表达主体与连接时，调整布局或让互补视角承担关系。

候选机位冻结对象、时间、画幅和质量，分别判断焦点占幅、前中远错开、负形用途、关键关系、环境框景与其他方向。选择解决当前问题且不破坏重要目标的方案；单个可见度分数不足以决定整体构图。已有锁定机位时，改相应布局和形体。

## 5. 从实际宿主求接触与净空

优先从最终网格采位置/法线；解析高度场仅在三角划分和插值与发射网格一致时可等价求值。多层、悬挑、斜面或复杂宿主指定实际表面。局部锚点经当前world matrix转换，非世界父级再乘父级逆矩阵；可能含剪切时保留矩阵，避免强拆TRS。

| 关系 | 构造与独立复查 |
|---|---|
| 路面/岸线贴合 | 路径先细分到最终采样密度，再求中心及两侧高程/法线；做厚度、路肩或支架，查看全线纵坡/横坡与交界 |
| 物件落地/附着 | 从真实底面取完整足迹与边/内部样点；基部负责有限贴合，主体按重力、生长或安装方向建架；发出后复测真实接触面 |
| 双端承托 | 先发下宿主和上方真实底面，再按上下足迹求跨度；完整帽/法兰/脚垫均参与。漏命中或负跨度需改位置/宿主，不能以包围盒替代 |
| 基础与可见构件 | 分开入土/嵌入跨度和露出跨度；斜撑、套接与服务接口放在真实露出区间，并保留厚度和余量 |
| 大占地结构 | 沿边界与关键内部位置采宿主，按顺坡、分级或水平基座策略生成底面/挡土/支架；检查转角、入口和整圈承接 |

表面查询、足迹资格与双端承托的可调用API见[制作工具](production-toolkit.md)。查询命中只是构造输入；最终接触误差从已发出网格另取顶点、边中点或内部样点测量，密度覆盖宿主局部变化，记录允许间隙/嵌入与可见结果。

### 由使用者定义通路

区分真实路面/通道、物体中心轨迹和说明引导线。按使用者的身体、附件、姿态和设计余量确定宽高；端点接真实平台/门洞/接口。多路线同到一处时，连全宽和进入方向一起设计落地空间。

刚体固定姿态沿直段平移可先把真实网格AABB移到两端并求并集，再加余量，得到保守连续扫掠盒。AABB仅作粗筛，碰到候选障碍后用实际三角形或更合适碰撞体细查。斜向平移有额外角区，转动/变形需扫掠胶囊、凸体或覆盖段间运动的保守界；稀疏姿势盒不足以保证中间净空。末端允许的对接重叠仅限指定宿主/接口。

正式曲面或布局改变时，区分被锁定的设计接口与由宿主派生的支撑/落点。重算后者并回看受影响的路径、接触、遮挡和图纸；保留其他有效设计。

## 6. 为完整观看环设计内容

可交互场景从开始就规划完整水平360°及合理俯仰、距离、缩放和复位。先定环绕中心与合法包络，在八个水平方位及端点安排主体关系、前中远层和有意遮挡，再制作资产细节。

检查每侧及斜角是否有空间焦点和环境延续，近处不穿体、远处不露场地边界；区分正常实体遮挡、功能面朝错和缺少环境。相机位置与宿主相交、相机到关键内容的视线被阻断是两个问题，分别查看实际网格。控制器若推开/抬升相机，还要确认实际构图保持目标内容。

庭院、线性街巷、桥梁等拓扑都可使用；各自把侧背、端部和地平线设计完整。影片只覆盖导演机位/运镜范围；影片加自由查看分别管理相机写入权。真实输入、缩放与复位的做法见[相机交互](camera-interaction.md)。

## 7. 近中远共享世界身份

| 景别 | 保留的内容 | 合适表示 |
|---|---|---|
| 近景 | 剪影转折、厚度、真实孔洞、连接、材料区与动件 | 正式截面/拓扑、内壁、基部与米制表面 |
| 中景 | 原型身份、体量分组、主要空隙、遮挡与材光节奏 | 简化分段、有限开口、成组构件与分块实例 |
| 远景 | 天际线、轮廓族、关键负形、区域色块与层次 | 低段数体量、程序簇或承担中远表面的程序立面 |

各档共享稳定ID、主尺寸、地面基准、关键端口和材料身份。简化省略不可读小层，保留世界拓扑及地标位置；例如中远立面靠近后由真实洞口接替。

在切换边界同机位比较轮廓、基部、孔洞和阴影，沿实际路线来回看跳变。用滞回避免抖动；交叉淡化同时处理透明、阴影与双份渲染成本。质量档变化后仍检查场景身份和承诺观看范围，最后按[验收](validation.md)回看完整作品。
