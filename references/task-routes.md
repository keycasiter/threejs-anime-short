# 按最终交付的制作路线

本页只决定**先从哪条制作主线进入**。后续仍使用 `production-workflow.md` 的共同六阶段，并按需组合空间、构造、表面、材光、动态和验收责任；不要为同一作品并行启动多套完整流程。选路线时看用户最终要求什么，以及哪类缺失会使交付物不成立。

多个信号同时出现时，先按最强交付约束分类：

1. 用户要求最终编码视频/固定时长镜头时选导演短片；交互预览是辅助证据。
2. 用户要解释运动状态或部件因果时选机制讲解；播放、暂停、步进和复位是该路线的责任。状态之外的相机操作不改变主路线。
3. 用户要探索空间、在区域间导航、选择对象或查看所有方向（包括高低/底面）本身构成交付验收时选交互导览。单物体的常规环绕/缩放/复位是展示相机责任，不单独触发交互路线；环境的水平全景环绕也不自动改选交互路线。
4. 单一物件的形体/装配/材料是视觉焦点时选物体展示；需要多个区域、路径、地貌共同表达地点时选环境场景。主体的轻量操作（如调焦或俯仰）并不自动改选机制路线。
5. 自然形态描述对象类别而非另一种交付格式；按整体尺度加入物体展示或环境场景的自然形体、水体和分布责任。

## 路线间的数据接力与资源归属

这些是设计交接字段，不是新增强制API。沿用[表示选择与资源scope契约](implementation-foundations.md)和已有模块的返回类型；没有对应消费者的字段不要提前造出来。

| 路线 | 上游输入 → 下游交付 | 必须实际消费的位置 | 资源归属边界 |
|---|---|---|---|
| 环境场景 | 单位/轴向、稳定区域和对象ID、空间图/足迹、地形或承载查询 → 共享布局与表面源 | 路径/道路构造、区域/建筑摆放、贴地细节、空间材质与镜头标记读取同一源 | 组装器/场景scope拥有实际几何与生成资源；多个资产借用共享布局/表面句柄，不重复dispose |
| 物体展示 | 资产局部单位/轴向、截面或构造参数、端口/锚点、材质需求 → `root`、本地端口、实际表面/动态句柄、`dispose` | 展台定位、支撑/附件、局部材质坐标、检查视图和必要动作从对应端口/句柄读取 | 资产工厂拥有自己生成的几何/动态资源；调用者按契约借用材质，外层owner按依赖顺序清理 |
| 机制讲解 | 单位、关节/约束、时间或交互状态 → 一份纯状态求值结果（姿态、相位/数值） | 各运动件变换、阶段/UI读数、事件/效果都读取同一结果；不能各自维护近似相位 | 纯状态函数不拥有GPU对象；资产owner拥有几何/材质，控制器只拥有自己的监听/时钟/临时资源 |
| 导演短片 | 固定seed、时长/帧率、绝对时间 → `renderAt(seconds)`的完整可见状态与`__FILM`导出契约 | 相机、场景、动态、DOM覆盖读取同一时间；`render_film.mjs`按时取样和写成片 | 场景scope拥有画面所需Three资源；导出器拥有隔离浏览器/目标视频与报告，不替场景声明资源所有权 |
| 交互导览 | 可执行的用户动作、相机目标/极限/复位、可选稳定对象ID → 相机状态/选择状态/语义反馈 | OrbitControls或显式导航器消费相机合同；拾取/标签/UI读取稳定ID与实际命中/状态 | 页面资源scope拥有监听器、controls、HUD和场景根；选择/高亮逻辑借用源mesh/material。若创建私有覆盖层，由创建者拥有并释放 |

**替换时检查接力完整性：** 改一个上游输入，确认它改变了表中指定真实消费者；替换工厂后查询/锚点/动件同步更新；旧资源释放而借用的共享资源仍可用。对资源ownership有歧义时回到工厂创建点确认，不能从scene traversal猜所有者。

## 非影片场景的观察覆盖接力

**适用范围：** 所有最终允许用户环绕观察的环境、物体和机制场景。它是横跨主路线的验收责任：普通环绕不因此切换到交互导览；影片的导演相机使用短片路线的镜头路径审计。

1. 从资产工厂为每个身份/功能关键特征登记稳定ID及真实表面样点；样点表达孔口、接口、支撑、正背面等实际目标，不以包围盒中心代替表面覆盖。动态机构先求目标状态，并将当前特征点变换到世界坐标。
2. 从真实控制器可达的相机范围取候选观察位，包括默认机位、8个水平代表方向、俯视/低角度、近远端和题材风险组合。每个候选带目标、方位、俯仰、距离及其要证明的特征；工具不会读取OrbitControls限位或自动生成相机范围。
3. 用 [`selectObservationView`](../assets/scene/observation-view.mjs) 帮缺失特征寻找补充视图；人工确认构图职责后，使用 [`auditObservationSet`](../assets/scene/observation-view.mjs) 审计最终选定视图的联合覆盖与每项独立阈值。已有采样与阈值接口见 [`core-systems.md`](core-systems.md)；不要以一个总覆盖率抵消入口、背面或连接的单项缺失。
4. 独立执行 [`camera-interaction.md`](camera-interaction.md) 的实际拖拽、读回相机状态、俯仰/缩放端点和复位检查，确认候选位可达；机制任务对关键状态重复其负责的特征检查。
5. 在目标浏览器检查实际渲染，确认反射、透明、阴影、后期和材质仍可读。几何覆盖只证明登记样点与视锥/遮挡条件，不证明整张画面完整或好看。

交接记录采用简明表：`特征ID → 负责视图 → 目标状态 → 实际可达机位 → 覆盖结果 → 画面观察`。每项缺失返回其源头：样点/阈值错回设计规格，视图不可达回相机控制，几何遮挡/空缺回空间与构造，实际着色不清回材光；不要通过缩小角度、降低阈值或隐藏背面来消除失败。

**工具适用边界：** `auditObservationSet`单次最多64个视图、32组特征；大场景按区域/资产族分批审计，连接关系另作为独立特征，不能合并后稀释缺失。它和`selectObservationView`当前构建的是`PerspectiveCamera`；若交付相机为正交投影，改用`inspectFeatureVisibility`搭配真实`OrthographicCamera`逐视图检查，再按语义汇总，不能拿透视候选代替。它对显式三角形Mesh做CPU射线，不重现alpha裁切、玻璃透射、shader位移、裁切面、透明排序或后期；透明/程序表面按实际可见语义传真实网格或保守遮挡代理。Three.js可射线检查`InstancedMesh`，但更新实例变换/几何后由调用者刷新其bounds；样点也须由调用者在当前状态下重新计算。工具成本随候选视图数、样点数和遮挡几何射线成本增长，应在构建或状态检查时运行，不放进每帧循环。逐项能力边界见[`view-readability.mjs`](../assets/scene/view-readability.mjs)源码注释。

**可运行接线样例：** 新建这类场景时先读[`visual-relations/main.mjs`](../assets/examples/visual-relations/main.mjs)，看它如何从发出的三角面取稳定样点、用真实世界矩阵转换、把最终可见结构交给`inspectFeatureVisibility`，并记录实际遮挡对象；多视图需要互补覆盖时再读[`core-world.mjs`](../assets/examples/core-world.mjs)，看如何从构造器的实际曲面查询产生带语义ID的样点，再排序候选位并验证联合覆盖。只迁移样点来源、状态更新顺序、遮挡集合和报告字段；示例中的资产、相机坐标、阈值与视图数量必须按新作品重定。

## 环境场景

**适用：** 城市、建筑群、地貌、园林、聚落或其它多区域完整场景。核心交付是可读的整体空间，主对象需要依赖场地和配景建立意义。

**流程：** `visual-design.md` 提炼必需区域/对象/视向 → `scene-layout.md` 建场地、连通图、承托面和前中远景 → 按连接/地貌类型选 `world-methods.md` 或 `nature-methods.md` → 先做一块有地面、主物、路径/连接和配景的代表区域 → `code-guidance.md` 接到真实几何/摆放消费者 → 再扩完整区域 → `rendering-choices.md` 与 `camera-interaction.md` 完成材光和查看范围。

**现有起点：** [`world-showcase`](../assets/examples/world-showcase/index.html)从r187代码生成连通聚落、地形、街巷、单体瓦面、林缘、温泉庭院和动态水雾；其[场景工厂](../assets/examples/environment-world.mjs)复用`buildLandscapeContext`，并把实际地形查询交给植物、岩体和水道。它是完整的环境纵向代码样例，展示可复用的空间/资产/材光/相机接力；构图、建筑风格与数值是该样例自身的选择，复制时按新任务重做设计，不将它视为跨题材的视觉金标准。`activity-lab`、`core-lab`和`guided-world`仍分别作为区域关系、共享几何和构件更新工作台。自然洞瀑按“环境主线 + 连续自然形体/水体责任”处理，不单列一套竞争流程。

**交接和首检：** brief产出必须包括区域关系、承托/通路、近中远对象责任和承诺视向；白模数据至少被实际路径、摆放或地面查询消费。可环绕场景同时执行[观察覆盖接力](#非影片场景的观察覆盖接力)。首次完整页面执行 `node <skill-root>/scripts/validate_offline_html.mjs <project>/index.html --require-offline`，再在 r187 浏览器中实看全貌及路线指定视向。离线检查只证明资源闭合，不代表空间完整。

**失败回退：** 区域/路径断开回到连接图和空间拓扑；道路、溪流或建筑与坡面脱开回到共享高程/道路字段和锚点；整体成立但一块仍像代理，回到该区域的代表资产与扩场，不靠全场随机细节掩盖。

**已知缺口：** 当前只有一个聚落环境纵向样例；尚未覆盖多种气候、自然主导场景和不同空间尺度。样例的技术闭环已通过代码/离线包检查，视觉品质仍需按目标浏览器中的全貌、区域、反向和近景真实观察确认。

## 物体展示

**适用：** 以一个主要物体、装置、角色或资产族为观看焦点，要求展示结构、装配、材料或操作动作。

**流程：** `visual-design.md` 定身份轮廓、尺度、目标视角和表面特征 → `procedural-construction.md` 选择表示 → `geometry-recipes.md` 生成截面、壳体、开口与连接 → 先建立主体/支撑/底座或展示环境的完整代表关系 → `surface-detail.md` 与 `rendering-choices.md` 接入真实材质信号 → 加入必要状态/俯仰/焦距控制 → `camera-interaction.md` 检查互补视图和背面。

**现有起点：** [`product-showcase`](../assets/examples/product-showcase/index.html)和[样例说明](../assets/examples/product-showcase/README.md)提供完整的影棚产品展示纵向切片；其[相机工厂](../assets/examples/product-camera.mjs)展示壳体挤出、镜头分层、实例化微细节、稳定锚点、参数消费者与资源归属。它是单一产品题材的完整实现样本，材质/机位/光源数值需为新任务重新设计。几何选择仍可参考[`foundation-lab`](../assets/examples/foundation-lab/index.html)，工厂/锚点/替换接力见[`guided-assembly.mjs`](../assets/examples/guided-assembly.mjs)，木料与实体接头见[`stock-lab`](../assets/examples/stock-lab/index.html)。

**交接和首检：** 记录主体比例、局部坐标、关键连接轴/锚点、材质输入与真正消费者；改变一项比例或姿态，确认支撑、连接、开口和材质分区随之更新。静态资源检查通过后，运行完整入口，检查默认视角、正背侧、顶部、目标近景，并拖动焦点/姿态控制确认真实几何消费者；可环绕场景同时执行[观察覆盖接力](#非影片场景的观察覆盖接力)。

**失败回退：** 主轮廓或截面不对回到表示/截面参数；比例变化后连接和附件不跟随回到工厂锚点与共享输入；结构正确但材料身份消失回到UV/PBR通道、实际环境和目标受光，不叠加泛化后期补救。

**已知缺口：** 当前完整产品展示只有一个相机样例；其它产品轮廓、透明/软质表面和更复杂的变形状态仍需用同一交接契约验证。示例中的静态环境探针不适用于动态光照/移动环境，所有路径仍需真实浏览器视觉检查。

## 机制讲解

**适用：** 机构、机械、解剖或其它对象的部件会运动，或用户需要理解内部状态、因果和部件关系。

**流程：** 先列部件/关节/连接关系和需要解释的状态 → `procedural-construction.md` 与 `geometry-recipes.md` 建静态可读结构、剖切窗口和枢轴 → 在 `motion-and-scale.md` 定义唯一状态源（影片按绝对时间 `stateAt(t)`，交互机构需明确暂停/步进/复位状态）→ 所有网格变换、标签和读数消费同一状态 → 补齐展示场景、材光和说明UI → 对初始、关键状态和中间状态逐一检查，验证长度/轴线/碰撞等适用约束。

**现有起点：** [`mechanism-showcase`](../assets/examples/mechanism-showcase/index.html)及[样例说明](../assets/examples/mechanism-showcase/README.md)提供完整机构、互动状态、结构标注和可导出短片；其[滑块曲柄工厂](../assets/examples/slider-crank.mjs)把解析`stateAt(t)`同时交给零件变换、读数与`renderAt(t)`影片消费。它以理想刚体运动学为范围，不等于力学/热学仿真。单一铰链工厂见[`hinged-cabinet.mjs`](../assets/examples/hinged-cabinet.mjs)，参数影响几何的实验见[`algorithm-lab`](../assets/examples/algorithm-lab/index.html)。

**交接和首检：** 状态数据明确单位、关节轴、范围/相位和可逆求值方式；每个可见动态件至少有一个真实变换消费者。运行相应的状态/运动单测，随后检查关键状态、循环接缝/行程端点与中间状态的实际页面；影片调用同一状态源时还要执行离线导出、随机访问确定性与最终MP4解码后验。可环绕场景在关键状态执行[观察覆盖接力](#非影片场景的观察覆盖接力)。

**失败回退：** 机构行程或约束错误回到运动学/状态函数；状态正确但运动件接头漂移回到枢轴、局部根和装配；模型动作正确而标签/读数不同步回到唯一状态消费者；静态外观粗糙则回到构造路线，不靠加速/减速掩盖。

**已知缺口：** 当前完整机制纵向样例只有理想滑块曲柄；多关节、闭环机构、解剖/软体运动与接触/力学求解仍需题材专用模型，不能把本例解析式当通用状态解算器。新机构必须单独推导或选择其约束解法，并检查多解、奇异位形和稳定性。

## 导演短片

**适用：** 用户要的是一个固定时长/节奏/镜头的成片、循环动画或可导出视频；若用户要在场景里自由探索，则交互导览才是主路线。

**流程：** 先按环境/物体/机制之一完成可读的完整场景 → 明确镜头段、焦点、动作节拍和时长 → 以影片绝对时间函数统一相机、物体、表面、灯和DOM覆盖 → 固定seed与离线资源 → 预检整条镜头的主体可见性和场景遮挡 → 运行官方导出 → 从最终MP4解码抽帧并完整播放，检查首中尾、运动极值、循环接缝、文字和压缩。

### 镜头路径覆盖预检

相机位姿/速度在循环首尾相等只证明状态连续，不证明主体在画面中或摄影机在场景内部。至少登记 `t=0`、每个镜头切换点、路径最近/最远位置、关键动作点、25%/50%/75%和最后一个编码帧；10秒、24fps成片的最后编码帧为`10 - 1/24`秒，不是`10`秒。

从目标工厂取真实世界表面样点，为主主体、关键连接和环境锚点分别设置可读阈值；每个登记时刻调用同一`renderAt(t)`更新动态与相机，再调用现有[`inspectFeatureVisibility`](../assets/scene/view-readability.mjs)核对投影、屏幕裁切和不透明几何遮挡。样点应来自目标表面，遮挡集合使用最终几何或保守代理；这不是构图/美术评分，阈值也须按任务登记。

```js
import {inspectFeatureVisibility} from './assets/scene/view-readability.mjs';

export function auditFilmPath(THREE,{samples,renderAt,camera,features,occluders,viewport}){
  return samples.map(({id,time})=>{
    renderAt(time);                 // must update the whole scene and camera at this absolute time
    camera.updateWorldMatrix(true,false);
    const results=features.map(feature=>{
      const report=inspectFeatureVisibility(THREE,{
        camera,points:feature.pointsAt(time),occluders,viewport,epsilon:feature.epsilon??.01
      });
      const minVisible=feature.minVisibleFraction??1;
      const minWidth=feature.minProjectedWidthPx??0;
      return {id:feature.id,report,satisfied:
        (report.visibleFraction??0)>=minVisible &&
        (report.sampleBoundsPx?.width??0)>=minWidth};
    });
    return {id,time,results};
  });
}
```

任一必需主体样点被裁切、被院墙/山体/道具挡住或低于登记像素尺寸，先修相机轨迹/目标点；若该视向本来就要求看见该主体，才调整上游空间/遮挡物。通过几何预检后仍要审最终MP4：透明材质、反射、后期和实际构图不能由射线报告代替。

**现有起点：** [`scripts/render_film.mjs`](../scripts/render_film.mjs)和[`video-export.md`](video-export.md)是影片取帧/编码/后验工具，不是场景创作模板；`assets/examples/production-lab`是材光工作台，不是短片环境范例。

**首检：** `node <skill-root>/scripts/render_film.mjs --html <absolute-film.html> --out <absolute-export> --video`，随后 `node <skill-root>/scripts/verify_video.mjs <absolute-export>/manifest.json`。两条命令只验证导出链与文件契约；完成度仍以最终编码视频实际审看为准。

**失败回退：** 循环跳变或镜头轨迹不连续回到绝对时间状态/相机曲线；编码前画面正确而MP4不符回到最终视频解码与编码参数；导出报错回到READY/`renderAt(t)`/资源完成契约，不以屏幕录制代替可复建导出。

**已知缺口：** 有稳定导出器与接口契约，缺少通用的完整片段/时间线起始工程；每部短片需由主场景路线提供资产。

## 交互导览

**适用：** 最终作品必须由用户拖拽环绕、改变观察位置、选择物体或探索区域；交互是主要交付能力。影片中的导演相机按短片路线处理，不要用OrbitControls替代导演镜头。

**流程：** 按环境/物体主线建立完整场景 → 列出用户可执行动作、状态和复位契约 → 用 `camera-interaction.md` 定义目标点、缩放/俯仰/方位限制和输入 → 场景建立足够的背面、底面/顶面及侧向内容 → 逐个执行动作/观察任务，检查遮挡、相机穿越、背景空洞和UI状态一致 → 对缺失方向回到空间拓扑补场景，不以放宽controls冒充内容完成。

**现有起点：** [`guided-world`](../assets/examples/guided-world/index.html)和[`activity-lab`](../assets/examples/activity-lab/index.html)可查看交互接线。`guided-world/main.mjs`将极角限制在0.2至1.42弧度，因此它不能证明完整顶/底视已实现；复制时需依据交付约束重新定义limits，并实际检查场景外壳与背面内容。技术工作台并非360°成品模板。

**交接和首检：** 执行[跨路线观察覆盖接力](#非影片场景的观察覆盖接力)，再按本路线实际动作检查探索区域、对象选择和状态反馈。360°任务至少实际检查前后左右、顶视、低角度/底视和高风险组合；控制器覆盖与实际画面分别记录。

**失败回退：** controls到不了要求的方位，回到相机范围和交互事件；镜头到达后暴露空幕后方、开口或地表底面缺失，回到环境/物体几何与闭合空间，不放宽角度限制隐藏缺口；放大后穿模则检查缩放端点和真实包络。

**已知缺口：** 当前工作台有受限OrbitControls示范，缺完整闭合场景、多角度观察点与360°回归样例。

## 路线组合与任务映射

主类型按最终交付唯一选择；其它要求作为组合责任：

| 当前任务信号 | 主路线 | 可组合责任 |
|---|---|---|
| 多区域目的地、山谷村落、洞窟环境 | 环境场景 | 自然形态、水体、路径/道路、材光、导览交互 |
| 独立可展示的仪器或物件 | 物体展示 | 机械动作、局部室内/展台、材质和产品光照 |
| 四冲程、铰链动作、解剖状态 | 机制讲解 | 物体展示环境、说明UI、特定角度相机 |
| 10秒循环并输出视频 | 导演短片 | 环境场景、自然形态、物体或机制资产 |
| 漂浮岛需拖动360°查看 | 交互导览 | 环境场景、自然地形、对象细节和底部结构 |

冻结基线的12条短/详细提示词分别覆盖上述六种任务族：`ENV`→环境，`OBJ`→物体，`NAT`→环境+自然责任，`MECH`→机制，`CINE`→导演短片，`INT`→交互。短/详细版本维持相同主路线；详细版只把约束落入同一规格，不增加另一个主流程。路由分类本身是静态覆盖，不代表模型遵循行为或画质收益；需在评测中另外验证。
