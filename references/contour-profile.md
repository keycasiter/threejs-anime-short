# Continuous contour profile and complete relations

`createContourProfileSource(T, options)` in `assets/geometry/contour-profile.mjs` sweeps a simple closed `(outset,z)` section around a strictly convex closed XY contour. Positive outset points outward; local +Z points out of the reference plane. Exact adjacent offset-line intersections provide miter corners. Invalid offset collapse, excessive miter, self-touching sections, lost Float32 clearance and triangle-budget overflow reject construction. This is a bounded 2D offset family, not an arbitrary 3D offset or manufacturing guarantee.

The returned source owns its geometry and exposes `metadata`, `surfaceAt(u,v)` and idempotent `dispose()`. `surfaceAt` samples the actual Float32 indexed triangle, returning independent point, normal, tangent, right-handed frame and triangle/band identifiers. The normalized parameters follow reference-contour and section arc lengths; 1 wraps to 0. Explicit crease arrays govern equal-weight neighboring cell-normal averaging; material boundaries alone do not create creases. Offset-ring arc UVs can shear at miters. Geometry must remain unchanged while querying; queries reject after disposal. Materials are externally owned.

## Design before calling the generator

Choose the reference contour from the actual opening or outer boundary. Positive outset expands it; negative outset moves into it. A reference contour is not automatically the final envelope. Design the section as real thickness, shoulders, returns and joining bands at the intended view scale; extra segments do not supply that design. Use the same boundary and actual section to construct adjacent surfaces, then check finite contact rather than a center-only anchor.

| Option | Actual contract |
|---|---|
| `contour` | 3–2048 finite XY points, no repeated endpoint; strictly convex simple ring, either winding |
| `profile` | 3–256 finite `[outset,z]` points, simple closed section, either winding; inward offsets must remain valid |
| `contourCreases / profileCreases` | Matching boolean arrays, default all true; true separates adjacent cell normals at that vertex, false explicitly smooths it |
| `bandMaterialIndices` | One nonnegative safe integer per section edge, default 0; a material array must cover the indices it uses |
| `uvMeters` | Positive finite units per UV unit, default 1; approximate ring/profile arc chart, not a universal orthogonal TBN |
| `miterLimit / epsilon` | Defaults 4 / 1e-9; finite miterLimit ≥1 and epsilon >0; failures reject rather than clamp the shape |
| `maxTriangles` | Positive safe integer, default250000; `2 × contour.length × profile.length` must fit before allocation |

Bind the returned geometry to an actual Mesh, preserve its source coordinates before placement or merging, and transform query points/frames through the same part/root matrices. Normals need the inverse transpose. Change structural parameters by rebuilding source, neighbors and their queries together under one existing slot; borrow shared materials. If the requested contour is concave, the offset folds, or a general 3D path is needed, choose another supported representation instead of silently repairing this input.

## Complete technical relationships

`createContourRelation(T, {design, id='opening-bearing', mode='profile', parameters={}, materials})` in `assets/examples/contour-relations.mjs` reads the supplied design. Node consumers load `assets/examples/contour-relations-design.json` using `readFile`; the browser fetches that exact file. Both consumers read one numerical design rather than duplicate its coordinates in the entry.

| Input | Behavior |
|---|---|
| `id` | `opening-bearing`: open frame plus genuinely holed thick panel and raised contact fixture. `support-recess`: horizontal frame plus a finite recessed deck. |
| `mode` | `plain` selects registered control section; `profile` selects registered design section. Both retain envelope, contour and neighbor data. |
| `parameters` | `spanX`, `spanY`, `sectionWidth`, `sectionHeight`, default 1; finite values in `(0,3]`, additionally subject to actual finite-support validation. Unknown own keys (including `constructor`, nonenumerable keys and symbols) reject. Contour and panel outer XY share span scaling; profile outset uses width scale. All profile and neighbor Z values use height scale, preserving contact and scaling the recess. |
| `materials` | Required borrowed `frame`, `panelDeck`, `attachment` Three materials. Every frame band binds the same frame material. Relation disposal never releases these. |

B1 panel uses the exact frame reference contour as its hole. Panel front and frame rear coincide at Z=-.10, with finite annular bearing and a genuinely open center. The contact fixture keeps the identity `opening-contact-fixture` across A/B, but uses each registered branch's actual band/t/s to follow the changed surface. Its footprint uses registered base depth/width; its raised body height is twice registered base width. Its base is aligned to the actual source frame, with no separate ideal-profile contact formula. Every base corner must lie in the selected actual Float32 cell (two indexed triangles); because this cell and base are convex planar polygons, this certifies the complete finite footprint. Candidates whose fixed base crosses a band edge or contour corner reject before commit. The full rear bearing must also fit the actual rectangular panel bounds. Thus positive numeric scales alone do not establish a valid relation; for example B1/profile sectionWidth=.2 rejects, while frozen defaults remain unchanged. A footprint spanning adjacent cells is conservatively rejected even when those adjacent cells might happen to be coplanar.

B2 deck uses the exact reference contour as its outline. Its side meets the frame inner wall over a finite interval, and its top at local Z=-.035 sits .060 below the highest lip at .025. The complete local construction, including ports, sits in an internal group rotated X=-PI/2; the external asset root stays an ordinary Y-up unit frame. No ground plane obscures the underside.

The returned handle provides actual `root`, `parts`, `materialBindings`, `anchors`, `ports`, `readState()` and `dispose()`. Parts include `axes` and `frame`, plus `panel`/`attachment` or `deck`. Bindings contain the actual mesh and borrowed material, with the semantic role. The source owns frame geometry; the relation scope owns neighbor and fixture geometry. Do not register these children again with another owner.

`ports.query({contourSegment,t,profileBand,s}, space='root')` converts registered segment/band coordinates to the source's arc parameters and calls its actual `surfaceAt`. Both t and s must be finite in `[0,1)`. Each named cell maps to the normalized half-open interval `[arc[index]/total, arc[index+1]/total)`. If floating-point conversion rounds an interior coordinate to the upper bound, the adapter uses that bound's previous representable number; the exact lower bound stays in the named cell. This also preserves the last segment/band before the closed seam at 1. The kernel's direct normalized exact-boundary rule still selects the outgoing cell. Verify contact against the returned triangle ID and the actual indexed Float32 positions/normals (including winding), not an ideal section formula. `ports.surfaceAt(u,v,space='root')` exposes direct normalized queries. Space is `source`, asset `root`, or `world`. Point/frame composition includes source axes and, for world queries, all root/parent transforms. Normals use the inverse-transpose matrix. The returned frame retains the full affine transform under nonuniform asset scaling, so it need not remain an orthonormal matrix. Queries and anchors reject after disposal. `readState()` remains available and returns a serializable detached snapshot with parameters, source metadata, local anchors, actual geometry/material UUIDs, triangle/draw budgets and disposed state.

## Local interactive lab

Serve the package root using a local HTTP server and open `assets/examples/contour-lab/index.html`. Supply Three **0.180.0**, its matching `examples/jsm/` tree and LICENSE at `assets/examples/contour-lab/vendor/{build,examples,LICENSE}`. This external dependency directory is supplied by the project and is not vendored into the Skill. Do not mix Three runtime instances or addon versions.

The lab uses the existing resource scope, synchronous asset slot, lighting rig, native sky/PMREM helper and OrbitControls. The renderer is registered before scene-owned dependent color/depth materials, so reverse cleanup disposes those materials while native renderer program/property bookkeeping remains alive. The loop and listeners stop before assets/targets/materials retire; renderer disposal comes last. For this lab’s opaque rigid meshes only (no displacement, morph or skin), the scene owns one shared `MeshDepthMaterial({depthPacking:T.RGBADepthPacking})`. The actual slot builder lends it to every shadow-casting mesh via `customDepthMaterial`; relation factories continue to own geometry only and never dispose this borrowed depth material. This conditional rendering policy is not a general shadow-material recipe for deforming or cutout meshes. Fixed lighting bounds are computed once from the actual union of all four default relationships, then remain unchanged through A/B switching and custom rebuilding. Lighting, material recipes, exposure and camera poses come from the shared JSON. Native sky gradient defaults remain source-bound; a single sky-only PMREM capture is retained through all rebuilds. The visible sky radius is half camera far (20), and follows the camera. No object capture, detail maps, postprocessing or double-sided geometry enter this comparison.

UI supports full azimuth orbit, full polar limits (OrbitControls retains its native pole epsilon), zoom/pan, registered view selection, camera reset, complete default reset, relation/mode switching, four structural parameters, continuous shared frame roughness in `[0,1]` (slider and API preserve the same value), invalid candidate rejection, ten rebuilds and exit. Mode/parameter replacement preserves the user's camera; changing relationship through the UI refreshes the view list and selects that relationship's first registered pose. Programmatic rebuild({id}) refreshes options while preserving the current camera and explicitly labels it custom. Selecting a registered view verifies the actual post-controls camera position and target within 1e-8 m before naming it; all six JSON poses are admitted by the controls. Camera changes are never overwritten by the render loop. The custom-view option is disabled and serves only as the displayed state selected by Orbit/API; users choose among registered views. Custom parameter/material changes are explicitly labeled and are not frozen comparison views.

`window.__CONTOUR_LAB__` exposes:

- `readState()`: real asset/slot revision, render count, camera/target, material and geometry UUIDs, actual anchors, renderer memory and the actual `renderer.info.programs.length`, scene-owned shadow depth UUID/packing, fixed lighting bounds, sky UUID/capture count and owner state. Returned values are detached.
- `rebuild({id?,mode?,parameters?}={})`: synchronous candidate build, mount and commit; returns true on success or false on failure, retaining the prior live root/revision on pre-commit failure. A retirement error after commit returns true and adopts the actual new current/revision; `replacementStatus` is `committed-with-cleanup-error` and the UI states that the new version is committed. Normal commit reports `committed`; pre-commit rejection reports `rejected`. Parameters are merged with current values only after strict own-key checks; DOM synchronization sits outside the replacement catch.
- `setView(name)`, `reset()`, `setRoughness(value)` and `setUIVisible(boolean)` for reproducible view capture and controls.
- `dispose()`: stops the animation loop, removes listeners, retires the current slot, disposes sky/lights/controls/shared materials/renderer and removes the canvas. Repeated calls have no effect; readState remains available.

Node checks use real Three and the current kernel. They verify holes/front-back hits, closed neighbor volume, finite contact, recess/underside, A/B envelope and attachment behavior, nonuniform root/world composition, parameter vertices, snapshot isolation, slot failure retention, late construction cleanup and exact geometry ownership. A narrow main-state test additionally executes the actual main rebuild/sync/status/view-list consumer functions with real slot/factory and DOM-value doubles. It injects a real old geometry disposal-listener exception and verifies committed revision, state and UI labels together. It also executes the actual r180 OrbitControls configuration against all six registered poses, the production initializer with a CPU renderer-lifecycle double to verify dependent-material retirement order, and actual slot builders to verify shared depth borrowing across replacements. The disabled custom display option is checked independently. This is a CPU boundary test; it does not execute WebGL/startup or claim browser input coverage. They do not qualify actual GPU rendering, browser input/resource behavior or visual improvement. Qualification still requires the registered 2 relationships × 2 modes × 3 views and independent paired review of edge transitions, thickness/negative space, contact and overall proportion.

## Complete world consumers

The [core world](../assets/examples/core-world.mjs) uses this same kernel through [regional construction](../assets/examples/region-programs.mjs) and the optional `buildArchitecturalBay(...,{frameProfile,materials:{frame,...}})` path. A bay section is local `[outset,z]`, with z=0 placed at the actual wall front. Its finite rear band joins the wall, its outer band joins the sill; dimensions stay within the declared frame width/depth. Omitting frameProfile keeps the original plate-frame path. `profileSources` holds the actual source/part and source/part/root/world triangle query; the bay owns it, callers borrow it.

Regional `boundarySources` connects live source/part/query handles for opening frames, horizontal edges and genuinely open containers. Horizontal edges share actual inset boundaries with their solid core; a roof opening remains open. Container bottom and soil/deck derive from that same interior boundary. The [section recipes](../assets/examples/boundary-profile-design.mjs) are this example's editable data, not universal edge styles. New tasks design their own sections and neighbors.

World placement still measures the complete actual envelope and validates it against the layout. New profile slots use scalar/native formed response, since their miter UVs do not guarantee a metric normal-map chart. Peripheral sources pass their actual indexed groups and source fields into static assembly, then retire. `bakedBoundarySources` contains detached definitions, source-to-world-root-local matrices and [actual output ranges](assembly-provenance.md), not closed query handles or material-inferred identities. Live `boundarySources` remains in regional-root or explicit world space; multiplying a baked position by world.root.matrixWorld gives its current world position.

Use [core-lab](../assets/examples/core-lab/index.html) with the same local r180 vendor layout to inspect all three topologies/two looks, structural replacement, actual source snapshots and lifecycle. Its presentation owns one shared depth material for the current rigid opaque casters before any world reflection capture; deforming/cutout assets require matching shadow representation. This is a mechanism example. More articulate edges can help local reading while whole-scene hierarchy, distribution and material design still need their own target checks.
