# 可执行的场景制作系统

将视觉目标落实到五类生产能力：资产生成、表面表达、空间组装、环境渲染、运行与检查。每类都回答“输入是什么、怎样生成、谁使用、如何看见”。制作从完整空间草案进入完整代表关系，再扩展资产族；由真实画面决定继续投入哪一层。

## 1 让模块真正接力

### 运行依赖与开发节奏

运行初始化可依次为：renderer/scene/camera → 材质与公共字段 → 资产工厂 → 场地/对象组装 → 背景/天气/动态 → 反射探针与shader预编译 → 帧循环。这个顺序说明运行依赖；开发可以在同一代表区域内往返设计、形体、材质与灯光。

项目按下表组织真实接口。表面、环境、镜面、视觉雨、后期和工作台已有[可调用模块](production-toolkit.md)，先按目标选用；资产/场地逻辑仍由具体设计实现，不能把这些接口当万能场景引擎：

| 模块 | 输入 | 返回/真实消费者 |
|---|---|---|
| 材质目录 | renderer、质量档、材料配方、环境状态 | `get(name, options)`返回实际Material；颜色/数据纹理与统一uniform由Mesh消费 |
| 资产工厂 | 结构尺寸/形态、表面状态、seed、材质目录 | `root`、局部`anchors`、活动件句柄、占地/碰撞近似、`dispose()` |
| 场地 | 统一布局、区域/路线/宿主、工厂 | 世界场景、分区、室内/开口、表面查询、镜头；几何与其他消费者读同源数据 |
| 环境/FX | 场地语义、相机、光照、时间与事件 | 真实mesh/shader/灯或声音；需要每帧更新的返回`update(t,dt)` |
| 渲染 | 完整scene/camera、灯、深度、质量档 | 最终像素；反射/后期pass明确顺序、输入与输出颜色空间 |
| 工作台 | 同一工厂与真实运行入口 | 单资产/材质样片/完整场景、固定镜头、状态冻结、效果开关和统计 |

共享context只保存确实共同使用的renderer、scene、camera、seed、quality、clock、fields和事件。按名称派生随机源，例如“区域/资产ID/用途”的hash；改变一类细节时不应改变全场随机序列。历史模拟若仍用Math.random或帧间状态，需要显式复位，不能自称像素确定。

**实际接通的标准：**读取同一输入值→发出真实geometry/Material/uniform/instanceMatrix→进入当前scene并被渲染。元数据里写了light、wet或LOD，未接到消费者时仍只是计划。字段变化实验先检查真正读回的消费者，再看像素。

## 2 从形体规格到完整资产工厂

### 选择能表达特征的生成方式

| 目标形体 | 生成步骤与Three.js方向 | 需要单独处理的部分 |
|---|---|---|
| 板壳、框架、屋面 | 先外轮廓与开口，再用`Shape`/holes挤出厚度；框架按开口边界分件；倒角尺度由构件尺寸与镜头决定 | 内外壁、端面、窗洞内侧、门轴、饰边与承载，不能只贴黑色矩形 |
| 管、瓶、塔、轮组 | 写有物理尺度的回转剖面；外壁/内壁分开；端环连接；周向与剖面UV按长度生成 | 开口、胎面/胎侧、法线硬折；读[截面几何](profile-geometry.md)并用已有源码 |
| 波纹、肋板、层状体 | 写一个包含峰/谷/平直段的截面单元，按周期展开；端部/边框另做，法线在设计折线处分开 | 数量变化不能改掉整体包络；近景轮廓承担几何，细小重复可换表面表达 |
| 船壳、车头、地质/有机连续体 | 沿结构轴给分站截面：宽、厚、偏心、旋转、收分；在转向/交界处加控制站，放样并连接 | 开口和分叉另建拓扑；在最终曲面上检查局部朝向，整体正体积不能证明没有翻面 |
| 布罩、垂片、软组织 | 从支撑/包络求主面，再定义垂落、压缩或张力方向；网格密度跟随弯曲变化 | 褶皱依附受力方向，边缘有有限厚度/翻边；不把每点噪声当软体结构 |
| 树木、毛簇、生态对象 | 先主干/主枝/分枝层级与生长方向，再按枝段建立从属群；保留疏密、空隙与重量变化 | 叶/花/附生物分布依附真实枝段或宿主，不能在球形包络均匀填粒子 |

这些是表示选择，具体尺寸来自设计。选定后把一个资产拆成：**主结构→结构分段/转折→连接与开口→功能件→表面形成区域→少量身份细节**。每部分有真实空间位置，子件位置由同一局部尺寸与锚点导出；修改宽高时门、框、铰链、开口和附件一起重算。跨资产装配实际读取输出锚点并变换到共同坐标；代表关系完成后扰动一个主尺寸，读回连接端点距离，避免只声明anchors而仍手写独立坐标。

### 把结构变成可复制的生产代码

[资产装配器](../assets/scene/asset-assembly.mjs)提供已经实现的接口：

```js
import {createAssetAssembly} from './asset-assembly.mjs';
// THREE与mergeGeometries由同一锁定版本注入。
const assembly = createAssetAssembly(THREE, {mergeGeometries});
assembly.add(panelGeometry, shellMaterial, {
  matrix: panelLocalMatrix, castShadow: true, receiveShadow: true, layers: 1,
});
assembly.dynamic(doorPivot); // 尚无parent的真实活动层级
assembly.anchor('mount', mountLocalMatrix);
const asset = assembly.finish();
scene.add(asset.root);
// asset.anchors是Map<string, Matrix4>，均为资产局部坐标。
```

它克隆输入几何、烘焙局部变换，以材质UUID/阴影/图层分桶，并兼容索引/非索引及基础属性；动件保留。输出stats是结构统计，不是GPU draw calls或美观评分。它拒绝镜像/退化变换、morph/skin/实例属性等不适合此静态路径的输入；这些对象走独立运行分支。已有多材质geometry先提取成对应子几何与材质，再送入；不会按geometry.groups自动分材质。

`finish()`结果可复用，之后不能再add；`dispose()`只释放装配器创建的静态几何。输入geometry/material和动态子树由调用者管理。生成工厂应统一回收临时几何以及自有动件几何，避免把“可重复生成”变成显存泄漏。

可直接运行的组合例子：[有铰链与通风开孔的设备箱](../assets/examples/hinged-cabinet.mjs)。它组合已有真实开孔板与新装配器，返回活动门、静态局部锚点与`setOpen(open)`；`serviceClosed`是闭门布局快照，`parts.serviceAnchor`是门下随动Object3D，使用`getWorldPosition()`取得实际服务点。展柜与场景都调用`buildHingedCabinet`。示例证明接口、结构与连接方法；不同题材的最终美术仍需重新设计。

### 形态变体、实例变化与缓存

几何变体控制截面、门姿态、部件布局或破损形状；实例变化控制位置、有限偏转、颜色和表面状态。几何cache key包含所有影响结构的输入；材质对象或目录作为外层上下文，避免第二个项目拿到首个项目材质。克隆的geometry/material通常仍共享，需形变/改材质时明确克隆或生成新变体。

动作会改变的门、叶片、骨骼和灯状态使用独立句柄；静态合并结束后不能再按旧子件变换。远景可用不同表示，但共享主尺度、轮廓站位、开口和布局。

## 3 让表面从形成规律生成

### 先定尺度、区域与通道

每种材料明确：基材与涂层、米制图案尺度、使用/环境形成规律、颜色/粗糙度/金属度/高度或法线的响应。低频负责大区域、中频负责接缝/斑块、细频负责表面颗粒；噪声只扰动已定义的结构，不取代结构。

| 形成原因 | 可执行区域构造 | 通道响应示例 |
|---|---|---|
| 底部受潮/泥溅 | 相对真实承载面的高度带×暴露方向×低频破边 | 底色稍暗，roughness改变，法线幅度随水膜减小 |
| 涂层脱落 | 磕碰/边缘或使用区域×成簇缺损；露底、底漆、锈与流痕分别算 | 颜色与metalness随真实层改变，roughness和height同步变化 |
| 纤维/木纹/拉丝 | 构造方向、UV主轴或曲面参数确定方向，结点/接缝局部扭曲 | 细长频率、轻微高度与粗糙度，不用各向同性彩噪声 |
| 湿地/积水 | 大尺度水位差或凹陷mask→连续积水/浸润/潮湿带，结合排水/屋面遮挡 | 水面法线与地面法线渐变，roughness、反射权重与底色共同变化 |
| 自然表皮/生长 | 组织分区、曲率/枝段年龄、朝向和接触面 | 色层/半透/粗糙度按题材选型，保留光滑/粗糙区域对比 |

可从[原创程序材质目录](../assets/materials/procedural-palette.mjs)选配方，或用[表面字段模块](surface-detail.md)将自定义同源材料场烘焙为需要的通道；接入方法与物理尺度见[可调用工具](production-toolkit.md)。颜色数据按颜色空间处理，roughness/metalness/height/normal是线性数据。ORM约定R=AO/G=roughness/B=metalness；必须核对实际material读取通道及乘数，不能因为打包正确就默认材质正确。

### UV与法线要有尺度

盒体根据面法线选择对应的资产局部XY/XZ/YZ米制坐标；扫掠侧面U取截面累计长度、V取路径累计长度；回转周向取圆周距离，纵向取剖面弧长；端盖单独投影。统一材料tile的米制尺寸，再决定repeat。不要同时在UV和repeat中重复缩放。

高度转法线时，用实际世界高度幅度与每像素物理尺寸求斜率，不能把“2个像素的差”当成固定世界坡度。UV不等比例与切线度量、非均匀缩放需按[表面细节](surface-detail.md)处理。远处用mipmap、导数衰减与合理roughness控制细纹闪烁；扩大微法线不应让整件物体变成砂纸。

### 烘焙路径与动态路径

一次生成、反复使用的材料可先用CPU/Canvas/DataTexture烘焙并缓存；许多复杂材料或大纹理确有成本时再用GPU离屏生成。MRT是减少生成遍数的方案，不是高品质前提：GPU路径需验证附件数量、格式、编码与读回，程序失败要记录实际降级。

局部标识、数字、规则图案和使用痕迹可由Canvas生成表面贴花，按实际表面参数/网格贴合；留边防atlas串色，厚度/开口仍由几何承担。模型表面数据与概念图替身的用途不同。风格不需要做旧时，使用洁净表面与有控制的材质差异。

## 4 用空间语法组织完整场景

先做功能骨架，再组装对象。每个区域明确工作/通行/停留/储存或生境用途、观看焦点、支撑面、与邻区的连接。组成一组的对象从同一局部框架生成：工作面决定设备前向，接口决定线缆/管道端点，路径边决定护栏和照明，生长带决定植被密度。随机仅在这些关系内产生变化。

| 尺度 | 建造动作 | 目标画面 |
|---|---|---|
| 全场 | 布局主要体量、承托面、高程、路径和远景，安排可见空隙/地平线 | 一眼能读出方向、焦点与空间层次 |
| 分区/组团 | 区域内有主物、支撑物、次级物和用途联系；边界与留白参与构图 | 物件属于同一个场所，疏密有变化 |
| 单体/部件 | 通过统一工厂生成结构、连接与表面；焦点和相邻支撑都达到对应景别 | 近看没有占位物破坏关系 |
| 远景 | 按邻接高度省略不可见内面，减少小构件，保留轮廓空洞、节奏与色块 | 远处延续场地，三角与绘制量可控 |

相机用位置、目标、FOV、俯仰和前景共同设计；先固定目标景别，观察透视与遮挡，再改体量/组团。改变相机距离与焦距不能相互混淆。360°场景每侧都有有意的空间信息；远景环绕、背面结构、透明面和受光随相机检查。不要为填满每侧牺牲所有负形。

复杂宿主、层叠地面与悬挑使用真实表面/锚点；解析曲面优先从同一`surface(u,v)`生成附件。散布先做候选容量预演和允许区/间距/支撑筛选，再复用实际通过点。更多算法按需读[分布方法](detail-distribution.md)，不用为此自动加载其正式阶段台账。

## 5 统一环境、受光与渲染链

### 先让环境真正可反射

先设计主光方向、明暗分区和背景内容，使大形体、转折与连接能被看见。天空或环境生成器同时服务可见背景与PMREM；太阳极高亮圆盘可在环境捕获时单独处理，避免与方向光重复供能或产生高亮噪点。普通材质需要真实环境才能展示粗糙度/金属差异。

室内反射探针在场景几何和关键灯具完成后捕获，按室内材料/区域分配；有动态变更时明确更新预算。发光面、真实灯、反射里的亮面和Bloom是不同机制；要看见照亮地面，必须有灯或对应光照算法消费者。

平面反射适用于近似平面且画面确需场景镜像的接收面。镜像相机、斜裁剪平面、反射矩阵、目标分辨率和采样约定成套实现；排除接收面自身与递归对象，保存并恢复renderer状态。凹凸/roughness用于扰动和过滤反射；曲面/大范围不同水位不能强套一张平面。已有[平面镜像适配器](../assets/rendering/planar-reflection.mjs)复用官方Reflector，适用清晰平面镜像；它不提供本段所述roughness过滤和PBR湿地混合。需要后两者时单独实现采样/能量与多层表面，再验证小样。

### 再选择必要的后期

| 目标 | 路径与输入 | 常见需要定位的责任层 |
|---|---|---|
| 接触/夹缝更可读 | 正确几何与投影为基础，必要时AO读取深度/法线；避开亮面脏边 | 间隙过大先修几何，不能只加黑AO |
| 远近与光束 | 深度、相机射线、方向光阴影、介质密度；低分辨率计算时做深度感知上采样 | 简单全屏色雾无法表达被遮挡的光束 |
| 湿面反射 | 基材/水膜、roughness、法线、真实环境/平面或其他适合的反射源 | 只有亮斑不等于反射到场景 |
| 高亮柔和与光学气氛 | 线性HDR→有限Bloom→曝光→一次tone mapping→显示输出；眩光有遮挡依据 | 重复tone mapping、颜色图当线性数据、过亮曝光掩盖材质 |

中间HDR pass保留线性辐亮度，最终tone mapping与输出转换各执行一次。直出渲染与自定义后期分别配置，不把renderer的tone mapping和自写曲线重复叠加。每新增pass都记录尺寸、格式、深度与资源释放，失败时显示实际降级状态。

## 6 动态、反馈与预算一起设计

先主动作与结构因果，再次级动作：门→铰链/连杆，枝干→从属枝叶，波浪→边缘泡沫/漂浮物，接触事件→水花/声音。共享场/事件应有真实消费者；有相似参数名并不代表同步。

持续天气可用相机附近实例体积和shader位移，不逐个建Object3D；室内/遮蔽/开口条件从场地读。短时事件拆成少数寿命层：起始、主响应、余波，分别控制方向、颜色、尺度与衰减。透明粒子使用有界池、批次与排序策略；超预算采用明确删层/降采样，不让几何无限增长。真实物理不是每种效果的前提，解析轨迹和规则形变需要诚实描述其边界。

| 预算层 | 优先控制 |
|---|---|
| 几何 | 局部细节按像素分配；同材质静件合并；同几何实例化；近/中/远结构表示 |
| 材质/纹理 | 配方与变体缓存、标签atlas、物理尺度、mipmap；避免每对象新建一套大纹理 |
| 渲染 | 阴影覆盖、更新频率、反射分辨率/排除对象、AO/体积步数与多遍次数 |
| 动态 | 活动灯池、粒子/声音/模拟槽、距离删层、避免每帧生成对象和纹理 |

质量档改变具体预算和表现，而不是只改一个DPR。先量实际设备的帧时间、draw calls、三角、纹理与pass；将结构统计、估算显存、瞬时FPS和持续性能分开。降级后还要检查目标视觉是否成立。

## 7 建立能检查真实结果的工作台

已有[工作台与绝对时钟](../assets/runtime/scene-workbench.mjs)和[完整接线例](../assets/examples/production-lab/main.mjs)可复用。在同一代码入口实现场景、单资产、材质样片模式；URL参数只是选择真实模块。最小工作台提供：

| 控制 | 必须改变/读回的真实状态 |
|---|---|
| 资产类型、结构参数和seed | 真实工厂输出的网格/动件，展柜和全场共用同一调用 |
| 相机快照 | 实际position/quaternion/FOV、target和矩阵；停止循环后设置待处理参数不算相机已改变 |
| 时间与状态 | 动作时间、历史模拟步、粒子年龄、随机状态、曝光/累积历史分别固定或复位 |
| 材质/效果开关 | 真正的material/uniform/pass，注明关闭范围；普通normalScale不控制自写shader的法线 |
| 运行统计/错误 | 当前质量档、renderer与shader实际状态、资源/调用统计；失败或占位回退不写成品质通过 |

做消融先固定相机、几何、时间/状态、视口与曝光，复取同一基线确认稳定，再逐项关闭/替换机制。实际打开对照图说明看见的变化，不用像素差数量作为美观分数。同场消融能解释局部贡献，不能证明新Skill跨题材效果提升。

## 方法依据与适用边界

维护时查[源码机制索引与验证范围](production-systems-source-map.md)。
