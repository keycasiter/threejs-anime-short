## 核对层级

| 阶段 | 实际验证 | 进入下一阶段的依据 |
|---|---|---|
| 参考拆解 | 可见画面与对应实现证据 | 有复用/改造决策，未知项明确 |
| 核心镜头 | 目标机位/分辨率下的形体结构、最终材质/光影、动作和构图，含原尺寸帧及连续片段 | 达到下述统一放行标准后才扩片 |
| 视觉成片 | 全片接触表、关键帧大图、连续动作 | 角色/环境/FX 一致，无已知严重穿模、遮挡和跳变 |
| 实时运行 | 按交付模式检查时间轴控制；若包含可交互场景，真实操作环绕/缩放/复位并抽查相机包络 | 时间状态正确、音画合理对齐；所有可达视角均由已建模环境覆盖 |
| 目标交付 | 实际文件或链接、视频信息、抽帧和声音 | 用户能打开所要求的产物，验收范围记录清楚 |

区分视觉帧/连续动作、播放器交互、声音和性能：缺交互证据就写“交互未验收”，缺视觉证据才写“视觉未验收”；一项不替代另一项。审片结果必须对应具体提交或构建、视口、时间点和文件，不能复用旧截图证明新版本。

## 逐项视觉证据链

制作和打磨时，用下表把设计目标连到实际实现与画面证据。记录聚焦于焦点资产、关键识别特征、主体支撑关系和主要环境层；重复资产可按族记录。

| 镜头/资产 | 目标特征或质量卡 | Three.js实现/资产路线 | 当前构建证据（视口、时间、帧/裁切） | 结论与根因 |
|---|---|---|---|---|
| 示例：焦点资产与支撑环境 | 主轮廓、比例和结构关系符合视觉规格；接触/遮挡可读 | 按形体选择的程序网格、模型资产或混合实现 | build-id / 目标分辨率 / 镜头与时间 / detail-crop.png | 通过 / 或记录轮廓、连接或构图根因 |

“已写代码”“模型能加载”“浏览器无报错”“生成参考图很精细”都不能替代当前Three.js构建的目标视口证据。无证据的行保持未通过/未验收，不从总体印象推定通过。

## 核心镜头放行标准

这是扩片的统一阶段门槛；其他参考中的检查方法用于形成证据，不另设较松的放行表。按任务规格选择画风和景别；有选定参考时比较相似景别，无指定参考时对照已记录的视觉质量目标。

| 检查面 | 所需证据与通过条件 |
|---|---|
| 场景构图与环境完整性 | 目标视口缩略灰盒中能辨认主体所在空间、主次关系、深度/尺度线索和视线落点；环境提供与主题或情绪相关的信息。留白与边缘裁切有意图；既不因背景简化而让主体漂浮，也不靠无关道具填满画面。若提供可移动相机，所验收的全部可达视角均处于已构建的环境覆盖内 |
| 参考到代码的视觉对应 | 按视觉规格逐项对照相同景别/画幅的参考和当前Three.js画面；关键轮廓、结构层级、材质响应和动作线索有明确代码实现或记录为有意变化。参考中的识别特征不能只停留在题材命名，也不能由生成图、标题、雾或粒子替代。关键项缺失、主要对象读成通用占位或主体/背景细节等级明显失衡时不放行 |
| 全场景组成逐项完成度 | 用全场景组成台账逐项检查所有可见资产/环境/效果及每类重复群体；每项均达到自身质量卡里规定的轮廓、结构、材料、空间关系和目标像素要求。未完成灰盒、通用占位或没有设计意图的空面不得以“支撑/背景/太小”为由通过；确属风格化简化的元素须在设计规格中明确其形态规则并在整镜中成立 |
| 形体与结构 | 主体轮廓、比例、厚度/连接和中层结构在目标视角成立；必要时以灰模/侧视定位，原尺寸图不靠特效掩盖缺口 |
| 材质与光影 | 最终材质、主光及必要环境反馈达到约定画风；材料区别、体积与空间层次可读，相比质量目标的明显差距已解决 |
| 动作与构图 | 核心事件、重心和需要的接触可见；关键帧前后及连续片段没有严重穿模、结构断开、纹理游动或闪烁，标题不挡主体 |
| 运行与预算 | 同一时刻复取画面稳定；目标分辨率的运行/导出成本已验证且可支撑扩片。实际播放、声音及跨景别检查按交付范围另验 |

为这些检查面记录结论、对应构建/帧/片段及仍失败的问题；全场景组成台账每行记录通过帧或裁切、未通过原因和修复结果。主体单项通过不能替代完整场景门；只生成视频或只通过技术探针也不足以放行成片扩展。原型、技术研究或用户明确限定的阶段交付按其范围报告，不冒称完整视觉成片通过。

## 交互相机验收

仅对规格中包含可交互场景的交付适用。通过用户实际打开的页面完成相机操作，不能用导出截图、静态帧或存在canvas代替：

1. 连续水平旋转一整圈，在至少8个方位观察；检查已声明的俯仰高低端和近远距离端点。
2. 检查地平线/背景连续性、地面/水面边界、物体背面、透明排序、阴影/反射、相机穿模、裁切和界面遮挡。出现未建模黑空、空白背面或状态跳变均不通过。
3. 若影片与自由查看并存，分别验证两种模式；播放/跳时不能覆盖用户相机，返回影片模式能恢复可重复的导演镜头。

合理的俯仰/距离限制可以排除地底、物体内部等非设计方向，但要在规格中说明；不要靠过度限制掩盖本应可达方向的场景缺失。相机范围和场景覆盖方法见[Three.js代码化制作SOP](threejs-code-sop.md#场景构图参考映射与相机包络)。只交付影片或固定机位播放页时无需增加自由环绕，但要明确交付的是固定/导演相机。

## 最小制作记录

按项目现有目录保存即可，不强制新框架：

- 设计与实现来源：参考方法、实际新作、直接/改造复用及许可范围；原创建模任务应有新对象结构规格和生成实现，不拿旧角色换场景作为完成证明。
- 镜头表与关键 cue：接触、落地、入网、反应、结尾等。
- 关键帧：覆盖核心事件之前、发生时、之后；每镜至少有能代表其质量的画面，重点镜头按实际问题扩展。
- 问题记录：时间/区域、现象、确认根因、改动、最新运行证据、结论、未覆盖项。

整体质量的通过条件与当次目标对应；字段存在、脚本PASS或复用资产好看都不能证明从零创作能力。

接触表用于看构图和连续性，原分辨率图用于看面部、线条、穿模与纹理；连续播放用于判断节奏和重量。三者不能相互代替。

## HTML 检查脚本

```sh
node scripts/validate_offline_html.mjs path/to/film.html --require-offline
```

脚本解析最终 HTML 的可执行内联 JS，拒绝未填的 bundle 占位符，并检测脚本语法错误；`--require-offline` 额外拒绝资源标签及 CSS url 中的外部引用。默认只报告依赖。此检查不覆盖 JS import、fetch、Worker、CSS import 等所有资源路径，无法证明离线运行或 WebGL 正常，仍需浏览器离线播放验证。

解析不执行影片逻辑。退出码 0 表示这些静态检查通过；1 表示语法/占位符/离线约束失败；2 表示输入或工具错误。

构建代码应使用回调 replacement 并转义 script 结束标记，避免压缩变量或字符串中的 `$&`、`$'` 等破坏生成的脚本。

## 接触检查脚本

```sh
node scripts/check_contacts.mjs path/to/contacts.json
```

输入为 JSON 数组，每项代表一个真实采样的接触事件：

```json
[
  {
    "id": "strike",
    "time": 5.25,
    "pointA": [0, 2, 0],
    "pointB": [0.12, 2, 0],
    "radiusA": 0.10,
    "radiusB": 0.03,
    "tolerance": 0.01
  }
]
```

时间用秒；点、半径和容差使用相同场景单位。点来自渲染时实际世界变换；容差按模型尺度、镜头和动作确定，不能为了通过检查随意放大。涉及 shader 变形时从等价 CPU 解算或变形后采样取点，未变形网格坐标不能证明接触。

输出 `distance` 与 `surfaceGap = distance - radiusA - radiusB`。`surfaceGap <= tolerance` 仅说明包围球接近/重叠，不能证明真实脚面触球，也不能判断深度穿模；须配合接触前后帧与表面检查。

退出码 0 表示全部粗检通过；1 表示有接触超差；2 表示字段无效。这个脚本适用于有接触事件的动作片；无此类事件不必制造检查数据。

## CUA 和运行证据

交付页面在允许使用的CUA/MCP中检查真实目标视口、连续播放与控件；视频、原尺寸帧和接触表属于作品证据，不冒充CUA验收。遇到锁屏/通道故障时记录具体未覆盖项，不能宣称CUA视觉/交互通过。

使用当前可用工具的文档，不把固定浏览器 API 写死。正常顺序是读状态、操作目标、读最新状态、看目标画面。普通连接故障可选文档支持的路径；若工具明确拒绝目标URL或要求停止，不得换入口绕过限制。用户切换窗口后重新查询目标，不操作无关页面。只保留目标视口，避免系统整屏截图带入桌面和无关应用。自有影片导出帧属于作品审片证据，不能代替播放器交互的实际操作证据。

构建出错、浏览器语法错误、时间不前进、canvas 空白、遮罩拦点击属于不同层次。先看最终 HTML 和运行错误，再沿初始化/事件/时间/渲染调用链定位，避免只凭症状改 CSS。

## 可执行离线影片导出

`render_film.mjs` 仅用于渲染自己有权制作的离线影片源码；不是网站浏览或 CUA 权限回退工具。依赖 Node 22+、本机 Chrome；`--video` 额外需要 ffmpeg/ffprobe。通过 `CHROME` 指定其他平台的可执行文件。

```sh
node scripts/render_film.mjs --html /absolute/film.html --out /absolute/review --times 4,12,20,28
node scripts/render_film.mjs --html /absolute/film.html --out /absolute/export --times 4,12,20,28 --video
```

适用接口及页面约定：

| 接口/条件 | 契约 |
|---|---|
| `window.__ready === true` | 必需资产、字体和渲染准备完成后置true；不是吞掉模块错误后的占位状态 |
| `window.__FILM={duration,fps}` | 时长为秒，两者均为有限正数；样本时间位于0至duration之间 |
| `window.renderAt(seconds)` | 同步、完整地求值并绘制该时刻，包括canvas、DOM标题/字幕与FX；返回Promise会明确失败。异步收敛需另按 [渲染路线](rendering-choices.md) 适配 |
| `body.render-mode`及`?still=1` | 页面进入静帧导出状态：只保留目标画面，暂停独立RAF、CSS墙钟动画/过渡等，所有可见状态由`t`确定。不得依赖某个canvas ID；支持多个canvas及DOM合成 |
| MP4及可选统计 | 当前脚本MP4路径要求同步`window.renderWav(22050)`返回WAV Uint8Array；无声作品可提供等时长静音WAV适配或改用无声导出器，不因此增加可听配乐；可选`window.filmMetrics()`提供项目可解释的统计 |

默认视口1280×720、deviceScaleFactor=1，可传`--width/--height`。页面依据该视口与`render-mode`确定布局；导出器添加该class并兼容隐藏旧`#start`入口，但影片自己的控制层由页面负责清理。字体在READY前准备，导出器也等待当前`document.fonts.ready`；按时间才发起的异步资源加载不符合此同步契约。

脚本检查页面异常、console.error、浏览器错误日志、READY、同步入口和随机访问图像一致性。导出与比较使用同一目标视口PNG，包含canvas及DOM；不依赖canvas.toDataURL。manifest记录源HTML SHA256、样本帧哈希、`determinism.scope="viewport"`、方法和复取样本，MP4模式另含媒体探测信息。

复用输出目录时，开始渲染前撤销旧manifest，只有本轮成功才重新生成；失败目录里的旧帧或视频不能作为本轮完成证据。

样本保留精确时间与独立文件名，毫秒舍入重名时附加序号；以manifest的时间/文件/hash对应关系追溯。MP4按本轮`ceil(duration*fps)`帧编码，旧frames目录里多余的尾帧不参与本轮视频；视频帧网格的时长为该帧数除以fps。

确定性比较要求本次固定浏览器/视口/质量档下，同一时刻复取的PNG SHA256完全相同，没有像素容差。它覆盖指定样本时间的最终可见画面，不证明所有时刻、屏幕外状态或跨设备位级一致。噪声与随机源固定；差异时先查状态、字体和动画时钟，不通过放宽阈值掩盖未解释的变化。

脚本不验证姿态好坏、完整离线依赖、音频听感、实时流畅度或播放器点击行为；这些分别记录。不要把headless逐帧耗时视为实时FPS。

小片逐帧全量导出即可。该脚本没有实现分段恢复；长片需按源码/资产hash、完成标记和帧范围校验实现缓存。不能把源码 hash 字段称为已具备断点续渲染。

支持 `--query 'study=clay'` 等查询参数并将其记录到manifest；诊断状态必须由影片自身实现，导出器不会自动将场景变成灰模。确定性检查在正序采样后先跳到不属于样本集合的时间，再逆序逐项比较；manifest记录`seekProbe`，保证单采样点也实际离开该时刻。灰模应在渲染阶段去掉材质细节与特效，不能只把最终截图去色。

导出器修改后运行真实浏览器回归：`node --test scripts/tests/render_film.test.mjs`。测试验证接口、最终视口确定性和错误门禁；它们不是影片画质或播放器交互验收。
