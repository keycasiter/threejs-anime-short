# 统一验收与交付检查

检查当前交付入口与对应构建，先看目标和实际画面，再查代码说明。技术能力、视觉品质、输入交互、连续动作、声音及性能分别下结论；用户只要计划/机制时仅检查该范围。记录可用项目现有格式，无固定阶段JSON要求。

## 视觉品质

| 检查面 | 具体看什么 | 失败回到哪里 |
|---|---|---|
| 全场构图与空间 | 全貌/缩略图读出焦点、尺度、前中远、负形和关键连接；每个区域有用途与层次 | 相机、空间拓扑、组团/边界与遮挡 |
| 主要可见组成 | 每个主要对象族至少有一个通过精修关卡的代表；主体、支撑、环境及重复群体均达到对应景别；没有未完成代理、空背板或随意填充 | 对应资产族/区域的代表关系与扩展 |
| 主形与中层 | 剪影、比例、体量收放、凹入、开口、厚度、承托和过渡接近目标；灰模侧光、侧背及接口两侧也成立；若基本体仍被当成有机/建筑主体，判失败 | 独立结构控制量、截面/拓扑与连接 |
| 细节分布 | 可见细节有工艺/形成/用途来源、真实尺度、方向与宿主；边界、终止、交汇都完成；没有仅换色/缩放伪装的变体 | 形成字段、原型/锚点、分布和边界封口 |
| 材质与光影 | 材料身份、尺度、反射/透射/粗糙度与接触阴影可读；真实环境/捕获提供所需反射；受光揭示形体，空间仍有明暗层次 | UV/通道、法线、环境源、灯与颜色输出 |
| 动作与反馈 | 关键姿势/事件前中后及连续片段：接触、重心、从属运动与FX有因果，无明显穿插/漂移/闪烁 | 枢轴/曲面、时间/历史、接触与反馈消费者 |

同时看全幅、原尺寸近景、互补方向；动态再连续播放。风格化可以精简表面频率，同时保留目标中的结构、材料差异和空间关系。一个好看的英雄角度或局部不能代替全场检查，数量和诊断分数也不代替审图。

### 资产放行与完整度声明

整场扩展之前，每个主要对象族的代表资产必须同时通过生产流程中的A–E精修检查，并保留目标景别、灰模侧光、近景连接、正式材质、互补侧背和上下文图。全场扩展后再对各区域的主要配角族分别检查；主资产通过不代替背景、环境和支撑物通过。看见代理几何、无意的实心占位、可见断面、悬浮附件、无来源噪声或只在单一方向完成的表面时，本次交付不得标成“最终美术完成”。

将结果明确标成两类状态：

- **结构/功能完成**：空间、模型关系、交互、动画或模块连接成立，但造型/材质仍未达到目标。
- **视觉完成**：上列结构通过，且主要对象族在目标画幅、光照、近景和承诺视角中均达到用户选择的写实或风格化目标。

阶段覆盖完整但仍有可见粗模，应报告阶段版并指出未通过的具体族/视图；不能因为代码与HTML齐全就称最终成品。没有实图或未实际操作的视角标为未验，不可按静态结构推断通过。

每个承诺视图用一句话说明观察任务和实际结论：焦点/连接是否可读，主要可见族是否达到该景别，遮挡/裁切是否有意且仍保留目标关系。每项关系的PASS必须由实际展示其预期线索的样本支持；若视图没有显示连接两侧、承托接触或目标对象的可读尺度，该样本不能支持这项检查，即使几何/坐标测试通过。一个样本可以支持多项检查，但逐项线索都必须在图中清楚；被遮挡或竞争时拆成互补视图。覆盖记录只回答该方向是否检查；诊断特写证明细节存在，合法近景证明用户能读到。界面有标题/说明时按[模型与界面](visual-construction.md#6-近景同时设计模型与界面)查看完整页面的文字/焦点冲突。

对照固定机位、时间/状态、视口、几何/布局、曝光与非测试变量，保留首次完整代表画面和当前画面。因果判断先复取稳定基线，再只改负责当前解释的一层；实际打开对照图，记录可见收益及新增损失。

取证前等待资源、着色器与所选累积状态就绪，以及加载层/过渡真正结束；用可观察状态确认，不以ready字段或一次固定短延时推断。正式图不能残留加载色罩。保持完整页面取证，不通过隐藏产品界面冒充消除了文字冲突。

随实现使用[消费者检查代码](code-guidance.md#5-写完当前关系就读回消费者)：参数看发出的几何/矩阵/通道，动作看指定可见子件与连续片段。普通Mesh矩阵探针不覆盖shader、实例或蒙皮；对应路径另读真实buffer/姿态与画面。时钟推进、uniform变化或两个PNG不同各只证明其观察项，不扩大为全部动作通过。近远/俯仰从真实控制器读边界，普通近景与局部放大用途分别解释。

## 运行健康检查与放行门

此门用于区分“源码能解析”与“最终页面真的工作”。在空间草案阶段先跑一次，最终交付前对最终构建再跑一次；任何代码、依赖或控件修改后，重查受影响路径。冻结评测候选记录失败原样保留，不为让分数好看而修补评测输入。

### 采集首帧与未处理错误

在真实页面的浏览器 DevTools 中清空 Console 后重新加载。随Skill提供的`assets/runtime/runtime-health-probe.mjs`可捕获已运行页面的未处理脚本错误、Promise拒绝、WebGL上下文丢失，并记录成功渲染标记与draw calls；它不隐藏或吞掉错误。

```js
import {createRuntimeHealthProbe} from './assets/runtime/runtime-health-probe.mjs';

const runtimeProbe=createRuntimeHealthProbe({canvas:renderer.domElement});
function renderFrame(){
  renderer.render(scene,camera);
  runtimeProbe.markFrame(renderer); // Only after this frame's render call returns.
}
// Read in DevTools after initial rendering, a stable interval, and core interactions.
console.table(runtimeProbe.snapshot());
```

入口模块未加载时探针代码也无法运行，因此模块加载/import错误、Three.js shader/program诊断与网络失败仍须查看浏览器Console/Network；需要覆盖启动前导入故障时，使用Console本身或在HTML模块入口前加短暂的经典脚本监听器。通过模块入口加载探针后，在DevTools读取`window.__threeRuntimeProbe.snapshot()`。`status: clear`只表示有成功渲染标记且当前没有捕获异常；不证明画面可见或美术质量合格。`drawCalls`也不能证明主体进入视锥，仍须看真实页面截图。

### 执行顺序与停线

1. 从最终交付目录打开精确入口，清空Console后硬刷新；确认Three.js与addons版本一致、所有本地模块加载成功，画布CSS宽高和绘图缓冲宽高均大于0。
2. 等到场景实际绘制，不以页面标题、`DOMContentLoaded`、`ready=true`或单纯存在canvas作为成功。至少一次`renderer.render`成功且`renderer.info.render.calls > 0`；再等完整动画周期，静态作品则观察一段稳定时间。反复出现的错误要按连续帧/时间记录。
3. 检查加载遮罩已真实退出；在目标视口截图并确认应有的主体和环境可见。首帧计数、draw calls只证明渲染调用，不证明重要对象进入画面；空黑画布、纯背景、全被遮罩或主体完全在视锥之外都算失败。
4. 实际操作作品承诺的控制：至少覆盖环绕/俯仰/缩放/复位，或机制状态/时间轴/播放暂停；影片检查最终编码文件。每类控制操作后再次看Console、首帧/持续渲染状态、加载遮罩和主体可见性。
5. 记录构建哈希、视口/DPR、浏览器和WebGL后端、首帧与运行时长、draw calls、console/page/unhandled-rejection/shader/上下文错误、截图哈希、操作复现步骤与结果。错误列表为空才可记录`runtime: clear`；有报错时记`runtime: issue`及首条堆栈，不得只写“页面能打开”。

**硬停线：** 未出现首帧、画布尺寸为零、页面继续显示加载遮罩、目标场景为空/全黑、存在未处理JavaScript异常或Promise拒绝、Three.js shader编译失败、WebGL context丢失，任一项都必须停止扩场/最终交付并回到故障所属模块。一次运行报错不要误归为画质低分；修复后的新运行单独留证，冻结盲测样本仍保持原样。警告不自动等价失败，但每条影响目标浏览器、精确版本或实际画面的警告都要解释。

### 故障归类

| 观察到的现象 | 先检查 | 常见代码根因 | 回到哪层 |
|---|---|---|---|
| 页面能解析但启动空白 | DevTools 首条异常、模块加载顺序、启动遮罩的退出条件 | 未声明常量/材质、import失败、异常发生在首帧前 | 启动入口/模块依赖 |
| 首帧出现后画面停止 | 异常发生时间、RAF/`setAnimationLoop`回调、当前更新对象 | 更新记录与创建记录字段名不一致、状态对象缺失、访问未创建的材质/变换 | 动画更新/状态契约 |
| 交互后出现错误或消失 | 每个控件事件、合法状态范围、变更后的实际对象 | 几何和Mesh混用、错误对象类型、空引用、坐标/数组输入不可迭代 | 控件到真实消费者的接线 |
| 有draw calls但主体不可见 | 目标视角截图、相机近远裁剪/遮挡、对象显隐、材质与灯光 | 渲染调用成功但主体在镜头外、被遮挡、透明度/曝光使其不可读 | 空间/相机或材光，不能判运行健康已通过 |

## 真实运行与相机

交互场景按[相机方法](camera-interaction.md)在最终页面实际拖转一整圈、滚轮缩放和点击复位，检查水平8方位及承诺的俯仰/远近端点。内容覆盖与控件操作分别记录；配置或静态设机位不能证明用户操作成立。记录实际设备、浏览器/后端、目标视口、质量档及一段持续帧时间/资源成本。

## 视口契约与屏幕安全区

在开始调镜头前，固定参考 CSS viewport；用户未指定时使用 1280×720 桌面视口，支持窄屏的页面另测 390×844。记录设备像素比。页面布局完成后，Three.js 相机/renderer、程序化占幅计算、浏览器截图必须共用实际 canvas 矩形；不能用一个宽高比写几何测试，再用另一个页面视口验收。

```js
function readCanvasViewport(renderer) {
  const rect = renderer.domElement.getBoundingClientRect();
  if (!(rect.width > 0 && rect.height > 0)) {
    throw new Error('Three.js canvas has no visible CSS layout rectangle');
  }
  return {
    left: rect.left, top: rect.top,
    width: rect.width, height: rect.height,
    aspect: rect.width / rect.height,
    dpr: window.devicePixelRatio
  };
}

function projectToScreen(camera, worldPoint, viewport) {
  camera.updateWorldMatrix(true, false);
  const p = worldPoint.clone().project(camera);
  return {
    x: viewport.left + (p.x + 1) * viewport.width / 2,
    y: viewport.top + (1 - p.y) * viewport.height / 2,
    inFrustum: p.z >= -1 && p.z <= 1 && Math.abs(p.x) <= 1 && Math.abs(p.y) <= 1
  };
}
```

用真实模型/特征样点而非只用目标中心，测主体边界、入口、支撑/连接和题目要求的细节；相机投影改变时按实际 canvas aspect 更新。将标题、按钮、说明等 DOM 的 `getBoundingClientRect()` 与关键 3D 投影一起检查：重叠只有在明确设计为图文叠层且目标仍可读时才接受。对俯仰滑杆、相机 zoom、预设镜位和交互状态，实际驱动页面控件到最小值、默认值、最大值，再读取当前对象姿态和投影；不要只调用另一个离线函数代替真实控件。任何状态裁边或被 UI 遮住，都回到镜头、目标或安全区布局修正，然后在同一 CSS viewport 复拍。

只保留目标页面视口；CUA/MCP、Playwright或直接CDP各按实际执行范围说明。通道不可用写具体未覆盖项，不以导出帧冒充输入操作。页面/console/shader/资源错误、空canvas和事件遮罩分层排查。

## 可复核证据记录

每份证据都要能回答“检查的是哪个构建、在哪个环境、以什么方式复现、实际看到了什么”。对每个检查点使用稳定ID，并记录：构建/run标识及源码或输出哈希、CSS视口和DPR、浏览器版本与WebGL后端、视向/时间/交互状态的复现步骤、截图或视频片段路径及SHA-256、观察结论与`clear`/`issue`/`unchecked`状态。`issue`是有效的检查结果；它不能被省略来换取“通过”。

用一份需求覆盖表对应简报中的每个必需表现和禁止项，五项画面观察分别写构图、空间、形体/中层、细节/分布、材质/光照，并引用检查点ID。交互逐项记录操作和结果；影片另记录完整播放的最终编码文件及接缝、相机、运动对象、水/粒子等时序检查。没有真实画面或操作证据就标为`unchecked`，不凭代码存在或记录字段齐全推定通过。

在本仓库的冻结评测套件中，`evals/visual-evidence.template.json`给出字段样例，`node evals/validate-visual-evidence.mjs <run-directory>`检查记录、哈希、观察点和视口关联；对整组运行加`--acceptance`可让缺证据的候选以非零状态失败。校验器只检查证据文件和声明的完整度，不解码图像、不证明截图来源、不确认交互真实发生，也不评价品质；仍须由评审实际查看页面/媒体。普通项目可用Markdown保存同等字段，不需要套用评测集专属JSON或伪造任务ID。

## HTML与资源包

```sh
node <skill-root>/scripts/validate_offline_html.mjs <project-root>/index.html --require-offline
```

检查脚本语法、本地资源、静态ESM导入链与简单import map；不承诺离线时去掉`--require-offline`。脚本不执行场景，计算URL/条件加载仍需真实浏览器请求和离线重载验证。返回0为静态检查通过，1为检查失败，2为输入/工具错误。

批量核对随包HTML起点时，先在本机准备与Skill版本一致的Three.js目录，再执行：

```sh
THREE_ROOT=/absolute/path/to/node_modules/three node <skill-root>/scripts/verify-example-suite.mjs
```

批量工具先对`assets/`与`scripts/`下的JavaScript运行`node --check`，再在临时目录复制源码并接入所提供的本地`three@0.187.0`，不联网安装、不改Skill目录；它逐页调用上述离线检查器，证明源码语法和资源闭包而非浏览器运行或画面质量。单项目仍使用第一条命令。

最终包包含HTML/源码、生成参数与seed、必需依赖/许可、运行说明。实际打开该包并走通主要操作，承诺离线时断网重载。生成内联脚本时用回调replacement并转义script结束标记，避免`$&`等被字符串替换解释。

## 接触粗检

有实际接触事件时，可从最终世界变换或等价变形求值导出：

```json
[{"id":"contact-01","time":2.5,"pointA":[0,2,0],"pointB":[0.12,2,0],"radiusA":0.1,"radiusB":0.03,"tolerance":0.01}]
```

```sh
node <skill-root>/scripts/check_contacts.mjs <project-root>/contacts.json
```

秒与场景单位保持一致，容差按尺度与可见误差设计。`surfaceGap=distance-radiusA-radiusB`只判断包围球接近/重叠；不能证明实际面接触或排除深穿插。配合真实表面、足迹和接触前后帧检查；没有接触事件不制造检查数据。

## 视频与交付结论

影片执行[视频导出与后验](video-export.md)，完整播放最终编码文件，查看解码关键帧、文字/细节可读性、压缩伪影、时序与尾帧；有声音再试听同步、层级、失真、底噪和结尾。编码前浏览器图不替代编码后审片。

**最终视觉交付门：** 从交付目录实际打开本轮最终入口/媒体，核对构建标识或哈希、目标视口与所检查状态一致。非影片作品覆盖全貌、合法近景和所有承诺的环绕/交互状态；影片完整播放最终编码文件。每个检查点记录`视向/时间/状态 → 观察到的关系 → 结果 → 截图/片段`，未检查的状态保留为`未检查`。静态代码、单张默认角度、导出 manifest、`rendered:true` 字段或页面成功打开均不能单独作为画面验收；场景视觉未实际检查时，运行产物可交付，视觉验收状态必须明确为未完成。

验证记录写：当前入口/版本、目标状态、实际观察或命令结果、对应图/片段、未解决问题与负责层。修正后用当前构建复核受影响状态。发现缺陷就明确剩余差距，不以“功能完成”包装为最终高品质。交付说明区分已完成的真实检查与未覆盖范围；不把研究、机制小样或计划级遵循测试说成完整作品画质提升。

## 当前资产的缓存与真实取图

测资源稳定性时，先记录当前候选首次进入各实际渲染路径的曲线，再在同一候选上重复相同路径检查平台。新候选会退休旧材质；前一个候选已经切过look，不代表当前候选的主场景/反射捕获、形成开关和输出路径都已预热。保存首次编译的峰值和重复后的基线；几何/相机身份、资源数量和原生创建/释放分别核对。发现增长先定位消费者，不靠调高常数阈值掩盖。

匿名比较若约定只评3D画面，在真实页面收起或隐藏版本文字、工作台等覆盖层后重新取原始视口，保留操作和状态。元素截图仍可能包含叠在其上的DOM；先实际查看产物，再确认协议成立。作品本身需要的标签/界面按对应交付目标保留，不用后期涂抹替代真实运行取图。
