# 从优秀实现提取可迁移方法

按研究目标选择源码追踪、真实运行观察或受控实验。解释原理/流程时，以已有作品、帧、源码和一手制作记录为依据；需要验证机制时做有明确输入、干预与观察的小样。修改现有产品或制作完整新作品取决于用户请求范围。

## 选择证据

按画风、题材、目标景别和平台选择少量可观察实现的案例。电影公开论文、开源制作工程、实时成品和技术demo提供不同证据；不把官方demo、新论文或单张封面当成所有场景的画质标准。

| 证据 | 能支持的判断 | 边界 |
|---|---|---|
| 作者提示词、制作合同、复盘 | 已记录的设计目标、分工、输入和修改机制 | 不等于完整对话、实际工时或每次决策 |
| 固定版本源码 | 入口、生成器、数据流、坐标、消费者、状态边界 | 声明/公式存在不证明已连接或全片生效 |
| 真实源帧、成片及运行状态 | 构图、轮廓、材料/光色、连续动作、播放行为 | 接触表、原尺寸帧、连续观看和声音分别记录范围 |
| 实际构建/日志/媒体信息 | 运行、导出、帧数、时长、确定性与错误 | 不证明审美、表演或独立原创能力 |

先列证据表：确定结论、来源/版本/函数、实际阅读范围、未知项、可迁移范围。完整实现历史不可得时保留未知，不由最终文件推演作者经历。

## 按当前缺口查教程与示例

需要补足实现方法时，从当前可见问题选一条学习路径；不通读全站，也不把示例集合当制作质量标准。下列站点正文用于定位机制，API与行为再核对项目安装包及其官方实现。

| 当前缺口 | 可定位的机制来源 | 回到当前作品必须设计的内容 |
|---|---|---|
| 曲面、管线或型材轮廓 | [样条控制点](https://www.webgl3d.cn/pages/717f0f/)、[截面沿路径扫描](https://www.webgl3d.cn/pages/a06aed/) | 截面/路径/厚度、连续性和端口；映射到[代码SOP](geometry-recipes.md)与适用的[截面模块](profile-geometry.md)，不能把绘线当实体 |
| 表面方向、塑料感与反射不分材质 | [UV](https://www.webgl3d.cn/pages/71e307/)、[PBR](https://www.webgl3d.cn/pages/ca9079/)、[环境反射](https://www.webgl3d.cn/pages/780376/) | [形成规律、尺度与数据通道](surface-detail.md)，以及[实际颜色/光照消费者](rendering-choices.md)；示例默认参数不作为设计值 |
| 指向/选中不符合观看意图 | [Raycaster](https://www.webgl3d.cn/pages/a448b6/)、[场景层级拾取](https://www.webgl3d.cn/pages/dd2774/) | canvas坐标、实际命中对象到语义实体的映射、遮挡/触控与相机写入权；真实操作验证而非仅改相机坐标 |
| 细节增加后卡顿或纹理成本过高 | [Mesh数量](https://www.webgl3d.cn/pages/6f7d51/)、[纹理像素规模](https://www.webgl3d.cn/pages/d5e3f0/) | 当前目标机位的占像素、draw calls/显存/捕获时间；选择复用、实例、LOD或纹理尺寸，保留核心轮廓和材料区别；不统一减细分 |

示例HTML可能通过import map和运行时拼接寻找依赖，沿调用处到实际URL核对。镜像文档、示例与正文可能来自不同Three版本，不能拼装为一套当前工程。

## 每项机制必须解释

围绕“目标效果→设计输入→生成/更新规则→消费者→失效条件→可见证据”追踪。区分相机与物体运动、几何与图案/凹凸、资产制作与运行加载、文档目标与实际采样。确认输入在哪一帧绑定、单位与坐标是否匹配。

程序化工具负责保存、编辑和传播设计信息。曲线、权重、锚点、UV、材质分区与风格预设的价值在于正确的关系，不能仅按参数数目或代码量判断。简单三维代理也可以服务有明确下游绘制的混合方案，需要追踪最终画面贡献。

## 转化为新题材能力

提取适用的结构表示、变形/表面坐标、镜头节拍、材质/缓冲契约和生产依赖。将案例专属的角色、参数、配色、镜头和文件布局留在研究记录。先说明新对象需要什么设计/资产输入，再决定生成器与工具。

跨工具参考沿最终画面贡献核对；本分支仅迁移能转为代码构造、字段和渲染的机制，仍由当前项目生成几何。若作者用粗模出图再做图生视频，记录其二维下游；实时三维目标仍需把形体和材光回写运行资产，不能由漂亮效果图推定可旋转模型已同等精细。方法迁移以输入、操作、产物和接入点说明，供应商/耗时/固定轮数留在案例边界。

研究交付是原理、机制和路线，写文档不等于模型训练。已理解、已复现、已控制、已迁移按下文证据等级分开记；复制旧资产后整合不能证明从零造型。进入制作后按 [生产流程](production-workflow.md) 推进，视觉门槛统一见 [验收](validation.md)。

## 逐帧研究的适用范围

用户明确要求逐帧拆解或把参考片作为质量基准时，使用以下方法；普通制作不默认导出参考全片。

## 先定义研究范围和证据

先沿用 [任务边界](../SKILL.md)。研究阶段只使用已有影片/帧和源码；下面的新增导出、运行与干预仅在明确验证授权或制作范围内执行。固定源码版本、发行产物、片段时间窗、fps、分辨率和内部采样倍率。需要且已获准时连续导出所选片段，保留真实帧号与状态；接触表用于通读，目标景别的关键帧按原尺寸看。区分“连续帧已导出”“接触表已审读”“原尺寸已查看”和“音轨已审听”，报告实际范围。

源码版与正式产物可能不同。增加诊断引用、替换依赖解析或改动导出配置后，选相同时刻与发行产物核对；不能只确认入口成功。预渲染视频有压缩和采样差异，比较时区分结构一致与像素相等。

## 一帧记录什么

| 维度 | 屏幕事实 | 需要追踪的数据 |
|---|---|---|
| 叙事 | 当前主要信息、焦点、主次动作 | shot、cue、局部时间、阶段 |
| 镜头与空间 | 占幅、轮廓、遮挡、尺度参照、层次 | position、target、FOV、roll、锚点投影 |
| 形体与表演 | 截面/关节变化、速度、支撑、延迟、收势 | rest mesh、pose、骨架/变形、实际支撑锚点 |
| 材质与光色 | 几何/图案/凹凸分工、受光区域、可见细节 | rest/UV/world 坐标、ID、key/sun、像素尺度、pass |
| 交互与反馈 | 接触、喷发/尘雪起点、附着和衰减 | 变形后表面、环境高度、FX时钟、出生位置/速度 |
| 声画与稳定 | 强调时刻、保持/更新、闪烁、随机seek | audio cue、各层时钟、seed、hash与异常日志 |

逐帧文字不必重复同一模块说明。以帧状态保留连续数据，以阶段表解释变化，以源码追踪解释成因。自动分段注释不等于每一帧均经过原尺寸人工审读。

## 容易学错的机制

**动作和镜头分开求证。** 主体在屏幕上的变化同时受世界轨迹、机位、目标点和FOV影响；不要将占幅变化全归因于模型移动。分析前后帧时一起记录它们。连续shot也可能切换LOOK或姿态配置，需检查边界。

**检查实际采样，不抄节奏口号。** 沿每个消费者核对角色、主体、相机、海面、贴身效果和粒子的时间变量；文档所说“一拍二/三”不保证所有对象相同。把事件触发时间、量化后的求值时间、首个可见像素和峰值时刻区分开，命名为peak的cue不一定是某个anchor的坐标极值。

**区分结构和表面。** 截面、连接和真实雕刻决定体积；albedo区分材料；bump改变受光；墨线根据身份/法线/深度显示边界。沿参数追到生成器确认消费，例如名为bevel的参数可能没有生成倒角。优先检查这种断链，再堆装饰。

**纹样附着与环境场不同。** 固定在衣物/皮肤上的纹样通常应随rest/UV变形；世界坐标适合空间雾、风雪、投射等用途。移动时材质穿过噪声场的风险要用运动帧求证。细节密度需适应目标像素尺度，避免亚像素图案跳动。

**环境反馈从交互数据派生。** 由变形后表面/接触锚点确定起点和方向；例如身体与水面的实际交界可驱动水花，而不是另猜一个固定喷发中心。大块体积、贴面薄层、碎滴、雾和表面痕迹可采用不同表示，再统一风格与时钟。

## 做能判因果的干预

以下只在用户明确授权机制验证或进入制作后执行。研究阶段记录可证伪的假设与既有证据，不启动新实验或试渲染。

先写一个明确假设：哪段、哪个区域、什么症状、疑似机制、改变后预计出现什么差异。根据源码选择最少的关闭项或调试输出，固定时间、相机、种子、视口与其余输入，取得前后画面。保留干预范围与残留效果，例如半径归零未必关闭整个绘画pass；同时关闭一组水效只能证明整组贡献，不能分配到单项。

像素差、位移和白色面积可定位复看帧，不能替代审图，也不能给模块排普遍“重要性”。大差异可能来自正常运镜或抽帧，小差异可能发生在关键眼睛/接触区域。对目标区域和相邻动作共同判断。两次同类微调仍失败时，重查表示、空间或时间关系。

这属于验证机制的定向实验；不以大量随机参数组合代替原因分析。原项目暴露的开关或最小诊断hook通常足够，无需先重写场景。

## 用能力证据决定是否掌握

| 状态 | 必须提供的证明 |
|---|---|
| 已理解 | 画面事实能对应输入→生成器→消费者→失效条件 |
| 已复现 | 固定版本的运行帧、必要的模块/错误检查、随机seek与发行结果核对 |
| 已能控制 | 预期的机制修改产生对应的局部可见变化 |
| 已迁移 | 为新对象独立完成对应设计与生成/更新实现，在目标景别达标；记录方法来源和实际新增能力，直接使用旧角色不证明新造型能力 |

前三种不自动推出第四种；环境/巨物镜头也不证明真人脸、衣物或手部表演。Skill保存决策依据与接口，项目保存帧、参数与审片记录，写文档不等于模型训练或质量提升已经发生。

复刻参考流程时，区分作者复盘、源码可确认、实际运行和未知历史；浅克隆、缺失原始参考帧或前作时，不补写完整制作经过。借鉴已核对的工具结构和协议，为新题材实现；默认不带入参考角色或专用实现，是否复用源码遵循主文件的授权边界。具体核心镜头制作顺序见 `production-workflow.md`。

## 已核对的实现线索

[Saltline固定源码](https://github.com/realcodebear/saltline-fable-5.2/blob/09c51774cd77aad750bd2d6c42af2b1020cb668d/index.html)可研究工厂、动静分离、程序表面与世界字段消费者；[Claude of Duty上游建筑](https://github.com/mshumer/Claude-of-Duty/blob/main/src/world/buildings.js)与[构造kit](https://github.com/mshumer/Claude-of-Duty/blob/main/src/world/kit.js)可研究真实洞口、壁厚和开间语法。上游与线上部署是否一致分别核对，不由最终作品推断作者提示词、一次生成成功率或行业排名。迁移机制，具体题材、布局和参数重新设计；保留实际复用代码的许可。
