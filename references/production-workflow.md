# 从需求到最终作品的生产流程

本页是主链路的详细执行说明。技术做法进入各自参考，放行标准统一由[验收](validation.md)定义；项目只保留一份制作规格和一条主时间线。

## 制作记录与依赖

在项目现有目录保存一份可更新的制作规格。篇幅随作品规模缩放，至少覆盖：

| 区块 | 内容 |
|---|---|
| 目标与依据 | 观众、用途、情绪/信息、事实与风格参考、未知项、来源/许可 |
| 画面与资产 | 视觉目标板、画幅/景别、焦点、形体/材料/空间关系、设计取舍、资产路线与像素细节 |
| 空间与时间 | 单位/轴向/原点、相机模式及包络、镜头/cue、主体/接触锚点、字幕安全区 |
| 运行与交付 | Three.js与依赖版本、渲染入口、时钟、声音状态、HTML/源码/视频、目标设备与预算 |
| 完成依据 | 质量卡对应的当前构建画面、连续动作、相机操作、资源/媒体检查与未覆盖状态 |

## 生产阶段与放行

### 0. 方向提案

开放式需求先提取已确定项和真正开放的设计变量，提出至少5个有实质差异的方向。用生成图做清楚分格的方向板，每项配画面描述、推荐理由、Three.js实现抓手、事实/风格依据和取舍；工具不可用时说明形式限制，给可比较的文字/构图板。请用户选择或混合方向。用户已明确方向或要求直接执行时，记录选定项或合理假设后推进。

方向图只用于比较设计，不证明真实结构与尺寸。选定后才进入详细资产设计；不要把多个候选全部制作成场景。

### 1. 制作规格与视觉基准

先写观众将看到什么、看清什么、发生什么变化，再定时长、画幅、输出与相机模式。短单镜可默认约5–8秒、16:9、24fps、自包含HTML；教学/叙事按事件需要定长。

把质量目标落实到实际视觉目标板：用户选定图、可靠对象/成片图、设计生图或有表达力的结构/色彩稿。全貌规定构图、体积、空间层次和光区；局部规定决定品质的结构、边界、材料响应。没有用户参考时自行建立并选择，不重复索取已确定方向。生成图是设计提案，真实尺寸/连接/物种等事实另行核对。

在规格里分别写“要保留的视觉关系、允许有意改变的设计、事实未知项”。用局部差异解释精细度：例如连续体积与薄片、真实连接与邻近摆放、层次受光与统一底色、材料反射带与高光白块；不把面数和数量作为品质目标。当前代码第一帧可以用于排错，不能自动成为质量基准。

**产物：**制作规格、全貌/关键局部的视觉目标板、来源/设定与取舍。缺少视觉依据时标记“视觉基准待校准”，技术探索可继续，但不宣布参考级或高品质已验证。

### 2. 场景、资产设计与方案选择

先从目标板读出设计关系，再选实现。按[资产设计](asset-craft.md)组织：整体比例/重心/负形 → 体积和中层结构 → 连接与边界 → 材料/光影 → 运动及环境关系。全场景规划焦点、支撑、前中远景、尺度、密度与安静区域；每个主要组成都有自身目标景别与完成标准。

对尚未确定且会改变品质上限的选择，做少量有针对性的方案比较，例如整体体量与深度组织、关键资产的构造方式、光区/材料分配或代码/模型路线。用草图、灰盒、多视图或局部样件使差异可见，说明为何所选方案更接近目标；方向已经确定时，这属于内部设计，不重新让用户选题。已被用户或可靠设计锁定的决定直接继承。

建立“目标图可见特征 → 选定设计 → Geometry/Material/Shader/布局或资产 → 对应视角”的映射。多视角图核对比例、数量和连接；视图漂移与未见背面标为假设。代理布局真实取帧后，复杂资产先验证最难局部，再扩展正式资产；预算不足时减少次要资产或镜头。

把第一项实施任务限定为完整代理场景取帧：

1. 只写最小渲染入口、目标相机、稳定坐标和全场景代理体；代理表达主要体积、支撑、前中远景与建筑边界，此时不写正式细节生成器或复杂材质。
2. 实际运行并捕获目标视口；查看导演关键机位及最易暴露问题的侧背/包络视角，修占幅、遮挡、地平线和安全区。把渲染图、当时源码版本和审图结论保存后，再开始正式资产。
3. 自由相机同时核对水平/俯仰/距离与合法视锥覆盖，分离影片和自由相机写入权；布局可达范围决定后续几何/环境与光影需要覆盖什么。

**产物：**选定方案、特征/资产台账、实际代理场景渲染与结论、空间接口和相机包络。只有文字草图、未运行的代码或后来细化的最终图，不算本阶段已经执行；工具故障保留未完成状态及实际原因。

### 3. 代表画面实现与差异校准

固定视觉目标、机位/景别、种子与分辨率。把下一项任务限定为尚未证明的关键形体/连接或材料难点：在代理场景中替换这一局部，实际取近景/侧背图检验；可用同工程的隔离视图，不另建无关试片。简单或已有同表示/景别证据的部位可引用相应依据。难点的实现有效后，再扩成完整代表镜头，按主形/体积 → 连接/中层 → 材料/灯光 → 像素细节推进。代码方法按[实现SOP](threejs-code-sop.md)对应章节使用。

灰模检查体积、厚度、连接和支撑；最终材料检查反射/明暗边界、材料差异、空间层次和焦点。含动作的代表镜头在本阶段实现必要的关键姿态、最小绝对时间求值和因果反馈短片段，用前中后帧及短连续片段验证其运动品质；静态任务不制造额外动作。目标板与真实Three.js画面按同画幅/相近景别并排，主要局部以原尺寸看。先只看画面判断差距，再读实现说明，避免被代码数量和制作者描述引导。

分别记录：内容是否齐全；目标关系是否可读；执行品质相对基准还差什么。写明最影响效果的实际差距及其责任层，修后在相同条件复看；有意偏离必须来自设计理由，不能事后降低目标。具备条件且获授权时用独立审阅；没有独立审阅时如实记录制作者自评范围。

**产物：**当前构建原尺寸彩图/必要灰模与局部、目标对照和差距结论；动作任务另含代表片段前中后帧、短连续片段与最小时间接口。按[核心镜头标准](validation.md#核心镜头放行标准)判断是否扩展。特征“都存在”但体积、材料或场景层次仍显著落后基准时，返回对应设计/生成层。

### 4. 动画、摄影与交互整合

在代表镜头与必要最小动作片段成立后，扩展到完整时长、其他镜头、次级动作、交互与声音整合。

镜头表记录`id / t0 / t1 / 必须看清的事件 / 主体锚点 / 相机 / 动作 / 环境反馈 / 声音 / 字幕区`。先设计关键状态和方向、速度、停顿、支撑/重心，再连接曲线；运动过程中的临时构图也需要成立。

实时播放、seek和导出共用完整的`stateAt(t)`/`renderAt(t)`。每次写完整基准状态后求姿态、相机、显隐、材质、FX和文字；不依赖上一帧。需要抽帧画风时量化指定层的求值时间，事件cue仍按精确主时间。累计物理/粒子使用重放、快照或缓存，详见[状态与规模](motion-and-scale.md)。

动作、接触与FX共用最终变形后的世界锚点。地表/水面、风、密度与反馈使用共享空间场；环境响应说明来源、方向、尺度、寿命和衰减。先完成主动作与因果反馈，再做次级动作和表面动态。声音使用同一cue表和独立轨道；有音频时以音频时钟驱动画面，play/seek/resume更新offset。

**产物：**关键事件前中后帧、连续片段、乱序seek及模式切换结果。检查接触、遮挡、运动稳定性、纹样附着与相机归属后，再导出最终文件。

### 5. 最终构建、运行与交付

冻结源码/资产版本、视口、fps、seed、质量档和入口。只从该版本构建最终HTML/媒体；失败目录的旧成片不作为本轮结果。同步与渐进渲染分别采用对应的捕获协议，见[渲染选择](rendering-choices.md)与[导出契约](validation.md#可执行离线影片导出)。

在用户实际打开的文件中检查开场、关键事件、结尾、连续播放与控件。自由查看实际完成一圈、至少8方位及俯仰/远近端点；双模式分别操作。按目标设备检查流畅度、资源与错误；视频核对帧数/时长/分辨率/fps/音轨，有声音审听最终混音。工具故障时具体标记未验收能力。

**交付包：**最终可打开文件、源码入口与必需资产、依赖版本及可重建的构建/运行命令、资源来源/许可、当前版本的视觉/交互/声音/性能证据和边界。用户要求成品时，不把内部原型当成最终交付。

## 返工与阶段衔接

每个问题记录：`镜头/时间/区域 → 可见症状 → 已确认根因 → 负责的生成器/资产/相机/材质层 → 改动 → 新证据`。局部改动先检查受影响帧与连续片段；共享规则改变、阶段合并和最终交付扩大到全片。连续两轮无对应可见改善时，重查上游设计与表示，停止同层调参。

## 按职责组织制作与集成

一个执行者也可顺序承担以下职责；使用多Agent须符合当前授权和工具规则。每个任务提供目标、上游就绪状态、允许编辑文件、接口、证据和缺口，明确其他执行者也在工作，保留他人改动。

| 职责 | 唯一维护的内容 | 交接内容 |
|---|---|---|
| 导演/集成 | 制作规格、镜头/cue、全局空间/渲染契约、相机与共享入口 | 当前视觉规则、接口及最终组合画面 |
| 主体/角色 | 自有模型、材料、姿态/变形 | 造型、可见性、最终变形后表面/锚点 |
| 环境/道具 | 自有场景、空间布局与支撑面 | 尺度、接触定义、实例和锚点 |
| FX | cue与运动/接触派生的效果 | 来源/寿命、数据消费者、预算 |
| 声音 | 旁白、音乐、音效及混音 | cue、稳定媒体版本、试听结果 |

共享文件与每镜相机/LOOK各有一个写入者。先稳定上游接口，再安排独立消费者；强耦合形体与绑定、摄影与构图统一协调。模块成功加载后仍须审查组合镜头。
