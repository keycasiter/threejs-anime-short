# 从需求到最终作品的生产流程

本页是主链路的详细执行说明。技术做法进入各自参考，放行标准统一由[验收](validation.md)定义；项目只保留一份制作规格和一条主时间线。

## 制作记录与依赖

在项目现有目录保存一份可更新的制作规格。篇幅随作品规模缩放，至少覆盖：

| 区块 | 内容 |
|---|---|
| 目标与依据 | 观众、用途、情绪/信息、事实与风格参考、未知项、来源/许可 |
| 画面与资产 | 画幅/景别、焦点、识别特征、构图/光色、全场景组成、资产路线、目标像素细节 |
| 空间与时间 | 单位/轴向/原点、相机模式及包络、镜头/cue、主体/接触锚点、字幕安全区 |
| 运行与交付 | Three.js与依赖版本、渲染入口、时钟、声音状态、HTML/源码/视频、目标设备与预算 |
| 完成依据 | 质量卡对应的当前构建画面、连续动作、相机操作、资源/媒体检查与未覆盖状态 |

## 生产阶段与放行

### 0. 方向提案

开放式需求先提取已确定项和真正开放的设计变量，提出至少5个有实质差异的方向。用生成图做清楚分格的方向板，每项配画面描述、推荐理由、Three.js实现抓手、事实/风格依据和取舍；工具不可用时说明形式限制，给可比较的文字/构图板。请用户选择或混合方向。用户已明确方向或要求直接执行时，记录选定项或合理假设后推进。

方向图只用于比较设计，不证明真实结构与尺寸。选定后才进入详细资产设计；不要把多个候选全部制作成场景。

### 1. 制作规格与质量目标

先写观众将看到什么、看清什么、发生什么变化，再记录时长、画幅、输出形式与相机模式。短单镜可默认约5–8秒、16:9、24fps、自包含HTML；教学或叙事按事件需要定时长，不填充无因空镜。

把质量形容词展开为可观察特征：轮廓/比例、体积与厚度、连接/负形、中层结构、材料差异、光影与环境关系、运动因果。选择2–4个决定身份或表达的重点，其他可见组成各有自己的细节等级。事实参考约束位置/连接/尺寸，风格参考约束画面表达，生成图不覆盖可靠事实。

**产物：**制作规格、质量卡与参考列表。目标无法从画面或动作中判断时，先重写目标。

### 2. 全场景与资产方案

先做目标画幅的构图稿和完整灰盒，确认焦点、前中远景、尺度参照、负形、光区和字幕区。真实地点或有明确结构的对象同时核对俯视/正交位置与观看方向的遮挡；不能从单张透视图推断全部背面。

按[资产设计](asset-craft.md)建立“可见特征→表示→实现→验收视角”映射。复杂焦点资产先验证最难表达的形体，选择程序网格、DCC/许可资产或混合路线。需要多角度/近景时补对应视图和部件细节图，核对比例与连接一致性；未见结构标为设计设定。按[代码方法](threejs-code-sop.md)落实生成器、截面/布局、材料、锚点、边界和资源预算。

场景组成台账覆盖焦点、支撑、环境、群体与FX。逐类规定主形、中层、材料、空间关系与目标像素；重复群体定义形态族、变化范围和固定种子。环境应有组织的结构与深度，留白有意图。

相机设计与几何同时进行：导演镜头记录起中止；自由浏览记录环绕中心、水平/俯仰/距离范围，并规划所有可达方向的内容和光影。影片与自由查看的相机更新权分离。完整环绕的实现与验收见[相机验收](validation.md#交互相机验收)。

**产物：**全场景灰盒、资产/特征台账、表示选择、空间接口、相机包络。构图和关键形体仍未定时继续本阶段。

### 3. 代表画面与Lookdev

选最能暴露弱点的镜头及必要侧背视角，固定相机、种子、分辨率与参考景别。实现顺序是：主轮廓/体积 → 结构连接/中层 → 材质/灯光 → 目标像素细节。主体及其主要环境一起成立，不能只审主体单体。

先用灰模和剪影确认形体、厚度与支撑，再用最终材料和光照检查体积、材料差异、空间层次与焦点。图像参考与当前Three.js画面同景别并排；局部裁切检查近景关键结构。代码/网格数量、模型可加载、后期丰富均不代表这些目标达成。

**产物：**当前构建的原尺寸静帧、必要灰模与局部、特征差异记录。满足[核心镜头放行标准](validation.md#核心镜头放行标准)才扩展到动画和其他镜头。大形或结构反复失败时换表示/资产路线。

### 4. 动画、摄影与交互整合

镜头表记录`id / t0 / t1 / 必须看清的事件 / 主体锚点 / 相机 / 动作 / 环境反馈 / 声音 / 字幕区`。先设计关键状态和方向、速度、停顿、支撑/重心，再连接曲线；运动过程中的临时构图也需要成立。

实时播放、seek和导出共用完整的`stateAt(t)`/`renderAt(t)`。每次写完整基准状态后求姿态、相机、显隐、材质、FX和文字；不依赖上一帧。需要抽帧画风时量化指定层的求值时间，事件cue仍按精确主时间。累计物理/粒子使用重放、快照或缓存，详见[状态与规模](motion-and-scale.md)。

动作、接触与FX共用最终变形后的世界锚点。地表/水面、风、密度与反馈使用共享空间场；环境响应说明来源、方向、尺度、寿命和衰减。先完成主动作与因果反馈，再做次级动作和表面动态。声音使用同一cue表和独立轨道；有音频时以音频时钟驱动画面，play/seek/resume更新offset。

**产物：**关键事件前中后帧、连续片段、乱序seek及模式切换结果。检查接触、遮挡、运动稳定性、纹样附着与相机归属后，再导出最终文件。

### 5. 最终构建、运行与交付

冻结源码/资产版本、视口、fps、seed、质量档和入口。只从该版本构建最终HTML/媒体；失败目录的旧成片不作为本轮结果。同步与渐进渲染分别采用对应的捕获协议，见[渲染选择](rendering-choices.md)与[导出契约](validation.md#可执行离线影片导出)。

在用户实际打开的文件中检查开场、关键事件、结尾、连续播放与控件。自由查看实际完成一圈、至少8方位及俯仰/远近端点；双模式分别操作。按目标设备检查流畅度、资源与错误；视频核对帧数/时长/分辨率/fps/音轨，有声音审听最终混音。工具故障时具体标记未验收能力。

**交付包：**最终可打开文件、源码入口与必需资产、依赖版本及可重建的构建/运行命令、资源来源/许可、当前版本的视觉/交互/声音/性能证据和边界。用户要求成品时，不把内部原型当成最终交付。

## 返工与阶段衔接

每个问题记录：`镜头/时间/区域 → 可见症状 → 已确认根因 → 负责的生成器/资产/相机/材质层 → 改动 → 新证据`。局部改动先检查受影响帧与连续片段；共享规则改变、阶段合并和最终交付扩大到全片。连续两轮无对应可见改善时，重查上游设计与表示，停止同层调参。

## 按职责组织制作与集成

一个执行者也可顺序承担以下职责；使用多Agent须符合当前授权和工具规则。每个任务提供目标、上游就绪状态、允许编辑文件、接口、证据和缺口，明确其他执行者也在工作，保留他人改动。

| 职责 | 唯一维护的内容 | 交接内容 |
|---|---|---|
| 导演/集成 | 制作规格、镜头/cue、全局空间/渲染契约、相机与共享入口 | 当前视觉规则、接口及最终组合画面 |
| 主体/角色 | 自有模型、材料、姿态/变形 | 造型、可见性、最终变形后表面/锚点 |
| 环境/道具 | 自有场景、空间布局与支撑面 | 尺度、接触定义、实例和锚点 |
| FX | cue与运动/接触派生的效果 | 来源/寿命、数据消费者、预算 |
| 声音 | 旁白、音乐、音效及混音 | cue、稳定媒体版本、试听结果 |

共享文件与每镜相机/LOOK各有一个写入者。先稳定上游接口，再安排独立消费者；强耦合形体与绑定、摄影与构图统一协调。模块成功加载后仍须审查组合镜头。
