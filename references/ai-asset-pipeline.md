# AI 图像、3D 与声音资产管线

本参考把生成服务接入 Three.js 短片制作。它们是可替换的生产工具，不是画质保证，也不取代镜头设计、模型修整、动画、灯光和试听。先按[资产设计](asset-craft.md)确定表示与资产路线，再用[Three.js代码方法](threejs-code-sop.md)构建场景对象和效果。图像生成结果默认是设计参考，不进入最终画面；需把可见特征转成 Three.js 几何、程序化材质、shader和动画。Meshy等外部3D网格路线是可选资产来源，须符合用户的资产约束，集成后仍要由Three.js渲染并通过目标镜头验收。只有用户明确要求图片作为最终资产时才改变图像素材默认边界。API、模型名、额度与保留策略会变化；每次实施前核对官方文档与账户权限。本页只提供通用接入流程；具体API/模型可用性、价格及额度需在实施时重新核对，不以历史研究日期背书。

## 先确认资产生产链能实际完成

按当前目标景别和最难特征选路线，再检查现有工具/凭据/成本；记录实际可运行的调用方式与可产出的文件。程序生成、DCC、许可资产、生成网格可混合使用。把“精修”落实为当前资产需要的工作，不把软件名或生成成功作为完成依据：

| 生产环节 | 实际动作与交接 |
|---|---|
| 设计输入 | 选定全貌、相关多视角/局部、尺寸或设定；统一身份、主要比例、材料区域和所需姿态 |
| 造型候选 | 规则部件由参数生成；复杂独特体积可用DCC或3D候选。先拿到一个完整代表资产及其构造来源，不直接批量生产 |
| 修整与材质 | 修轮廓/截面/交界、洞壁/厚度、法线和必要拓扑；按需要处理UV、材料槽/贴图语义、骨骼/权重与动作。静态资产无需绑定 |
| 规范导出 | 统一单位/轴向/支点、节点与材料角色；用glTF/GLB等实际可加载格式，随附必要纹理/动作、来源和可重建脚本或输入记录 |
| Three.js代表场景 | 真正加载或生成，与相邻体块/承载面组合；用当前镜头和材光看轮廓、结构、反射、姿态及侧背面；选定后扩资产族 |

若Three.js还要读取DCC生成的语义属性来布置、着色或生成效果，为它们写明稳定名称、含义/值域、数据类型、坐标空间/单位及实际消费者。导出后用目标文件和当前Three.js加载器检查字段名与类型，并在已知位置抽样，确认坐标变换后仍表示原来的区域或数值；不要仅凭DCC导出成功推断属性已保留。若格式或导出器未传递所需字段，用与资产ID和坐标变换绑定的JSON侧车数据、顶点色或数据贴图承载，再在相同消费者中复验。具体属性支持依导出器与版本而异；使用Houdini时，核对当前版本的[glTF导入/导出支持表](https://www.sidefx.com/docs/houdini/io/gltf.html)，不要把某一导出节点的能力推定为格式通用能力。

先读已有文件、工具帮助或服务状态确认可用性；仅有启动器/连接器名称时继续核对实际程序或任务终态。路线不能完成时，选择当前可表达目标的替代方式，并记录未解决的质量风险。预览图只辅助选择；三维网格、材质和动作进入运行链后才支持实时效果判断。

## 工具职责

| 阶段 | 可选工具 | 适合产出 | 不应假定 |
|---|---|---|---|
| 视觉设计 | 可用的图像生成/编辑工具 | 角色/场景概念、造型探索、定向编辑、贴图草稿 | 多视图完全一致、比例精确、可直接用于三维贴图或模型 |
| 网格候选 | Meshy | 图像/文字转3D、纹理、重拓扑、标准人形自动绑定与动作候选 | 拓扑可变形、面部可信、UV/材质完备、骨骼和动作适合镜头 |
| 声音素材 | ElevenLabs | 旁白、角色台词、环境/事件音效 | 发音、节奏、情绪、混音层级无需审听 |

若镜头需要稳定角色身份、复杂手部接触、精细表演或特定风格，优先把生成结果当作起稿；用 DCC/程序化建模、手工修模、已有许可资产或人工表演补齐关键质量。不要为了使用服务而强行替换已可靠的管线。

## 图像生成与编辑

先确认当前环境提供的图像生成/编辑能力，按工具文档选择调用路径、模型ID、尺寸、质量和背景，不沿用未核验的型号或参数。需要OpenAI API时查下方官方入口；其他工具同样记录来源与输入。

推荐把图像用于：

- 风格帧、角色正侧背设定和环境构图探索；生成多视图时，逐张核对身份特征和比例是否一致。
- 定向修改已选设计，锁定轮廓、服装分区、主色和光照，再进入 3D 阶段。
- 制作可平铺/可投影纹理的概念草稿，用来提取图案、尺度和色彩规律；默认不可直接把该生成图作为`TextureLoader`贴图。根据草稿用代码CanvasTexture、shader或人工绘制的新纹理重新实现，并检查接缝、投影、色彩空间与镜头尺度。用户明确授权使用图片纹理时才例外。

把最终选中的参考图、提示词、模型 ID、尺寸/质量、编辑输入和生成日期保存在项目设计记录中，并注明“仅参考”。再建立映射表，把每项可见特征映射到Three.js代码对象/参数/材质/动画；先渲染一个核心资产验证该映射，再决定补充视觉探索。图像细节不会自动变成真实几何、正确法线或可动画结构。

## Meshy 生成、处理与接入

Meshy 官方 API 提供 Image-to-3D、Text-to-3D，以及 Rigging 和 Animation 等任务。创建任务后会返回任务 ID，服务在后台处理；客户端可按官方 `Retry-After` 轮询、使用流式状态接口或配置 webhook。终态包括成功/失败；成功后下载模型结果，注意服务端资产存在保留期限。

建议流程：

1. 为目标资产准备清晰、主体完整、遮挡较少的输入图；人物尽量提供统一比例与可识别肢体结构的参考。仅当轮廓与造型方向已经确定，再启动高成本生成。
2. 请求导出 GLB，并只选择当前确实需要的几何质量、贴图/PBR、重拓扑或姿势选项。保留任务 ID、输入图、提示词、模型/参数、任务状态和输出文件 hash。
3. 任务完成后及时下载并本地归档；不要把临时签名下载 URL 当作长期资产地址。失败时读取任务错误并修正输入，不无限自动重试。
4. 在 Three.js 中实际加载 GLB，核对包围盒/单位、朝向、原点、法线、UV、纹理槽、透明材质、面数、节点命名、动画片段和运行成本。检查远/中/近景以及关键动作姿势。
5. 人物自动绑定只适用于结构清楚的标准人形候选。重点检查肩/髋/肘/膝体积、脚滑、接触点、手指、面部和衣物穿插。镜头不通过时，修模/重绑/手动画或更换资产。

Meshy 任务和导出字段会随 API 版本变化；不要复制旧模型 ID 或凭历史记录假设参数仍可用。网格“可加载”只代表格式接通，不代表造型、拓扑或表演达到交付标准。

## ElevenLabs 旁白与音效

ElevenLabs 可用同步 TTS endpoint 生成短音频，也可使用 Flows 的异步 TTS 生命周期；Sound Generation endpoint 可按文字提示生成音效，参数包括时长、是否循环、输出格式等。具体模型与参数以当前 API 文档为准。

制作时先锁定台词、角色声线和 cue，再生成试听版本。记录 voice ID、model ID、文本、发音字典/语音设置、输出格式、任务 ID/请求 ID 与文件 hash；每条台词采用稳定文件名和版本，避免每次导出时重新合成造成表演漂移。把生成的音频视作普通离线素材，按主时间轴剪辑、淡入淡出、混音并与镜头动作同步；不要在 `renderAt(t)` 或逐帧导出回调里实时请求 TTS。

人工试听中文专名、人名、停顿、情绪、呼吸、爆音/削波和音量连续性；音效还要检查瞬态、尾音、循环接缝及与对白的遮蔽。试听不过就调整文本标点/发音提示/设置或重生成，并复听最终混音。确认声线使用权限、项目用途和音乐/音效授权；涉及模仿真实人物声音时，先核验适用的授权与同意要求。

## 通用集成与验收

- 将服务调用封装在项目资产准备阶段，Three.js 运行时只加载已审核的本地/稳定托管资产；播放与导出不依赖在线生成 API。
- API key 放在本机密钥管理或环境变量，禁止写入源码、HTML、提交记录、浏览器 bundle 和可交付项目。前端不得直接暴露服务密钥。
- 为生成任务设定预算、次数、超时、有限重试和失败回退。异步任务状态清楚区分待处理、生成中、成功、失败；重复执行应可识别已有任务/输出，避免无意重复计费。
- 记录来源、模型/版本、关键参数、授权状态和输出校验值，使资产可追溯并能替换供应商。无 API 凭据、网络受限或服务不可用时，走人工生成、合法现成素材或程序化资产路径。
- 视觉验收以实际成片视口为准：图看设计一致性，网格看几何与动作，运行镜头看光影/遮挡/稳定性；声音以最终播放和混音试听为准。生成接口返回成功、HTTP 200 或 GLB 可解析都不等于验收通过。

## 按未知依赖选择最小接入验证

只在已授权制作或服务验证时执行；研究服务能力不自动授权调用、计费或试渲染。先列当前不确定的环节：凭证/API、输出格式、结构质量、变形或声音。优先用同一镜头所需资产和已有结果检查；最小验证可以是一个文件加载、一个姿势或一条发音，不固定角色、片长、GLB或旁白组合。

| 未知项 | 最少证据与判断 |
|---|---|
| 服务和下载是否可用 | 任务终态、参数、输出文件/hash；读取错误，不重复盲发任务 |
| 网格是否满足镜头 | 目标轮廓/结构、材质及需要的姿势；静态失败查造型，运动失败查拓扑/绑定 |
| 渲染是否正确消费资产 | 模型单位、材质/纹理语义、目标光照与可见结构；API成功不作为画质放行 |
| 声音是否可用 | 需要的发音/停顿/音色及最终混音审听；无声音需求不增加TTS |

设次数、预算和停止条件，已有通过证据且输入/接口未变时复用结论。服务互相独立时分开接入，不因采用一个服务而强制搭配其他供应商。免费/开源方案与付费服务遵循同样资产契约；结合当前环境核对许可证、硬件、推理与人工修整成本，开源不等于总成本为零。

对于人脸特写，图像生成和单图重建不保证身份稳定、背面正确或可用面部表演。若近景面部验收失败，先比较多视图重建、人工修模/贴图或许可清楚的现成角色资产；若人物结构通过而自动蒙皮失败，可保留模型并改用手工绑定。不能把“自动生成”的便利当作选择它的验收理由。
