# 参考短片生产流程：可迁移的工作法

本文把 THE BIG ONE 的 `docs/PLAYBOOK.md`、`docs/PROMPT.md`，以及 LEVIATHAN 的 `CONTRACT.md`、`README.md` 与构建工具，归纳为可迁移的短片制作步骤。两者都以 Three.js 源码、时间轴、渲染/声音与最终成片共同交付；不是只把最终 HTML 当作过程记录。

研究与生产分开：仅要求学习时先使用 `industry-production-study.md` 和既有证据；下面的生产、试片、渲染与验收步骤需要明确的制作或验证授权。

## 哪些过程有证据

| 证据类别 | 可以确认 | 不能据此确认 |
|---|---|---|
| 制作文档 | 故事节拍、镜头、制作目标、模块边界、渲染/导出命令、视觉验收方法 | 未记录的协作对话和每次临时决定 |
| 源码 | `renderAt(t)` 数据流、模型/材质/相机/FX/音频实现、构建和导出机制 | 某个效果在所有镜头都生效或已被审美验收 |
| 成品/接触表 | 实际可见的构图、颜色关系、角色尺度和镜头节奏 | 隐藏源码的结构，或未见到的中间稿 |
| Git 历史 | 已提交的变更顺序和记录 | 浅克隆只有单提交时的逐轮制作时间线 |

研究参考时同时保存这些证据；将“源码实现”“工具可运行”“成片可见”“主观验收”分别记账。

默认从参考提炼方法，为新题材实现，采用 [SKILL的参考边界](../SKILL.md#任务模式与参考边界)。参考仓库不作为新片的资产包或运行依赖；若任务明确允许复用，则单列原样/改造/新作和许可，能力结论仍按实际新增部分判断。

## 制作契约

在堆场景前，先建立一份随项目更新的制作契约。篇幅随片长缩放，字段保持可检查：

| 区块 | 最低内容 |
|---|---|
| 叙事与事实 | 故事弧线、史实节点、虚构角色/合成事件标签、来源和许可边界 |
| 视觉规则 | 构图比例、色彩/明暗、前中远景、主光、材质轮廓、节奏参考和目标景别 |
| 时间轴 | 分章 cue、镜头 `id / t0 / t1`、必须看清的动作、字幕区、声音和环境响应 |
| 空间/资产接口 | 单位、坐标、人物/道具锚点、可见性、谁拥有更新权、跨场景共用资产 |
| 运行/交付 | Three.js 版本、渲染入口、播放器时钟、音频契约、目标视口、HTML 与 MP4 的差异 |
| 验收门槛 | 核心镜头图、连续动作、接触、错误日志、随机跳转、音画和最终媒体信息 |

LEVIATHAN 的部门/文件 owner 契约适合并行产出时使用；顺序制作也要保留接口与可见性约定，但不需要为了形式拆出部门或代理。镜头数量、影片时长、目录名和具体题材不复制。

## 按职责组织制作与集成

| 已确认事实 | 一手证据 | 未确认项 | 采用范围 |
|---|---|---|---|
| LEVIATHAN 定义导演、环境、角色、船只、水下、两类FX及声音的文件归属，要求同时工作者只改自己的文件 | [CONTRACT：ownership](https://github.com/0xCodez/leviathan/blob/f12b3460fc5a74281170a873e17817d761d2d44d/CONTRACT.md#L106) | 实际执行者数量、身份和完整协作对话未公开 | 借鉴职责、文件写入范围和共享文件维护者 |
| 相机/LOOK按镜头提供；共享ctx、pose/anchor和每帧更新顺序有明确约定 | [CONTRACT：接口](https://github.com/0xCodez/leviathan/blob/f12b3460fc5a74281170a873e17817d761d2d44d/CONTRACT.md#L121) | 契约存在不等于所有模块/镜头都已逐项核验 | 先定接口和镜头数据，再拆独立任务 |
| 出水FX读取身体链，计算海面交界，围绕交界组织效果 | [fx-splash-sea.js：s20](https://github.com/0xCodez/leviathan/blob/f12b3460fc5a74281170a873e17817d761d2d44d/src/fx-splash-sea.js#L280) | 其他FX需各自追踪 | 消费主体的变形/接触数据，避免各模块独立猜位置 |
| THE BIG ONE 作者记录主Agent负责导演/渲染/建模/动画，两名子Agent分别负责声音和道具 | [PLAYBOOK：制作记录](https://github.com/keycasiter/the-big-one/blob/081fca87bcff74220a762b8ac64e4057b4e823fa/docs/PLAYBOOK.md#L5) | 作者自述，没有完整执行日志独立验证 | 按项目规模合并职责；不固定人数或复制全部部门 |

### 先确定责任与交接

导演/集成者维护全局：视觉规则、cue/镜头、资产接口、运行入口、渲染契约和最终画面。各职责模块在共同规则下交付资产及镜头输出，导演检查组合后的构图、表演、风格和技术稳定性。一个人也可顺序承担这些职责。

| 职责 | 交付给谁/交付内容 | 写入边界 |
|---|---|---|
| 导演与集成 | 全模块消费的镜头表、cue、契约、相机/LOOK归属；最终装配与质量判断 | 共享入口、时间状态、渲染契约；变更共享接口时同步消费者 |
| 角色/主体资产 | 动画与FX消费的造型、pose、可见性、变形后表面/锚点 | 自有模型、材质与动画文件；不自行改全局灯光或其他角色 |
| 环境/道具 | 镜头与动作消费的空间、尺度、支撑面、道具实例与锚点 | 自有场景/道具；与角色共享接触定义 |
| 特效 | 基于cue、主体运动/接触生成的反馈和渲染输出 | 自有FX；不重写主体姿态和机位来迁就效果 |
| 声音 | 基于同一cue的音乐/音效/旁白与混音输入 | 自有声音模块或媒体；时长变更由导演同步镜头 |

相机和LOOK可以像LEVIATHAN一样由镜头负责者提供，但每镜只能有一个明确写入者；导演保留总的构图/色彩约束。共享文件有唯一维护者，跨模块修改通过明确的接口变更集中落地。

### 每个任务必须拿到的输入

交接卡包含：目标镜头/时间范围、真实参考及设计依据、已固定视觉规则、允许编辑的文件、上游接口和就绪状态、输出接口、检查证据与未解决项。输入缺失时先交回缺口，不让模块自行发明新的比例、时间线或画风。

共享契约按项目需要规定：

- **空间与时间**：单位/轴向/原点、主时钟、cue、局部时间、对象采样节奏；随机seek必须重建所需状态。
- **资产与接触**：pose参数含义、anchor名称/返回空间、是否反映最终变形、更新顺序、set显隐及缺失输入处理。
- **画面输出**：相机/LOOK归属、材质数据通道、ID分配与相邻结构边界、阴影/反射参与、资源与耗时预算。数值以所选渲染器为准，不把某仓库ID范围设为通用协议。

### 安排任务与收口

先让上游接口可用，再把独立消费者拆出去。造型与绑定共享同一变形结构，相机与构图共享镜头设计；强耦合任务宜由同一维护者协调。声音可按稳定cue推进，FX需等可用锚点。接口仍在变动时先缩小分工，避免多个模块各补一套临时实现。

实际使用多Agent须符合当前用户授权和工具规则；职责划分本身不要求启动Agent。已获授权并行时，每个执行者明确文件所有权，说明其他执行者也在工作，不覆盖他人改动；研究任务依旧不启动制作。

模块提交时报告接口、产物、受影响镜头、证据与缺口。集成者先核对接口/更新顺序和直接受影响的镜头，再判断组合画面是否符合设计。模块运行成功不代表镜头通过，镜头通过也不代表全片通过。

## 生产阶段与放行

| 阶段 | 输入与产物 | 放行与退回依据 |
|---|---|---|
| 视觉开发与镜头布局 | 故事与结构参考→主形/色光依据、关键构图、镜头/cue、相机与尺度参照 | 主体身份、事件和主次能读；未定先回设计，不细化全场景 |
| 资产与生成实现 | 结构规格→新对象主/中/小形、拓扑/材质分区、变形与锚点 | 轮廓/厚度/连接及主要姿势成立，参数被实际消费；失败回表示/生成器 |
| Blocking与lookdev | 可用资产与镜头→关键姿势/接触、目标风格预览和统一色彩规则 | 重心/节拍清楚、变形连续，最终画风下体积仍可读；二者早期协同 |
| 镜头整合 | 动作与表面数据→环境/FX、灯光、合成与声音 | 按 [核心镜头标准](validation.md#核心镜头放行标准)；未过时只重开证据指向的层 |
| 扩片与交付 | 已放行机制→其他镜头、版本化装配、音画与媒体 | 全片连续性、来源、视觉/交互/声音/性能按validation分别验收 |

小demo只做必要产物，核心镜头就是交付镜头；代表性动作或材质可在其自身阶段审阅，不要求额外新建试片。先明确设计，再逐层落实，避免完整渲染时才同时发现造型、构图和动作未定。

## 一部片的闭环

```text
证据盘点 → 视觉/结构设计 → 制作契约 → 镜头/cue与接口
       → 新资产/动作/lookdev → 核心镜头 → 关键帧审片 → 修正根因 → 扩展场景
       → 接入声音/播放器 → 逐镜及全片检查 → 离线HTML/MP4验收
```

### 1. 证据盘点和目标锁定

- 获取参考成片、源码、接触表和运行入口；记录 commit/版本、许可与实际查看范围。
- 跟踪至少一条真实链路：入口 → 时间状态 → 相机/角色/场景 → 材质 pass → 音频 → 构建/播放。
- 把“想要的质感”翻译成屏幕证据：主体轮廓、空间层次、明暗主次、动作读得懂、镜头变化和声画节拍。
- 具体案例参数留在项目；写入 skill 的应是形成机制、适用条件和怎么证明生效。

### 2. 制作契约、cue 和镜头表

- 先确定短片的事件因果，不先堆地点名或视觉素材。
- 将史实句、戏剧化合成事件和现代旁白分开标注；一个镜头只能承载它确实能说明的信息。
- 用同一时间码组织画面、字幕、旁白、音乐、环境声和关键音效；需要精确接触的 cue 使用精确秒数。
- 每镜规定观众要看清什么、主体锚点在哪里、镜头怎么运动、背景怎样反馈、字幕避开哪里。
- 大片可按场景/角色/FX/声音划 owner，并定义统一的 `stateAt(t)`、锚点和更新顺序；小片以相同字段顺序制作即可。

### 3. 工程与渲染基线

- 确认依赖版本、离线入口、时间纯函数、种子随机、帧率、视口和错误报告。
- 新实现/协议变化且缺少通过证据时，用必要校准物验证颜色/法线/深度/材质ID或所选替代路线；已有同配置证据则沿用，不另造无关场景。
- 复用绘画 MRT 时连同输出协议、pass 状态、材质 ID 和调试视图一起迁移；只粘一个 shader 不算迁移完成。
- 让实时预览、seek 截图和逐帧导出调用同一时间求值入口；抽帧风格也不可挪动接触/事件时刻。

### 4. 角色/场景与核心镜头

- 先建立角色轮廓和基本形体，再处理中层结构，最后增加只在目标景别可见的表面细节。
- 先完成决定画质上限的核心镜头：最终机位、人物尺度、明暗、接触和环境反馈都齐全，才复制机制到其他镜头。
- 用中性光、灰模或关闭后期定位轮廓/拓扑问题；用最终材质和最终镜头判断色彩与质感。不要用雾、描边、泛光掩盖缺少的结构。
- 手/道具/支撑面用共同世界锚点；对接触前、接触、分离后的表面位置与连续画面共同检查。
- 场景以可显隐组按镜头选择，逐次完整赋值当前 `visible`、look、pose、字幕、FX，允许任意时刻顺序取帧。

### 5. 评审和返工

评审围绕当前阶段的明确问题和受影响范围展开：

1. 查看对应阶段产物及受影响镜头的证据，关键镜头看原尺寸，脸/手/道具/穿模疑点放大；阶段合并、共享规则改动或最终验收时再扩大到全片接触表。
2. 先写症状所在的时间、画面区域、可复现帧和用户观感；暂不直接追加装饰。
3. 分清根因在轮廓/拓扑、动作/支撑、相机/构图、主光/色彩、材质坐标、深度/pass、音频或播放器。
4. 只改已定位的根因，重新捕捉受影响帧和连续片段；必要时再检查全片。
5. 对异常位移、场景残留、首次着色器卡顿和渲染预算采用脚本/日志辅助；工具存在不代表本轮已经通过。

THE BIG ONE 的 `PLAYBOOK.md` 明确记了从视觉症状反查几何/变形原因的返工例子，并建议接触表、原尺寸观察和跳帧扫描。LEVIATHAN 的工具链把检查图、错误门禁、媒体导出和分段状态相连。按项目规模采用同等检查，不要求无条件复制所有脚本。

### 6. 声音、播放和最终交付

- 音乐、环境、效果、旁白用相同 cue 时间线、独立音量和可审听来源；留白需是设计选择。
- 有音频时用音频时钟驱动画面，暂停、拖动和重播时更新同一 offset。
- 明确区分实时 Three.js 页面和内嵌预渲染视频播放器；哪种是主交付、是否离线可打开，要说清楚。
- 最终导出复用同一 `renderAt(t)`；检查生成 HTML 的语法/运行、播放器实操、MP4 时长/分辨率/fps/音轨、抽帧和听感。
- 失败的导出不能以同目录旧成片冒充成功；缓存/分段需绑定源码与媒体 hash、帧范围和完成标记。

| 镜头/时间 | 观感症状 | 已证实根因 | 改动机制 | 新构建/帧证据 | 剩余边界 |

## 参考机制与新题材的边界

- 学方法：确定性时间轴、明确接口、形体/动作与画面分层、渲染 pass 契约、分镜节拍、逐轮审片、声音 cue 和可复现导出。
- 不复制案例：人物、怪物、故事、镜头复刻、具体镜头表、比例、材质参数和授权范围外的参考素材。
- 运行环境拒绝某项操作时，换到文档支持且不规避限制的方法；有条件障碍时明确记录，不用一次 build 成功宣称作品已完成。
