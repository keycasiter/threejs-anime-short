# 可迁移的造型、结构与光影能力

适用于资产技术齐全却缺少成品质感的情况。学习对象是“如何将可见形态转为可控模型、结构和光影”，不将某个故事的山峰、机器人、配色或镜头参数作为模板。参考实现为 THE BIG ONE 的 robot/boat/lord/sky，以及 LEVIATHAN 的 archer-geo/archer-mat/under-rock/world-coast。

## 从文字要求到可执行结构

这里“大语言模型/Agent”负责理解设计并编写程序；“三维模型”是程序运行或资产加载后得到的网格、属性与变形结构。文字不会被渲染器直接解释。程序化路径为：

```text
人的目标 + 真实结构/画风参考 + 已有实现研究
  → 镜头设计与结构规格
  → 新对象的生成函数、拓扑/部位/材质/变形规则
  → 运行时顶点、三角形、姿态、法线、纹理和uniform
  → 材质着色 + 选定的渲染/后处理 → 画面
```

已有资产/DCC路径由制作/导出/加载提供中间数据，仍需要结构与镜头规格。Agent可以同时编写几何与shader，不是只给一个永远相同的渲染器填参数。

| 设计描述需要解决什么 | 落实到哪里 | 检查什么 |
|---|---|---|
| 身份、比例、截面轮廓 | 尺度、截面控制曲线、关键体块、拓扑 | 正侧剪影、目标机位占幅与厚度 |
| 凹陷、折面、搭接与连接 | 局部几何位移、有厚度面板、孔/缝与支撑关系 | 掠射角与光照下结构成立，不是浮贴装饰 |
| 皮肤/布/金属等差异 | 材料分区、rest/UV、颜色/法线/粗糙度或风格着色 | 局部色与受光各有贡献，纹样随物体稳定 |
| 可动部位与接触 | 关节/脊柱/权重、约束、变形后锚点 | 极限姿势体积、表面接触和邻近时间连续性 |
| 光影、镜头与细节强度 | 相机、主光、材质输出与后期消费者 | 关键结构可见，细节在最终像素尺度不过密、不闪 |

“准确”指比例、位置、方向、连接和形成逻辑与设计目标相符，不是多写小数或堆顶点。“有依据”指细节服务身份、装配、受力、材料或叙事；不是每处都加随机凹槽。画面丰富度也不是质量单调指标，保留安静区域和主次。

给Agent的规格应说明可观察特征与关系，而非只写“电影级、超细节”。例如新灯具的灯罩有壁厚、包住发光体，支架落在基座，电缆连接真实接头；再把这些关系映射到截面/壳体、连接点和材质。数值由参考比例、尺度和目标机位推导，不要求用户提供全部尺寸。

两仓库的文字要求确实存在：LEVIATHAN `CONTRACT.md:Art direction/Designs/Shots`约束造型、画面与接口；THE BIG ONE `docs/PROMPT.md`是公开的复用提示模板，`PLAYBOOK.md`记录作者工作法。模板不是完整历史对话。B `lord.js`的实际链路是截面曲线→局部雕刻→网格→脊柱变形→专用材质；眼球顶点并入主体网格，虹膜/瞳孔和眼睑覆盖主要在shader绘制。讲解时区分文字原文、源码事实与自己的设计概括，不把“眼睑可控制”夸大成真实眼皮拓扑。

学习后为新对象重建设计规格和生成器；不复制案例数值、角色网格或专用shader再换背景。Three.js基础renderer、对象材质与自定义合成是不同层，同样用Three.js不能推出渲染流程相同；材质和灯光也共同决定质感。

## 从可见证据建立资产规格

先找决定身份与质感的可见证据：轮廓、比例、折面、厚度、连接、受力、磨损、干湿、主光和景别。题材的真实形态参考用于理解结构，成片参考用于理解画面表达，两者用途不同。不要只截一张封面，也不要从“自然物体就加噪声”出发。

建立简短资产规格即可：主体由哪些有体积的形状构成；哪些界面必须支持、搭接、连接或留空；最近镜头要读出哪些中层结构；各材料靠什么光响应区分。完成标准是可见结果，不是顶点数、几何件数或特效数量。

## 表示方式决定质量上限

| 需要表达的形态 | 可选表示 | 必须核对的限制 |
|---|---|---|
| 有厚度的壳体、装配件 | 连续基体加有厚度/倒角/折脊的面板 | 面板应解释装配与遮挡；不能用贴花代替外轮廓和厚度 |
| 封闭、不规则的自然体积 | 切面体积、多尺度三维雕刻、适量体块组合 | 宽度、深度、体积连续性与交叠；不能只雕正面，其余视角仍是板 |
| 地表、布面等连续表面 | 高度场、参数曲面或变形网格 | 单值高度场无法表示某些倒扣/洞穴；需要时换表示，不强行加细分 |
| 人体和长体生物 | 连续网格、骨骼/脊柱变形、关节修形 | 极端姿势下体积、法线、变形后锚点；零件拼装不自动变为皮肤 |
| 分枝、连接和承载结构 | 主干/骨架曲线加变半径截面，附属体积 | 主次粗细、方向与支撑；重复平片不能替代可转视角的体积 |
| 划痕、纹理、薄表面信息 | 局部/静止坐标贴图或shader | 只改变表面；无法修正错误的大形、接触和投影 |

几何类型可以混合。对同一资产先验证最困难的视角与结构关系，再选取表示。实际轮廓、遮挡或厚度持续失败时，换表示方式；不要无限微调原表示的颜色、噪声和细分。

参考中的4×5分段曲面面板也能有明确结构，因为它定义了正确折面与厚度。高密度曲面若只是同一收缩截面的重复，信息量仍然低。程序化的价值是把设计关系编码为可控规则，而非用随机性代替设计。

## 建立大、中、小三个尺度，按薄弱层修正

大形控制轮廓、比例、主次和重心；中层结构控制折面、分段、断裂、叠压、支撑和材料边界；小尺度控制纹理、颗粒、标识和磨损。

中层结构要解释对象：机械件的装配界面、人体的骨点与肌肉转折、自然物的生成/侵蚀方向，不能只提高全表面的噪声频率。没有中层的大形配上密集小纹理，常呈现“脏但空”的效果。

区分该连成一体的表面与真实分离的部件。细节像悬贴平台时，检查几何厚度、接触、底面遮挡与形成逻辑；应为主体形变的特征应进入共同曲面/雕刻场。确实由独立零件搭接的对象则保留分件，不能一概要求合成单网格。

控制密度也包括安静区域：主体需要有可读结构，次要平面和背景不必用同等强度填纹理。把高密度细节分配到实际会拍摄和辨认的位置。

## 表面高度、颜色与法线是不同能力

改变albedo只能增加色斑；改变几何才能改变轮廓、遮挡和投影；改变光照法线才能在保持轮廓的同时改变局部受光。明确需要哪一种效果后再选手段。

LEVIATHAN `under-rock.js` 使用CPU三维噪声/切面构造几何，再由片元高度场的切向梯度产生凿刻法线：

```glsl
float h = heightField(P);
vec3 g = vec3(heightField(P+vec3(e,0,0))-h,
              heightField(P+vec3(0,e,0))-h,
              heightField(P+vec3(0,0,e))-h) / e;
g -= N * dot(g, N);
vec3 shadedNormal = normalize(N - strength*g);
```

它是一种可迁移方法，不是所有材料的默认shader。高度场的方向、频率、强度要对应材料形成方式，微细层随像素尺度退场。金属更依赖有设计的折面、硬反射带、边缘与表面分区；皮肤也不能套用岩石凿刻。

几何法线、光照法线和描线法线可以有不同职责。阴影的接收点偏移与斜率bias通常使用几何法线；直接用强凹凸法线偏移可能将采样点推入真实表面，造成条纹或自阴影错误。把高频凹凸直接写入用于墨线的缓冲，可能将整面材质变成碎黑线。先确认哪种尺度应影响轮廓、受光与墨线。

## 光影需要解释形体与材料

先用一套明确的主光观察大体积，再建立亮面、背光面、深部和接触关系；风格化可以采用硬色阶和选择性阴影，不要求写实PBR。主光与相机应让关键转折可见，不能指望后期补救受光方向错误。

阴影先收紧相机范围，再处理法线偏移、斜率bias与过滤。自阴影条纹、漂浮阴影和缺失接触属于不同故障。用相同机位的开关对照确认贡献；更黑不等于更立体，投影若只压成脏块应重查结构和参数。

材料差异来自可读的光响应：反射带/高光的形状、明暗边界、局部色、透光或干湿变化。不统一把gloss/rim开大；也不把所有材质设成同一哑光底色再依赖描边区分。

## 颜色迁移先核对契约

核对颜色输入空间、shader运算、色阶/曝光与最终显示输出。Three.Color默认的sRGB解析、线性数值色板、画稿式硬色带并非可任意互换。参考 LEVIATHAN 的 `under-env.js:raw` 显式按 LinearSRGBColorSpace 解释十六进制数值，而部分通用cel材质沿用默认Color；相同色号可能得到不同数值。

迁移时先用小色板与亮/暗校准物检查，再明确选择并保持契约。禁止为了修一帧把所有颜色重复转换，或把某次“更亮”的转换写成通用修复。色彩丰富与体积清晰分开判断，灰度审图仍须成立。

## 核心镜头验收和扩片

选择最能暴露资产弱点的代表镜头，固定视口、构图和时间，保留改前构建。对应问题选择干预，避免制造无意义的全套测试：

| 证据 | 要回答的问题 | 常见误判 |
|---|---|---|
| 轮廓/低分辨率图 | 主次、身份、重心是否清楚 | 纹理细密掩盖重复或错误轮廓 |
| 灰模，关闭纹理/特效 | 体积、折面、厚度、支撑是否成立 | 仅把最终图去色，仍保留全部表面/特效，误称灰模 |
| 最终材质原尺寸图 | 材料区别、中层与微细层是否匹配景别 | 只缩略审图，漏掉近景空面、噪点和阴影条纹 |
| 同机位光影开关或局部对照 | 投影/法线/反射究竟贡献了什么 | shader存在便认定能力生效 |
| 邻近时间和连续片段 | 结构、接触、纹理是否随运动稳定 | 单张漂亮帧代表完整动作 |

结构关系可由实际网格或变形后的世界坐标采样验证：支撑面、手持连接、运动净空、源头/终点连续性。优先共享求值函数或从最终表面求锚点，避免两边独立硬编码近似值。容差按场景尺度与镜头制定，数值通过仍须审看可见表面。

上述干预用于形成核心镜头证据，按 [validation.md](validation.md) 的统一阶段门槛决定扩片。扩片要检查其他景别、遮挡、日夜/环境状态和预算；同一资产在一个机位成立不代表全片成立。技术门禁、视觉判断与用户验收分别记录，不把“已有导出视频”当作“已与参考同等质量”。

## 经验进入Skill的范围

保留因果关系、选择依据、接口和能证伪的检查方法；对象特定参数、镜头、配色、噪声seed及失败迭代截图留在项目。迁移到另一种对象时，先确认形成逻辑和表示限制，不直接重用原题材的外形公式。未验证的角色、材料或变形能力明确列为未覆盖。
