# B/L绘画短片：能力依赖与实施路径

仅在选择借鉴 THE BIG ONE/LEVIATHAN 的绘画短片制作机制时读取。路径依据 THE BIG ONE `081fca` 与 LEVIATHAN `f12b346` 的本地源码核对；文件名以下分别标 B/L。PBR、MatCap、烘焙或其他路线先按 [rendering-choices.md](rendering-choices.md) 选型，不默认采用下列MRT链。学习实现机制，造型、故事、镜头独立设计。这里的迁移步骤描述协议与因果，不授权直接复制专用源码；按 [参考边界](../SKILL.md#任务模式与参考边界) 执行。

## 1. 总体依赖：先交付一镜，再扩成全片

```text
故事事件与屏幕尺度
  ├─ hero silhouette → 曲面/拓扑/厚度 → 法线/静止坐标 → 表面设计
  ├─ 主姿势/支撑 → FK/IK/脊柱 → 变形后世界锚点 → 道具/FX/相机
  └─ shot + look + cue → 完整的 stateAt(t)
                          ↓
  shadow / reflection → MRT → paint → ink → water/atmos → soft overlay → bloom/grade
                          ↓
  逐帧同一入口 → 错误门禁 → 声画合成 → 实时页 / 视频播放器
```

长片可另按第7节实现可恢复缓存；当前同步导出器没有分段恢复。先选占成片质量上限的镜头，用最终机位和目标像素形成检查证据，并按 [validation.md](validation.md) 的统一核心镜头标准决定扩片。下面各能力的检查证据用于诊断，不替代阶段门槛。画面问题定位到最早失效的依赖：无轮廓用几何修，无重量修姿态，无层次修光色/构图；增加粒子或泛光不能代替这些依赖。

## 2. 形体路径：参数化设计，而非基本体拼装

| 需求 | 源码机制 | 新片实施方法 | 该能力的检查证据 |
|---|---|---|---|
| 有设计的机械主角 | B `robot.js:superEllipsoid/lathe`；L `archer-geo.js:hull/patch/solid` | 用截面曲线/超椭球控制轮廓；壳体有厚度、倒角、面板起脊；关节位于壳内，缝隙有结构理由 | 无纹理中性光正侧面和最近镜头，壳体不成空心纸片 |
| 连续生物或自然体积 | B `lord.js:section/sculpt/restPoint`；L `lev-body.js` | 先定义长轴截面宽/高/腹深，再雕刻眼窝、腹部、鳃或侵蚀凹槽；附属物嵌入主体 | 背光轮廓和转视角不暴露球串、薄板或断层 |
| 人物身份与皮肤关节 | 两参考均非写实人类皮肤方案 | 用真实正侧参考校准头身、颧骨、下颌、肩髋；大幅人体运动选连续蒙皮/修形或合适资产 | 身份可辨；肩髋在目标极端姿势保持体积。不能因机器人好看便推断人体胶囊方案足够 |
| 远近都有细节 | L `lev-mat.js:mpp/lod1/lod2` | 一级轮廓用几何；二级面板/褶皱用几何或法线；三级划痕/颗粒用材质，按屏幕占比退场 | 最近帧有可看细节，最远帧无亚像素闪烁 |

### 曲面实现要点

超椭球用 `sign(cos θ)*abs(cos θ)^(2/p)` 控制圆方，lathe 用平滑半径-高度曲线而非锥台串；长体截面按长度插值。分辨率随曲率和最近机位分配，增加顶点数不能弥补不合适的截面。

闭合曲面 UV 首尾常为不同顶点：焊接位置或平均接缝法线，保留 UV 断点。收口的一圈若半径为零，各角度必须落在同一位置；角度相关高度未同步归零会产生针刺。检查三角形朝向、有限法线、接缝和退化面。

非均匀缩放用 `transpose(inverse(mat3(modelMatrix * instanceMatrix)))` 变换法线；非实例模型也可用 Three 的 `normalMatrix` 得到视空间法线，再用逆视旋转转世界。`mat3(modelMatrix)*normal` 仅在特定缩放条件下正确。法线错误会同时污染受光、描线和材质图案。

## 3. 动作路径：从约束到连续变形

### 分件 / 人形：FK 主姿势 + 两骨 IK

B `robot.js:ik/pose`、L `archer.js:solve2/pose`：肩/髋起点 S，手/脚目标 H，两骨长度 a、b。设 `L=|H-S|`，投影长度 `x=(a²-b²+L²)/(2L)`，关节偏离轴线 `h=sqrt(max(0,a²-x²))`。pole 投影到垂直轴线的平面后归一化，肘/膝为 `S + dir*x + pole*h`。

接入时处理不可达距离 `[abs(a-b)+ε,a+b-ε]`、S=H 和 pole 平行退化；这些是迁移实现的边界，不能假定参考的简化求解覆盖所有姿势。脚目标来自支撑面；腰、胸、头分开安排，先重心/预备，再发力/回弹/跟随。IK 解决端点位置，不会自动生成重量与表情。

L `archer-pose.js` 在放箭时重置二拍采样相位；关键 cue 不能被 `floor(t*12)/12` 随意推迟。主时钟和相机连续，角色可二拍、FX 可三拍，但接触/放手事件用精确时间。B `director.js:lordDive` 有头部滞后、翻滚和鳍摆，不能简化成刚体整体旋转。

### 长体：静止曲面 + CPU/GPU 同构脊柱

L `lev-spine.js`：静止空间 +Z 沿长轴，横截面 XY。每骨存位置/截面尺度 P 和四元数 Q；位置 Catmull-Rom 插值，Q 同半球后归一化线性插值，顶点先处理颌部再绕骨架变形。`setBone` 用相邻 Q 点积负值翻符号；不处理会沿长弧旋转。

`Spine.at/toWorld` 与 shader 使用同样的索引、插值、关节和尺度。特效、镜头和接触点必须从变形后的锚点取世界位置；禁止用静止网格原点挂喷溅。迁移时逐项核对端点外延、逐骨尺度和 uniform 长度，不能只比较一条中心线。

验收同时覆盖：接触前/中/后，极限曲率，随机跳转，CPU 锚点与 GPU 可见表面的相对位置。CPU 公式相同是必要条件，仍须观察实际渲染形体。

## 4. 表面路径：形体稳定后再加复杂度

B `materials.js` 让 pattern 改 albedo/gloss/emis/litBias 等；L `archer-mat.js` 用分区材质属性、局部投影面板和硬边金属高光；L `materials.js:aRest` 把旧化固定在静止表面。新片按材料设计，不让所有物体共用同一个 fbm 噪声。

选择坐标有实际后果：

| 坐标 | 用途 | 错用现象 |
|---|---|---|
| rest / aRest（变形前保存） | 鳞片、旧化、脸部图案 | 变形后重算会拉扯、滑动 |
| object/local | 面板、树皮、独立石块 | world 噪声让移动角色穿过纹理 |
| world | 地形层理、跨物体水面反馈 | parent 缩放导致频率变化须标定 |
| flow（横向/沿流线米制） | 水帘、浪峰、飞沫 | 用同一 UV 速度时方向错乱、接缝明显 |
| screen + derivative | 笔触、LOD、颗粒 | 未按像素退场会远景闪烁 |

L `lev-mat.js` 的 `mpp=max(length(dFdx(uvm)),length(dFdy(uvm)))` 控制鳞片和细皮肤两级退场。迁移频率时重新标定米制和像素尺度；不复制巨兽几百米场景的阈值到 1 米人脸。

## 5. 渲染路径：迁移协议，不孤立复制效果函数

仅在生产/机制验证范围内执行，已有相同协议和依赖的通过证据可沿用；不为每次制作重复建探针。详见 [render-contracts.md](render-contracts.md)。需要新实现或适配协议时先检查“彩色校准块 + 非均匀缩放物 + 前景遮挡片 + 雾片”的代表镜头，再接入主体。保留 source/render/consumer 三端证据。

B：主 MRT → paint → ink → atmos → overlay → bloom → final。
L：定向 contact shadow → reflection → 主 MRT → paint → ink → screen water → atmos → soft overlay → bloom/grade。

阴影只选择需要接触关系的投射根节点，收紧 shadow camera 范围以减少 bias；L 的装饰背景不会自动把整片阴影压在角色上。水面反射按水位镜像相机位置、视线和 up，排除水面自己，投影矩阵保持一致。反射应先于水材质采样；不能读写同一 render target。

绘画背景与 cel 主体分流是成片风格的关键：远山云层可吃笔触，角色硬边保留，雾的软交界再缓和层次。所有物体一律描黑会像建模视窗；全画面模糊会损伤脸和道具。

### 云和水花：宏观体积统一，局部细节打断

B `sky.js:makeSky` 把每个 billow 的方位/仰角/半径/前后偏移存入浮点 DataTexture，每座 cloud tower 另有角域 bounds 和索引范围。片元先剔除不相交云塔，再选当前视线最前的 billow，融合局部法线与整座云塔的宏观法线（源码混合宏观占 .7），按两三档冷暖色着色；边缘用 fwidth 抗锯齿，前后 billow 接近时加重叠轮廓。这样团块负责花椰菜形边缘，整塔负责统一光照，避免每个球都出现一模一样的月牙。

迁移这类效果须同时保留数据纹理、bounds、角度 wrap、宏观体积和局部细节，而非复制几个缩扁的球。山雾则应选择柔软的深度粒子，不把积云几何套给所有雾。立起的浪用真实水体网格；水雾与水花的墨线策略不同，不能逐粒子强描边。选效果的表示方式要符合景别、体积和透明需求。

L `textures.js` 还说明“纯代码”可以生成 CanvasTexture 字形/面板图集；纹理并非只能用噪声。配合局部投影、mipmap 和 anisotropy，把划线、紧固件、标识集中为有设计的中层细节。单纯随机划痕不会产生参考装甲和船体的制作精度。

## 6. 镜头、LOOK、世界反馈是一套数据

L `look.js:PRESETS/applyLook` 协调太阳、天空、阴影、雾、水和最终调色；每镜 CAMS/LOOKS 分工。B `shots/director` 用事件组织镜头。建立 `shotId / start / duration / camera / look / cues / visibility`，从 `stateAt(t)` 完整求值。

先检查一镜的灰度主次、轮廓、主体像素占比、背景复杂度和字幕安全区；再检查镜头切换方向及中间构图。环境响应来自同一 cue/锚点：水花从真实入水点起，投影停留在接收面，箭与手/弦共享位置。`visible=false`、关节、材质、FX 和 UI 也须每次完整赋值，不能依赖播放历史。

“高质量”不等于一直高饱和。复制色彩关系：暖光/冷影、主体/背景值差、前中远景层次，再按题材选色。日夜混合须检查中间态；只看首尾会漏掉灰泥色和过暗主体。

## 7. 声音、性能和交付闭环

B `audio-dsp/audio-master/audio`：music、SFX、环境分总线，独立 dry/send，FDN 混响，EQ、压缩、前视限幅；留白在混响之后 carve，避免残响填满停顿。`player.js` 用 AudioContext.currentTime 作主时钟，暂停/seek 时停止旧 source 并重设 offset，避免两个时钟慢慢漂移。通用默认参数不是作曲/混音能力，完成听感仍需试听。

性能优先合并固定同材质网格，重复粒子/星/水滴用 InstancedMesh；随机种子固定，逐帧从 t 求位置。统计多遍总 draw calls：Three 默认每次 render 重置 info，若只读最后一个 fullscreen pass，会得到误导性的 1 call / 2 triangles。测耗时明确分辨率、缩放、场景时刻和设备，不把离线渲染速率叫实时 FPS。

L `tools/render.mjs` 的生产价值是错误门禁和版本隔离：逐段帧范围/帧数、源码/资源 hash、完成 sidecar、失败不算缓存完成，最终拼接核对完整范围。移植时覆盖实际依赖，而非盲信脚本名。开发 NOOP 容错只用于迭代，成片 required 模块缺失须 fail。

实时 HTML 和内嵌视频 HTML 是不同产物。保留可编辑实时入口；需要稳定观看时导出 MP4、核对实际时长/帧数/音轨/关键帧，再按需要包装 Blob video 播放器。不要在完成状态中混淆“代码构建”“导出成功”“视觉对齐”“播放交互通过”。

## 8. 实测反馈进入 Skill 的边界

把通用因果关系写入 Skill，把具体调色数值、人物比例和镜头曲线留在项目。每次使用形成能力表：参考机制、实际连接、可见证据、限制。环境片只能验证自然形体/水/雾/分镜，不能证明人体关节、巨兽脊柱和情绪表演已达标；这些须在对应题材中单独跑代表镜头。
